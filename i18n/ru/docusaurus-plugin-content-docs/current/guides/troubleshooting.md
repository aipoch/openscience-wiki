## Диагностика по точке отказа {/* #diagnose-by-the-point-of-failure */}

| симптом | Сначала проверьте | Условие действия и успеха |
| --- | --- | --- |
| Приложение открывает пустое рабочее пространство | Местоположение данных, профиль и Архив | Возврат к предполагаемому корню/проекту. Не создавайте сразу замену |
| Нет полезной модели | Логин провайдера, активный агент, совместимость моделей | [Настройка поставщика](providers.md)Маленький фактический ответ удался |

| Задание кажется остановленным | В ожидании плана, одобрения или карты взаимодействия | ответ на видимый запрос; прочтите его содержание, прежде чем разрешить |
| Острая коррекция не выполняется | Не сохранено / Отправка / состояние отложенной доставки | [композитор](composer.md)Убедитесь, что это стало сообщением пользователя |
| Модуль не найден | Точный устный переводчик и инвентаризация пакетов | [Среды выполнения](runtimes.md)Проверка импорта в выбранной среде |
| Утвержденная установка пакета все еще не удалась | Первая ошибка в сети/прокси/сертификатах | [Сеть](network.md)Перепроверить фактическую операцию после устранения ее причины |
| Notebook не может читать файл | Управляемый путь, вложение, грант папки и ссылка на версию | использовать предполагаемый разрешенный вход; Не расширяйте доступ к несвязанным файловым системам |
| Сервис Saved-file отклоняет рабочий путь | Зарегистрировано ли оно для управляемой публикации | Сохранить через поддерживаемую операцию артефакта; повторно открыть полученный файл |
| Таблица отличается от ожидаемого числа | Хеш источника, делимитер, столбцы метаданных и знаменатель расчета | Пересчет с одного и того же входного сигнала перед изменением ожидаемого значения |
| Файл видимый, но предварительный просмотр не работает | Формат файла / размер, версия и ошибка рендерера | [Превью](previews.md)Скачать, чтобы отличить рендеринг от отсутствия файла |
| Ссылка кажется отсутствующей | Вид библиотеки, фильтры, Inbox или Trash | Чистые фильтры, проверка состояния и восстановление в правильном жизненном цикле |
| Найден полнотекстовый источник, но вложение не работает | Реальный результат загрузки и проверка PDF | Используйте другой законный источник / локальный PDF, затем откройте вложение. |
| Side Chat отключен | Сообщение о совместимости агента/поставщика | [Делегирование](delegation.md)Проверьте ограничение совместимости, указанное выбранной вами структурой |
| Удаленная работа не может работать | Реальный хост, аутентификация, планировщик и условия выполнения | [Дистанционные вычисления](remote-compute.md) |

## HTTP ошибки: 400, 403, 429 и 5xx {/* #http-errors-400-403-429-and-5xx */}

Статус HTTP описывает ответ от поставщика моделей, службы Connector, службы локального браузера или прокси-сервера. **Определите службу реагирования перед изменением настроек.** Копируйте статус вместе с его телом ошибки: `403` сам по себе не сообщает вам, вызвало ли отказ разрешение API, политика прокси или ограничение ресурсов.

<span id="permission-request-keeps-waiting" />

### Запрос, аутентификация и доступ {/* #request-authentication-and-access */}

| Статус | Значение | Что проверить в Open-Science |
| --- | --- | --- |
| **400 Плохой запрос** | Служба отклоняет запрос. | Прочитайте названное поле или параметр. Проверьте конечную точку поставщика, идентификатор модели и поддерживаемые функции запроса. Для вызова инструмента проверьте его схему ввода. Попробуйте небольшой текстовый запрос, если вложения или дополнительная функция вызвали ошибку. |
| **401 Неавторизованный** | Действительная аутентификация отсутствует. | Проверьте, какую учетную запись или учетные данные использует неисправный сервис. Воссоедините соответствующую учетную запись подписки / OAuth или исправьте ключ API [Настройки провайдера](providers.md) или [Учётные данные Коннекторов](connectors.md). |
| **Запретный 403** | Сервис отказывает в доступе. | Проверяйте модель/право на ресурсы, разрешения организации/проекта и установленные ограничения доступа к сервису. Если ошибка говорит **HTTP CONNECT 403**Проверяйте [Прокси или сетевая политика](network.md)Вместо того, чтобы предполагать, что модельный ключ неверен. |
| **404 не найден** | Конечная точка или ресурс недоступны по этому адресу. | Проверьте базовый URL, путь API и идентификатор модели / ресурса. URL веб-сайта браузера не обязательно является конечной точкой API. Сервис может также использовать 404 для сокрытия недоступного ресурса. |
| **Метод 405 не допускается** | Конечная точка не поддерживает этот метод запроса. | Проверьте выбранный протокол API и транспорт Connector на соответствие сервисной документации. Сообщите о воспроизводимом несоответствии интеграции, а не угадывайте другой метод. |
| **Требуется прокси-аутентификация 407** | Прокси требует аутентификации. | Проверьте конфигурацию прокси-сервера с вашим сетевым администратором. Учетные данные модели API не аутентифицируют прокси. |
| **Слишком большой контент 413** | Орган запроса превышает лимит. | Уменьшите размер вложения/пакет или используйте поддерживаемый меньший вход. Подтвердите, какая услуга накладывает ограничение. |
| **422 Необработанный контент** | Содержимое запроса не может быть обработано по мере его предоставления. | Прочитайте сообщение о проверке на уровне поля. Правильные типы, требуемые поля или неподдерживаемые значения в запросе инструмента / поставщика. |

**400 и 403 требуют разных проверок:** для 400, который называет неподдерживаемый параметр, исправьте эту функцию запроса. Для 403, который называет ограниченную модель, проверьте доступ к этой модели. Если нет точной причины, сохраните ответ и запросите ID для поддержки. Не выявляйте причину только из числа.

### Квоты и временные сбои в обслуживании {/* #quotas-and-temporary-service-failures */}

| Статус | Значение | Следующее действие |
| --- | --- | --- |
| **Требуется платеж 402** | Удельный платеж/обработка доступа провайдера; HTTP сохраняет этот статус без универсального биллингового значения. | Прочитайте тело ошибки этого провайдера и страницу учетной записи. Не думайте, что пополнение требуется только от номера. |
| **429 Слишком много запросов** | Ограничение ставок; Некоторые модели API также используют его для исчерпания квоты. | Для ограничения ставки уменьшите параллельные запросы и ждите **Повторно** или документированная перезагрузка. Для ошибки квоты проверьте пособие / биллинг этой службы. Лимит подписки и кредитный баланс API являются отдельными. |
| **Ошибка внутреннего сервера 500** | Ответивший сервер не справился. | Проверьте его статус обслуживания. Повторите небольшой запрос после паузы, если это безопасно. сообщать о неоднократных сбоях с идентификатором запроса. |
| **502 Bad Gateway** | Шлюз получил недействительный ответ. | Идентифицируйте шлюз / провайдер и проверьте его статус и настроенный вверх по течению. Постоянный отказ пользовательских шлюзов может потребовать от своего администратора. |
| **Сервис 503 недоступен** | Сервис временно недоступен. | Последуйте за Retry-After и дождитесь восстановления. Для локальной конечной точки проверьте, работает ли и готов ли предполагаемый сервер модели. |
| **504 Gateway Timeout** | Шлюз приостановился, ожидая вверх по течению. | Проверьте, была ли операция уже начата или завершена до повторного запуска. Для анализа, представления работы или написания артефакта сначала проверьте существующий результат, чтобы избежать дублирования. |

Некоторые встроенные запросы Connector имеют ограниченные автоматические повторные запросы для 429, 500, 502, 503 и 504. Это не относится к каждой модели / фреймворку и не гарантирует безопасность повторных ручных представлений. Следите за ответом конкретной службы.

### Нет ответа HTTP или все еще не работает {/* #no-http-response-or-still-failing */}

Ошибки `ECONNREFUSED`, `ENOTFOUND`, `ETIMEDOUT` и сертификатов являются сбоями соединения / TLS, а не кодами состояния HTTP. Тайм-аут запроса не является автоматически HTTP 408 или 504. Начните с [Сеть](network.md).

После изменения настроек проверьте тот же провайдер / Connector с небольшим запросом, а затем повторите пораженную операцию. Если он все еще не работает, используйте [Инструкция по обратной связи](#report-a-bug-or-ask-the-community). Включите имя службы, конечный хост / путь без секретов, статус, тело ошибки, идентификатор запроса, если он присутствует, и временную зону. Никогда не вставляйте заголовок авторизации или URL-адрес с маркером в публичный отчет.

## Сопоставьте сообщение об ошибке {/* #match-the-error-message */}

Скопируйте точный код и сопроводительное сообщение из неисправного инструмента, диалога или журнала. Имена исключений **Коды**, Python и сообщения ОС — это разные типы идентификаторов. Open-Science не присваивает каждому сбою один универсальный цифровой код. Сообщение может иметь несколько причин. Для удаленных рабочих мест используйте [SSH и таблица ошибок вычисления](remote-compute.md#resolve-ssh-and-job-errors).

| Код или сообщение | Значение и последующие действия | Подтвердить восстановление |
| --- | --- | --- |
| `ModuleNotFoundError: No module named '…'` | Выбранный интерпретатор Python не может импортировать этот модуль. проверять [Среды выполнения](runtimes.md)Установите требуемый пакет в этой среде через поддерживаемый маршрут управления пакетами и следуйте любой инструкции по перезапуску. | Импортировать модуль в той же среде Notebook, а затем повторно запустить неисправную ячейку. |
| `ENOENT` / `No such file or directory` | Запрошенный путь найти невозможно. Проверьте имя файла и местоположение источника; Прикрепите существующий файл снова, если его ссылка устарела. | Просмотр или чтение предполагаемого ввода из той же задачи. |
| `EACCES` / `EPERM` / `Permission denied` | Операции не хватает доступа к файловой системе. Проверить как разрешение ОС, так и грант папки проекта; использовать [Проекты](projects.md) Предоставить только директорию, в которой нуждается задача. Для SSH `Permission denied (publickey)`Вместо этого проверьте подлинность. | Повторите оригинальное чтение/запись в пределах предполагаемого объема разрешения. |
| `ENOTDIR` / `Not a directory` | Операция каталога получила файл или недействительный путь родителя. Выберите фактическую содержащую папку. | Открывается список каталогов. |
| `EISDIR` / `Is a directory` | Операция с файлами получила каталог. Выберите предполагаемый файл. | Файл открывается или загружается. |
| Запрос на пакет, отклоненный для непубличного назначения | Проверьте отклоненный хост и разрешенный IP. Конфигурация прокси-сервера или DNS может предоставлять адрес блокам сетевой политики. Видишь? [Сеть](network.md); Установить адресное разрешение вместо того, чтобы расширять доступ вслепую. | Первоначальный запрос пакета и последующий импорт увенчались успехом. |

### Ошибки при запуске базы данных {/* #database-startup-errors */}

Эти коды появляются, когда приложение не может безопасно завершить открытие своих данных. Сохраните существующую папку данных. Прочитайте подробную информацию об ошибке перед повторным использованием; Удаление базы данных не является этапом восстановления.

| Код ошибки | Значение | Следующее действие |
| --- | --- | --- |
| `database_runtime_unavailable` | Движок базы данных не загружался. | Переустановите соответствующий официальный пакет приложений, сохранив отдельную папку данных. |
| `database_open_failed` | Базу данных открыть не удалось. Другой пример приложения, недостаточное пространство на диске или местоположение только для чтения может вызвать это. | Бросьте другие экземпляры, проверьте свободное пространство и разрешения папок, а затем повторите попытку. |
| `database_newer_than_app` | Более новая версия приложения написала этот формат данных. | Установите совместимый новый выпуск и откройте ту же папку данных. Не пытайтесь понизить его схему. |
| `database_history_invalid` | История миграции не соответствует ожидаемой истории приложения. | Сохраните папку и сообщите код. Если у вас есть известная хорошая резервная копия, обратитесь к процедуре восстановления перед заменой данных. |
| `database_migration_failed` | Обновление базы данных не закончилось. | Проверка свободного места, других экземпляров и разрешений; Используйте Retry, когда это возможно. Включите миграционный идентификатор, если он снова не работает. |
| `database_validation_failed` | Хранимые данные не соответствуют требуемой структуре. | Обновите приложение и перезапустите. Если он сохраняется, сообщите код, а не редактируйте строки базы данных. |
| `database_startup_unavailable` | Служба запуска базы данных не ответила и не завершила проверку. | повторный; Если он сохраняется, полностью отключите и откройте приложение, а затем сообщите об этом. |

Восстановление означает, что экран запуска очищается, а ожидаемые проекты открываются. Если доступно действие **Still stuck? Create an issue for help**, используйте поток обзора, описанный [ниже](#report-a-bug-or-ask-the-community). Эти значения следуют за [Руководство по запуску](https://github.com/aipoch/open-science/blob/v0.26.0/src/renderer/src/components/database-startup-gate.tsx).

Если экран запуска предлагает только **Quit**, выйдите из приложения, устраните причину и запустите его снова. Используйте **Retry** только тогда, когда страница предоставляет его. После восстановления откройте ожидаемые проекты и файлы.

### Восстановительные сообщения {/* #recovery-messages */}

| симптом | Следующее действие |
| --- | --- |
| Вычислительные задания остаются в очереди после восстановления хранилища | Прочитайте уведомление о затронутом разговоре, сохраните идентифицированные файлы, восстановите действительную копию и выберите **Recheck saved conversations**. Проверяйте ту же работу, прежде чем отправлять другую. |
| Загрузка PDF отменена, но ссылка остается | Откройте сохраненную ссылку и проверьте ее статус прикрепления; использовать пакет **Retry unfinished** Путь туда, куда предлагают. |
| Сохранение коллекции было отклонено после того, как другой клиент отредактировал его. | Откройте последнюю коллекцию и примиряйте изменения, прежде чем снова экономить. |
| Обновления Windows отказывают в доступе | Прочитайте точный путь файла и ошибку Windows. Следуйте инструкции уведомления использовать официальный установщик в качестве администратора. |
| Обновление Windows сообщает об используемом файле | Закройте процесс, идентифицированный как использование этого установочного файла, затем выберите **Retry**или **Cancel** Чтобы остановить обновление. |

Ошибки Windows представляют собой коды операционной системы, отличные от кодов состояния HTTP. Если восстановление не удается, включите установленную версию, точное сообщение и дезинфицированный файл / идентификатор работы, когда вы [Сообщить о проблеме](#report-a-bug-or-ask-the-community).

## Сброс локальных данных Windows {/* #windows-data-reset */}

Используйте утилиту автономного сброса только тогда, когда вы намереваетесь отбросить данные локальной установки и начать все сначала. Для копирования **Он навсегда удаляет перечисленные данные и сохраненные учетные данные; Они не восстанавливают и не подкрепляют их.** сначала нужны исследовательские файлы и резервные копии за пределами всех перечисленных каталогов. Только переустановка приложения сохраняет эти данные.

1. Из [Официальный гид сброса](https://github.com/aipoch/open-science/blob/v0.33.0/scripts/windows-reset/README.md) скачайте `reset-open-science.cmd` и `reset-open-science.ps1` с помощью **Скачать raw file**. Держите их вместе вне каталогов данных приложения.
2. Бросьте Open-Science, включая процесс лотка, и закончите и закройте его агент, Notebook, безголовый и WSL-процессы. Используйте обычную учетную запись Windows; Режим администратора не требуется.
3. В командной строке, открытой в папке загрузки, запустите `reset-open-science.cmd -Preview`. Просмотрите все предлагаемые данные, конфигурацию, профиль и путь кэша во время выполнения. Предварительный просмотр не удаляет данные.
4. Только после просмотра и резервного копирования этих локаций дважды щелкните `reset-open-science.cmd`. Он просит вас ввести `RESET OPEN SCIENCE` именно перед удалением. Любой другой ответ отменяется.
5. Прочитайте окончательный результат, прежде чем открывать приложение. После завершения сброса выберите местоположение данных и настройте поставщиков и снова управляйте временем выполнения.

Если процесс запущен или не может быть проверен, или путь небезопасен, сначала устраните сообщенное состояние. Не обходить отказ. Если настройки повреждены или задействовано пользовательское местоположение данных, используйте явную процедуру `-DataRoot` в официальном руководстве. Ошибка удаления может оставить частичный сброс, поэтому прочитайте ошибку, а не предположите, что ничего не изменилось. Утилита не отзывает внешние учетные записи провайдера и не удаляет отдельно установленные среды Python/R.

## Собрать полезную диагностику {/* #collect-useful-diagnostics */}

1. Запись версии приложения, ОС, активного агента/модели, проекта/сессии и времени отказа.
2. Копируйте первую соответствующую ошибку инструмента и операцию, которая ее вызвала. Включает ожидаемое и наблюдаемое поведение.
3. Для проблем ввода, включают в себя ссылку с открытым исходным кодом, имя файла, размер и контрольную сумму; Минимальный воспроизводимый вход более полезен, чем несвязанный скриншот.
4. Откройте **Settings → General → Diagnostics** и используйте **Открыто / Открыто** для журнала времени выполнения, когда это необходимо.
5. Проверяйте журналы перед тем, как делиться; Опустить токены учетных записей, контент из частного источника и несвязанные пути. Открытие журнала не отправляет его автоматически.
6. Укажите, будет ли та же операция успешной после изменения. Включенная кнопка не является условием успеха.

Технические значения сообщений собраны в [Ссылка на диагностику](../reference/diagnostics.md).

### Диагностика экспорта за один сеанс {/* #session-diagnostics */}

1. Откройте затронутый сеанс и выберите **Export diagnostics…** в его заголовке или **Export → Export diagnostics…** в меню сеанса.
2. Проанализируйте доступные источники. **session.json** и **Session database records** относятся к выбранной сессии. **main.log** и журналы исторических приложений также могут содержать метаданные из других сессий; Выберите их только в случае необходимости.
3. Выберите **Export**, выберите пункт назначения и дождитесь, пока **Diagnostics exported.** будет использовать **Show in folder**, чтобы найти архив.
4. Проверьте его манифест и экспортный журнал, прежде чем делиться. Отсутствующий или поврежденный источник может быть обобщен или опущен; Существование архива само по себе не доказывает, что все источники были захвачены.

![Выбор конкретных диагностических источников перед местным экспортом](/img/open-science/v0330/session-diagnostics.webp)

Обычный экспорт метаданных исключает частные поля контента. Если экспорт .science запускает проверку конфиденциального контента, список источников также может содержать отредактированные доказательства сканера и оригинальные помеченные файлы. **Оригинальные конфиденциальные файлы по умолчанию не проверяются; Выбор одного из них включает его исходные байты в архиве.** Выберите только необходимые источники и проверьте архив и скриншоты, прежде чем делиться ими. Экспорт остается локальным и не делает загрузку или запрос модели. Это диагностические данные, а не резервная копия исследования; Используйте [.science пакет](research-packages.md) для передачи исследования.

### Отправить полезный вопрос GitHub {/* #submit-a-useful-github-issue */}

1. Поиск существующих проблем с использованием кода ошибки или отличительной фразы. Если такая же проблема существует, добавьте соответствующие детали воспроизведения.
2. Войдите в GitHub и откройте **Сообщение о жуках**. Используйте заголовок, такой как `[Bug]: database_open_failed when reopening a project`, с вашей фактической ошибкой.
3. Заполните **Что случилось?**, **Шаги к размножению**, **Операционная система** и **App version**. Добавьте **Provider / model**, когда это уместно, плюс активную структуру Агента.
4. Согласно **Соответствующие журналы или скриншоты**, к ним относятся первая ошибка и небольшое количество окружающего контекста. Добавьте общедоступную или минимальную выборку, когда проблема зависит от входных данных.
5. Просмотрите отчет, затем отправьте его. Сохраните URL-адрес проблемы и опубликуйте результат любой предлагаемой проверки в той же проблеме. Если GitHub не предлагает создание проблем для вашей учетной записи, используйте Discord для поиска подходящего маршрута отчетности.

Используйте этот контрольный список при подготовке вопроса или вопроса о разногласиях:

```text
Open-Science version and installation method:
Operating system and architecture:
Agent framework / provider / model (if relevant):
Page and action:
Steps to reproduce:
Expected result:
Actual result:
Exact error code and full message:
Time of failure and time zone:
Public/minimal input (if needed):
Checks already tried and their results:
Relevant log excerpt or screenshot:
```

Для удаленного сбоя также включают режим выполнения, идентификатор работы приложения, идентификатор работы планировщика при наличии, код выхода и соответствующий stdout/stderr. Используйте нейтральный псевдоним для частного хозяина. Не прикрепляйте пароли, токены, закрытые ключи SSH, данные о пациентах или всю частную папку исследования; Замените конфиденциальные данные в минимальном примере.

### Подготовьте отчет об ошибке {/* #prepare-a-report-from-an-error */}

Выберите **Report this error** рядом с ошибкой разговора. Экран для запуска также может предложить **Still stuck? Create an issue for help**.

1. Прочитайте **Error details** и удалите личные пути, идентификаторы или конфиденциальный ввод перед обменом.
2. Проверьте **Also included** для версии приложения, операционной системы, фреймворка Агента, версии провайдера/модели и среды выполнения.
3. Используйте **Copy details** для копирования отредактированного текста и информации о среде. **Reveal log file** находит локальный журнал времени выполнения; Он не прикрепляется автоматически и нуждается в отдельном обзоре перед обменом.
4. Проверьте публичное признание, чтобы включить **Open GitHub issue**. Редактирование текста ошибки требует повторной проверки и подтверждения пересмотренного содержания.
5. Откройте форму GitHub, проверьте предварительно заполненные поля, добавьте полезные шаги воспроизведения, а затем отправьте, когда будете готовы. Одно только открытие предварительного обзора доклада не представляет проблемы.

## Общие вопросы {/* #common-questions */}

**Нужен ли мне модельный счет для каждой операции?** нет. Локальный просмотр, организация и множество настроек могут работать без модели. Ответы агентов, планирование анализа и сгенерированные моделью обзоры нуждаются в совместимом доступе к модели.

**Означает ли локальное хранилище, что вся обработка остается на устройстве?** нет. Выбранные подсказки, файлы или извлеченный контент могут быть отправлены в настроенную модель / службу при использовании. Локальные файлы и местоположение выполнения модели - это отдельные вопросы.

**Могу ли я работать в автономном режиме?** Существующие локальные файлы и доступные локальные просмотры могут оставаться пригодными для использования. Размещаемые модели, онлайн-базы данных и загрузки недостающих пакетов требуют соответствующих соединений. Удаленная/местная конечная точка также нуждается в собственном обслуживании.

**Является ли использование счета или баланс подписки?** нет. Он сообщает о доступной телеметрии. Недостающее использование не равно нулю; Платежи/лимиты сервиса остаются отдельными.

**Восстановление архива возобновляет работу?** нет. Восстанавливает навигацию для незавершенной работы. Живое ядро или неудачная операция могут по-прежнему требовать явного перезапуска / повтора.

**Успешный тест SSH означает, что мой анализ может работать?** нет. Проверьте выбранный режим выполнения, разрешения планировщика, время выполнения и запрос ресурса, затем запустите небольшую работу и проверьте ее выход. Смотрите [Дистанционные вычисления](remote-compute.md).
