# Сеть, прокси и зеркала пакетов {/* #network-proxies-and-package-mirrors */}

Откройте **Settings → Network**, когда модель, запрос Notebook или загрузка пакета не могут достичь пункта назначения. Эта страница разделяет статус соединения, разрешенные Notebook домены, прокси-сервер процесса и зеркала пакета. Проверка зеленых соединений не доказывает, что каждый защищенный запрос Notebook будет успешным.

Начните с неудачной операции: запрос провайдера, доступ к сети Notebook и установщик пакетов могут использовать разные маршруты. Держите имя хоста и точную ошибку при изменении этих настроек.

## Статус сети читать сначала {/* #read-network-status-first */}

Статус сочетает в себе информацию о сетевых ссылках и зонд пакетного реестра. **Готовы · Регистры пакетов доступны** указывает на то, что зонд удался. **Проверка**, недоступные или автономные состояния указывают на необходимость другой проверки или ремонта соединения. Используйте **Check again**, когда он доступен, после изменения соединения.

Если Сеть сообщает о **Ready**, но инструмент не работает, расширьте ошибку этого инструмента. зонд состояния проверяет свое место назначения; использовать имя и сообщение несостоявшегося запроса для диагностики поврежденного маршрута.

| неудача | Проверить дальше | Избегайте ошибочных выводов |
| --- | --- | --- |
| Логин провайдера не работает | Проверка подлинности провайдера и проверка подключения модели | Настройки домена Notebook будут предоставлять учетные данные модели |
| Одно имя хоста исследования отрицается | **Manage access** и точное имя хоста в запросе | Добавление широкого несвязанного домена исправит это. |
| Хостинг пакетов уже разрешен, но CONNECT не работает | Журнал установщика, прокси-сервер и разрешение DNS | Другой идентичный клик «Разрешить» устранит все сбои в сети |
| Проверка сертификата не удалась | Настроенный пакет CA и требования к доверию организации | Отключение проверки сертификата необходимо |
| Индекс пакетов не возвращает распределение после ошибок подключения | Ранние сетевые сообщения и выбранная платформа Python | Пакет не должен существовать |

## Настройка правил публичной сети {/* #public-network-rules */}

1. Открыть **Settings → Network → Manage access**. Прочитайте **Public internet access**, чтобы узнать, какие публичные чтения HTTPS могут продолжаться и какие запросы требуют одобрения.
2. Проверьте **Built-in services**. Группа с пометкой **Required** остается включенной; Для этой задачи могут быть выбраны другие группы.
3. Под **Custom public domains** введите точный **Domain hostname**, затем выберите **Add to list**. Просмотрите проект записи перед **Save changes**.

Правило публичного домена позволяет отправлять данные на это имя хоста; Он не распространяется на поддомены и не предоставляет доступ к частному адресу. Введите имя хоста без схемы, пути, порта, wildcard или IP-адреса. Имя хоста, разрешающее непубличный адрес, по-прежнему нуждается в соответствующем обзоре частных услуг. Эти правила также применяются, когда защищенный код следует за ссылками или извлекает значки.

## Доверьтесь частному сервису {/* #trusted-private-services */}

Используйте это только для известной внутренней службы, к которой должен получить доступ ваш исследовательский код. Это управление доступно в настольном приложении. Поддерживаются только адреса частных служб; Localhost, этот компьютер и зарезервированные адреса остаются заблокированными. Поле не принимает необработанные IP-адреса или wildcards.

1. В **Trusted private services** выберите **Add service** и введите **Hostname** и **Port**. Подтвердить точную услугу; По умолчанию порт 443.
2. Выберите **Review service**. Проверяйте **Approved addresses** перед выбором **Add to trusted services**.
3. Просмотрите список и выберите **Save changes**. DNS проверяется перед сохранением; Изменение адреса требует еще одной проверки.
4. Отправьте небольшой запрос в эту конкретную службу и проверьте ее ответ. Один только обзор адресов не проверяет аутентификацию или доступность услуг.

Грант покрывает точное имя хоста, порт и пересмотренные адреса. Это позволяет защищенному коду Notebook и Shell отправлять данные в эту службу во всех проектах. Добавьте только доступ, необходимый для выполнения задачи. Сохранение сетевых правил сбрасывает защищенные соединения и может прервать активную передачу; Завершите этот перевод перед внесением изменений.

## Выберите режим proxy {/* #choose-a-proxy-mode */}

Выберите **Configure proxy**. Используйте прокси-адрес, предоставленный вашей собственной конфигурацией сети; Порт на скриншоте специфичен для этого компьютера.

| Режим | поведение | Требуемый ввод |
| --- | --- | --- |
| **System** | Запросы приложений следуют за прокси-сервером устройства; Агентские процессы наследуют прокси-среду от запуска приложений | Нет явного поля сервера |
| **Manual** | Дайте новые запросы и процессы приложения с фиксированным прокси | **Proxy server** URL |
| **Direct** | Подключение без настроенного/унаследованного прокси для новых процессов | Нет серверного поля |

Ручной режим принимает URL-адреса HTTP, HTTPS, SOCKS, SOCKS4 и SOCKS5. Встроенные учетные данные в URL не поддерживаются. **Bypass rules** - это дополнительный список хостов, которые должны подключаться напрямую; Локальный хозяин всегда обойден.

1. Выберите **Manual**.
2. Заполните **Proxy server** рабочим прокси-адресом, используемым вашей сетью.
3. Добавьте правила обхода только в том случае, если соответствующие пункты назначения должны подключаться напрямую.
4. Выберите **Save** и ждите **Proxy settings saved.**
5. Начните новый запрос/процесс и протестируйте исходную неисправную операцию. Существующие сеансы агентов, ядра и установщики могут сохранять свои существующие соединения.

Если в ручном режиме сообщается о **Введите URL прокси-сервера**, введите рабочий прокси-адрес или отбросьте черновик с помощью **Done**. Сохранение действительного адреса само по себе не подтверждает, что прокси-сервер может нести неисправный запрос.

### Когда домен переходит на непубличный адрес {/* #observed-fake-ip-failure */}

Если установка сообщает `destination resolves to a non-public network address`, проверьте подробный журнал установки, даже если в короткой ошибке указано только `conda install failed` или `pip install failed`.

```text
deny network-outbound pypi.org:443
(destination resolves to a non-public network address)
```

1. Проверьте имя хоста и его разрешенный адрес. Адреса, такие как `198.18.*`, не являются общедоступными.
2. Отличить решение доменного списка от проверки назначения. `alreadyAllowed` не устанавливает, что разрешенный адрес является приемлемым.
3. Проверьте публичное разрешение DNS и предполагаемый прокси-маршрут с владельцем сети, а затем повторите первоначальный небольшой запрос. Держите защиту домена включенной.
4. Проверяйте установку и импорт отдельно. Сохраненного прокси-сервера, готового переводчика или успешного использования существующих пакетов недостаточно.

Если та же ошибка сохраняется, сохраните имя хоста, разрешенный адрес и прокси-режим с журналом установщика и следуйте [устранение неполадок](troubleshooting.md). Успешное сохранение настроек не является успешной загрузкой.


## Настройка пакетных зеркал и сертификат доверия {/* #configure-package-mirrors-and-certificate-trust */}

Выберите **Configure** или **Edit** под зеркалом пакета.

| Полное поле | Ввод и эффект |
| --- | --- |
| **Conda channel mirror** | Корень зеркала, используемый для загрузки канала Conda |
| **Python package index (pip)** | URL-адрес пакета Python, обычно заканчивающийся на `/simple` |
| **CA bundle path** | Путь к полному пакету PEM-доверий, включая необходимые государственные и корпоративные корни; бланк использует публичные сертификаты |
| **View available mirrors** | Открытый внешний зеркальный документ |
| **Save** | Храните конфигурацию для последующих операций с пакетами |
| **Cancel** | Откажитесь от проекта |

![Зеркало пакета и входные данные CA-bundle](/img/open-science/walkthrough-2026-09-08/56-package-mirror.webp)

Зеркало пакета изменяет источник пакета. Подтвердите требуемый формат root/index зеркала, сохраните и повторите небольшую операцию пакета в выбранном времени выполнения. Параметры прокси-сервера Model-Provider являются отдельными.

Настроенные имена хостов Conda, PyPI и CRAN получают временный доступ для управления пакетами. Это не добавляет их в постоянный список доменов Notebook или не предоставляет обычному коду Notebook такой же доступ. Перенаправления на другие хосты по-прежнему следуют за потоком одобрения сети.

Используйте поддерживаемый зеркальный URL-адрес HTTP (S) без встроенных учетных данных, белого пространства, локального хоста или необработанного IP-адреса. Принятая настройка зеркала не фиксирует недоступный сервер или имя хоста, разрешающее зарезервированный адрес. Если установка выходит из строя, проверьте фактическое назначение и ошибку этой операции перед повторным использованием. Удаленные конечные точки **model** имеют отдельный [Требование HTTPS](providers.md#custom-gateway-every-visible-field).

## Информация, которую нужно сохранить, когда запрос не выполняется {/* #information-to-keep-when-a-request-fails */}

Записывайте версию приложения, работу, время выполнения / среду, пакет или имя хоста, режим прокси и первую полезную ошибку. Сохраняйте исходный выход установщика: конечная линия «Нет соответствующего распределения» может скрыть более ранние сбои подключения. Исключите токены и прокси-удостоверения из общей диагностики.

Для отсутствующего модуля Python после успешного соединения продолжайте использовать [время выполнения и проверки пакетов](./runtimes.md). Удаленная настройка хоста отдельно рассматривается в [Вычисления](remote-compute.md).

## Поиск ошибки HTTP {/* #http-error-lookup */}

Для ответов 400, 401, 403, 404, 429 или 5xx используйте [Таблица устранения неполадок HTTP](troubleshooting.md#http-errors-400-403-429-and-5xx). Сохраняйте службу реагирования и ее подробное сообщение с кодом состояния.

После изменения настроек прокси-сервера, зеркала или домена Notebook подтвердите, что значения сохраняются, а затем повторите исходную операцию в том же режиме выполнения. Проверьте как загрузку, так и импорт пакета; Успешные настройки, за исключением одного, не устраняют ошибку установки.

## Ячейка R была заблокирована перед казнью {/* #r-network-warning */}

В v0.31.1 Notebook показывает встроенное предупреждение, когда сетевая защита блокирует запуск R. Следуйте по его установочной ссылке и проверьте запрашиваемый доступ. Предупреждение означает, что ячейка не была выполнена; Это не научный результат или завершенный забег. После решения конкретного требования снова запустить ячейку и проверить ее выход. Поддержка R в стандартном режиме Windows сама по себе не обеспечивает защиту сети.
