# Установка и обновления {/* #installation-and-updates */}

Большинство пользователей должны установить пакет рабочего стола из GitHub Releases. Участники или любой, кто тестирует новейший код, могут запустить приложение из источника. Клиент рабочего стола Electron подключается к общему серверу Node, который также обслуживает аутентифицированный локальный интерфейс браузера.

<PlatformGuide />

**Доступность v1.0.0:** [Этот релиз](https://github.com/aipoch/open-science/releases/tag/v1.0.0) содержит только десктопные пакеты, без автономных архивов CLI или Linux CLI `.deb`/`.rpm` пакетов. Скачайте с этой страницы и проверьте ее на `SHA256SUMS.txt`. Загрузка веб-сайтов и автоматические каналы обновления рекламируются отдельно, поэтому проверка может еще не предлагать 1.0. Настольные установки по-прежнему обеспечивают **Settings → General → Command line tool → Install command**.

## Выберите метод установки {/* #choose-an-installation-method */}

### Скачать десктопный установщик {/* #install-the-desktop-app */}

1. Открыть [Open-Science выпустили](https://github.com/aipoch/open-science/releases).
2. Загрузите пакет, который соответствует вашей операционной системе и архитектуре процессора.
3. Прочитайте лицензию, показанную установщиком, и заполните установку, затем запустите приложение. Пятиступенчатый мастер настройки открывается на первом пробеге.
4. Если операционная система блокирует неподписанное приложение, скачайте его снова из официального репозитория AIPOCH GitHub и следуйте запросу безопасности платформы только после проверки источника.

Выберите из **Активы**, прикрепленного к выпуску, а не автоматически сгенерированный исходный код ZIP. Доступность зависит от опубликованных активов этого выпуска.

В папке установки хранится приложение, а в папке **Data location**, выбранной в мастере настройки, — исследовательские файлы и среды выполнения. Эти расположения настраиваются отдельно. После установки перейдите к [первоначальной настройке](onboarding.md).

### Используйте автономный CLI {/* #standalone-cli */}

**Шаги отдельного пакета ниже применяются к выпускам, которые фактически отгрузили их, таким как: [v0.37.2](https://github.com/aipoch/open-science/releases/tag/v0.37.2)Не для активов v1.0.0.** Используйте эту старую версию только намеренно. Сопоставьте версии для настольных компьютеров и бэкэндов и не указывайте на более старый бэкэнд данных, написанных новым приложением. Для входа в командную строку 1.0 установите пусковую установку, поставляемую его настольным приложением, и следуйте [Настройка CLI](../reference/cli.md#terminal-setup).

#### Домашний джекпот CLI {/* #homebrew-cli */}

Существующая установка Homebrew CLI управляется через `brew install aipoch/tap/open-science`, отдельно от настольной бочки. Проверьте версию, которую предлагает Homebrew. Публикация 1.0 на GitHub не устанавливает, что формула продвинулась вперед. Установка не запускает системный сервис. Если пусковые установки конфликтуют, проверьте `type -a open-science` и используйте `"$(brew --prefix aipoch/tap/open-science)/bin/open-science"` для этой установки.

#### Пакеты Linux CLI {/* #linux-cli-packages */}

В этой таблице сохранен метод установки **v0.37.2** Linux CLI; v1.0.0 не публикует пакеты CLI. `open-science-cli` отделен от пакета рабочего стола `aipoch-open-science`. Если вам нужна более старая версия, получите актив и `CLI-PACKAGE-SHA256SUMS.txt` от [Активы v0.37.2](https://github.com/aipoch/open-science/releases/tag/v0.37.2), а затем проверьте перед установкой.

| Распределение/архитектура | v0.37.2 CLI актив |
| --- | --- |
| Debian / Ubuntu, x64 | `open-science-cli_0.37.2_amd64.deb` |
| Debian / Ubuntu, ARM64 | `open-science-cli_0.37.2_arm64.deb` |
| Федора, x64 | `open-science-cli-0.37.2-1.x86_64.rpm` |
| Федора, ARM64 | `open-science-cli-0.37.2-1.aarch64.rpm` |

Установите загруженный файл с соответствующим менеджером пакетов. В этих примерах используется x64; При необходимости используйте имя файла ARM64.

```bash
# Debian / Ubuntu
sudo apt install ./open-science-cli_0.37.2_amd64.deb
# Fedora: use this instead of the apt command
sudo dnf install ./open-science-cli-0.37.2-1.x86_64.rpm
```

Запустите `open-science-cli start --no-open`, затем `open-science-cli status --json`. После запуска используйте `open-science-cli url` для открытия аутентифицированного локального веб-интерфейса. Держите этот URL приватным. Продолжайте с [Настройка CLI](../reference/cli.md#terminal-setup) для конфигурации модели и проверки `doctor`, заменив `open-science` на `open-science-cli` в этих командах.

Пакет объединяет Node, бэкэнд и веб-интерфейс. Он не устанавливает Python/R и не создает автоматически запущенную системную службу. Предпосылки для хранения учетных данных ОС и песочницы по-прежнему применяются; См. [Безголовые учетные данные Linux](../reference/server.md). Используйте `open-science-cli` явно, когда установлена настольная пусковая установка.

Перед обновлением или удалением пакета завершите работу и остановите **Каждый профиль, начатый этим пакетом**. Установите следующий загруженный пакет через apt/dnf; Не существует репозитория AIPOCH apt/dnf, сконфигурированного с помощью этой установки. Удаление пакета сохраняет данные исследований и учетные данные. [Официальный путеводитель](https://github.com/aipoch/open-science/blob/v0.37.2/docs/standalone-runtime.md#linux-cli-distribution-packages) описывает командные конфликты и требования к платформе.

### Бег от источника {/* #run-from-source */}

Вам нужны Git, Node.js 24, npm, и платформа создает предпосылки для Electron. Установите или выберите фреймворк агента в приложении. Во время установки репозиторий генерирует клиент Prisma, применяет патчи приложений и подготавливает собственные зависимости Electron.

Для установки воспроизводимого источника выберите предполагаемый тег выпуска от [Изменить](../changelog/v1.0.0.md) перед установкой зависимостей. Клон по умолчанию следует за ветвью, а не за фиксированным выпуском. Запишите выбранный тег, исходный код и версии выполнения, чтобы другой человек мог воспроизвести окружающую среду.

Замените `RELEASE_TAG` ниже точным тегом, показанным на выбранном релизе (включая его ведущий `v`). Вместо этого, чтобы следить за текущим развитием, опустите `--branch RELEASE_TAG --depth 1`. Эта проверка будет следовать за ветвью по умолчанию.

```bash
git clone --branch RELEASE_TAG --depth 1 https://github.com/aipoch/open-science.git
cd open-science
npm install
npm run dev
```

Перед упаковкой производственной сборки запускайте:

```bash
npm run build
```

Используйте пакеты тегов package.json и [Отдельный Runtime Guide](https://github.com/aipoch/open-science/blob/v1.0.0/docs/standalone-runtime.md) для построения целей и зависимостей. `npm run dev:web` разрабатывает точку входа Node/Web; `npm run dev` также готовит настольный клиент. Используйте изолированный каталог конфигурации для разделения тестовых данных.

### Местные данные {/* #local-data */}

Мастер настройки показывает управляемое местоположение данных для больших исследовательских файлов, таких как артефакты, файлы Notebook и среды. Настройки приложений и история разговоров остаются в местоположении конфигурации. Перемещение местоположения данных исследования не является полной резервной копией приложения. Держите его отдельно от исходного хранилища; Используйте [Хранилище](storage.md), чтобы переместить его вместо ручного перемещения внутренних файлов во время работы приложения.

## Подтвердите, что приложение готово {/* #installation-is-complete-when */}

Открывается приложение, проходит необходимая проверка среды, устанавливается агент, проверяется доступ к модели. Настройка Python/R также требуется только для работы, которая выполняет эти языки. Открытие предварительного просмотра CSV или PDF не подтверждает время выполнения Notebook. Следуйте за [Первый раз установка](./onboarding.md), затем за [Поставщик и локальная настройка модели](./providers.md).

## Проверьте обновления приложений {/* #choose-a-reproducible-version-and-update-deliberately */}

В **Settings → General → About** прочитайте установленную версию и используйте **Check now** для проверки доступности обновления. Проверьте указанную версию перед ее установкой и закончите сначала активную работу. Создание источника разработки может сообщать об обновлениях иначе, чем упакованная установка. Хранить копию важных экспортируемых результатов до обновления; не переименовывать внутренние каталоги данных приложения.

Из 1.0 удаляется `open-science update`. Обновите приложение с помощью элементов управления рабочим столом или официального установщика и обновите установку CLI через менеджер установщика / пакета, которому оно принадлежит. Если **Check now** еще не предлагает опубликованный релиз, проверьте официальную страницу релиза. Удаление конфигурации или сброс приложения не будет способствовать обновлению канала.

<PlatformContent platform="macos">

Если появится **Установите Open-Science перед обновлением**, приложение будет работать только с места чтения. Выберите **Установить в «Программы»** или переместите приложение в Finder. После установки используйте **Перезапустить** или выйдите из этой копии и снова откройте ее в Приложениях, а затем снова проверьте наличие обновлений. **Продолжить работу** сохраняет текущую копию открытой; Это не делает это местоположение обновляемым. Если установка не удалась, следуйте отображаемой ошибке перед повторным использованием.

</PlatformContent>

<PlatformContent platform="windows">

Переустановка сохраняет существующие данные. Если вам необходимо начать работу с новой информацией после проблемы с данными, см. [Сброс локальных данных Windows](troubleshooting.md#windows-data-reset). Этот отдельный инструмент удаляет данные; Это не является частью обычного обновления.

</PlatformContent>

| Установка источника | Подтвердите `node --version` и `npm --version`и это `npm install` Закончено. Повторите прерванную установку зависимости. |
| первоначальной настройке | Прочитайте неудавшуюся проверку окружающей среды и устраните ее заявленное требование, прежде чем продолжить. |

## Название продукта после v0.31.0 {/* #product-name */}

Современный интерфейс и новые пакеты используют **Open-Science**. Модернизация сохраняет существующие названия и местоположения установки, данные исследований, учетные данные и настройки. Более старый путь установки, содержащий `Open Science`, сам по себе не является отказом от обновления. не переименовывать и не перемещать свои папки данных в соответствии с новым именем дисплея.

## Обновление до 1.0 и понимание совместимости {/* #version-compatibility */}

1. Завершите активное исследование и резервное копирование каталога конфигурации плюс любое отдельно настроенное местоположение данных. Один экспорт `.science` не является резервной копией всего профиля.
2. Закройте экземпляры рабочего стола / бэкэнда с помощью установки, а затем обновите через официальный установщик. Сохранить оригинальный профиль, данные и хранилище учетных данных ОС.
3. Откройте и проверьте версию, проекты, сессии, файлы, модели и время выполнения, прежде чем продолжить. Бинарное понижение не откатывает данные; Старые двоичные файлы могут не читать новые сохраненные данные.

1.0 сохраняет существующие исторические пути обновления и импорта. Номер версии не требует сброса профиля. [Политика совместимости 1.x](https://github.com/aipoch/open-science/blob/v1.0.0/docs/compatibility.md) охватывает документированные интерфейсы автоматизации CLI/SDK и Task, прямой импорт действительных пакетов `.science` и поддерживаемые обновления профиля. Он не гарантирует идентичные ответы на модели, доступность для третьих сторон или детерминированное воспроизведение всей исследовательской сессии или кросс-платформенную передачу учетных данных, защищенных ОС. Решения безопасности нацелены на последний стабильный выпуск.
