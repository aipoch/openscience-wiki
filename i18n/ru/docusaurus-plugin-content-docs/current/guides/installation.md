# Установка и обновления {/* #installation-and-updates */}

Большинство пользователей должны установить пакет рабочего стола из GitHub Releases. Участники или любой, кто тестирует новейший код, могут запустить приложение из источника. Клиент рабочего стола Electron подключается к общему бэкэнду узла, который также обслуживает аутентифицированный локальный интерфейс браузера.

<PlatformGuide />

**Текущие пакеты:** [Активы v1.3.3](https://github.com/aipoch/open-science/releases/tag/v1.3.3) включает в себя установщики настольных компьютеров, автономные архивы CLI и пакеты Linux CLI `.deb`/`.rpm`. Выберите предполагаемый тип установки и архитектуру, а затем проверьте контрольную сумму из того же выпуска. Десктопная пусковая установка остается доступной через **Settings → General → Command line tool → Install command**.

## Выберите метод установки {/* #choose-an-installation-method */}

### Скачать десктопный установщик {/* #install-the-desktop-app */}

1. Открыть [Open-Science выпустили](https://github.com/aipoch/open-science/releases).
2. Загрузите пакет, который соответствует вашей операционной системе и архитектуре процессора.
3. Прочитайте лицензию, показанную установщиком, и заполните установку, затем запустите приложение. На первом этапе открывается пятиступенчатый мастер настройки.
4. Если операционная система блокирует неподписанное приложение, скачайте его снова из официального репозитория AIPOCH GitHub и следуйте запросу безопасности платформы только после проверки источника.

Выберите из **Активы**, прикрепленного к выпуску, а не автоматически сгенерированный исходный код ZIP. Доступность зависит от опубликованных активов этого выпуска.


В папке установки хранится приложение, а в папке **Data location**, выбранной в мастере настройки, — исследовательские файлы и среды выполнения. Эти расположения настраиваются отдельно. После установки перейдите к [первоначальной настройке](onboarding.md).

### Используйте автономный CLI {/* #standalone-cli */}

Для установки терминала/браузера загрузите соответствующий автономный архив CLI из [v1.3.3](https://github.com/aipoch/open-science/releases/tag/v1.3.3). Он объединяет Node, бэкэнд и веб-интерфейс. Извлеките полный каталог, затем следуйте [Настройка CLI](../reference/cli.md#terminal-setup). Держите CLI и бэкэнд от одной и той же установки вместе.

#### Домашний джекпот CLI {/* #homebrew-cli */}

Установите или управляйте Homebrew CLI с помощью `brew install aipoch/tap/open-science` отдельно от настольной бочки. Проверьте версию, которую предлагает Homebrew. Формула может отставать от выпуска GitHub. Установка не запускает системный сервис. Если пусковые установки конфликтуют, проверьте `type -a open-science` и используйте `"$(brew --prefix aipoch/tap/open-science)/bin/open-science"` для этой установки.

#### Пакеты Linux CLI {/* #linux-cli-packages */}

Для использования терминала/браузера Linux выберите **open-science-cli**, отдельно от пакета рабочего стола **айпоч-открытой науки**. Загрузите пакет соответствия и `CLI-PACKAGE-SHA256SUMS.txt` из [Активы v1.3.3](https://github.com/aipoch/open-science/releases/tag/v1.3.3), затем проверьте перед установкой.

| Распределение/архитектура | v1.3.3 CLI актив |
| --- | --- |
| Debian / Ubuntu, x64 | `open-science-cli_1.3.3_amd64.deb` |
| Debian / Ubuntu, ARM64 | `open-science-cli_1.3.3_arm64.deb` |
| Федора, x64 | `open-science-cli-1.3.3-1.x86_64.rpm` |
| Федора, ARM64 | `open-science-cli-1.3.3-1.aarch64.rpm` |

Установите загруженный файл с соответствующим менеджером пакетов. В этих примерах используется x64; При необходимости используйте имя файла ARM64.

```bash
# Debian / Ubuntu
sudo apt install ./open-science-cli_1.3.3_amd64.deb
# Fedora: use this instead of the apt command
sudo dnf install ./open-science-cli-1.3.3-1.x86_64.rpm
```

Запустите `open-science-cli start --no-open`, затем `open-science-cli status --json`. После запуска используйте `open-science-cli url` для открытия аутентифицированного локального веб-интерфейса. Держите этот URL приватным. Продолжайте с [Настройка CLI](../reference/cli.md#terminal-setup) для конфигурации модели и проверки `doctor`, заменив `open-science` на `open-science-cli` в этих командах.

Пакет объединяет Узел, бэкэнд и веб-интерфейс. Он не устанавливает Python/R и не создает автоматически запущенную системную службу. Предпосылки для хранения учетных данных ОС и песочницы по-прежнему применяются; См. [Безголовые учетные данные Linux](../reference/server.md). Используйте `open-science-cli` явно, когда установлена настольная пусковая установка.

Перед обновлением или удалением пакета завершите работу и остановите **Каждый профиль, начатый этим пакетом**. Установите следующий загруженный пакет через apt/dnf; Не существует репозитория AIPOCH apt/dnf, сконфигурированного с помощью этой установки. Удаление пакета сохраняет данные исследований и учетные данные. [Официальный путеводитель](https://github.com/aipoch/open-science/blob/v1.3.3/docs/standalone-runtime.md#linux-cli-distribution-packages) описывает командные конфликты и требования к платформе.

### Бег от источника {/* #run-from-source */}

Вам нужны Git, Node.js 24, npm, и платформа создает предпосылки для Electron. Установите или выберите фреймворк агента в приложении. Во время установки репозиторий генерирует клиент Prisma, применяет патчи приложений и подготавливает собственные зависимости Electron.

Для установки воспроизводимого источника выберите предполагаемый тег выпуска от [Изменить](../changelog/v1.3.3.md) перед установкой зависимостей. Клон по умолчанию следует за ветвью, а не за фиксированным выпуском. Запишите выбранный тег, исходный код и версии выполнения, чтобы другой человек мог воспроизвести окружающую среду.

Замените `RELEASE_TAG` ниже точным тегом, показанным на выбранном релизе (включая его ведущий `v`). Вместо этого, чтобы следить за текущим развитием, опустите `--branch RELEASE_TAG --depth 1`. Эта проверка будет следовать за ветвью по умолчанию.

```bash
git clone --branch RELEASE_TAG --depth 1 https://github.com/aipoch/open-science.git
cd open-science
npm install
npm run dev
```

Перед упаковкой производственной сборки, запускайте:

```bash
npm run build
```

Используйте пакеты тегов package.json и [Отдельный Runtime Guide](https://github.com/aipoch/open-science/blob/v1.3.3/docs/standalone-runtime.md) для построения целей и зависимостей. `npm run dev:web` разрабатывает точку входа в Node/Web. `npm run dev` также готовит настольный клиент. Используйте изолированный каталог конфигурации для разделения тестовых данных.

### Местные данные {/* #local-data */}

Мастер настройки показывает управляемое местоположение данных для больших исследовательских файлов, таких как артефакты, файлы Notebook и среды. Настройки приложений и история разговоров остаются в местоположении конфигурации. Перемещение местоположения данных исследования не является полной резервной копией приложения. Держите его отдельно от исходного хранилища; Используйте [Хранилище](storage.md), чтобы переместить его вместо ручного перемещения внутренних файлов во время работы приложения.

## Подтвердите, что приложение готово {/* #installation-is-complete-when */}

Приложение открывается, обязательные проверки среды пройдены, выбранный Agent готов и активен, а подключение к модели проверено. Open-Science Agent входит в приложение; отдельная установка или обнаружение среды нужны только при выборе внешней платформы. Настройка Python/R также требуется только для работы, которая выполняет эти языки. Открытие предварительного просмотра CSV или PDF не подтверждает время выполнения Notebook. Следуйте за [Первый раз установка](./onboarding.md), затем за [Поставщик и локальная настройка модели](./providers.md).

## Проверьте обновления приложений {/* #choose-a-reproducible-version-and-update-deliberately */}

В **Settings → General** прочитайте установленную версию и используйте **Check now** для проверки доступности обновления. Проверьте указанную версию перед ее установкой и закончите сначала активную работу. Создание источника разработки может сообщать об обновлениях иначе, чем упакованная установка. Хранить копию важных экспортируемых результатов до обновления; не переименовывать внутренние каталоги данных приложения.

Из 1.0 удаляется `open-science update`. Обновите приложение с помощью элементов управления рабочим столом или официального установщика и обновите установку CLI через менеджер установщика / пакета, которому оно принадлежит. Если **Check now** еще не предлагает опубликованный релиз, проверьте официальную страницу релиза. Удаление конфигурации или сброс приложения не будет способствовать обновлению канала.

<PlatformContent platform="macos">

Если появится **Установите Open-Science перед обновлением**, приложение будет работать только с места чтения. Выберите **Установить в «Программы»** или переместите приложение в Finder. После установки используйте **Перезапустить** или выйдите из этой копии и снова откройте ее в Приложениях, а затем снова проверьте наличие обновлений. **Продолжить работу** сохраняет текущую копию открытой; Это не делает это местоположение обновляемым. Если установка не удалась, следуйте отображаемой ошибке перед повторным использованием.

</PlatformContent>

<PlatformContent platform="windows">

Переустановка сохраняет существующие данные. Если вам необходимо начать работу с новой информацией после проблемы с данными, см. [Сброс локальных данных Windows](troubleshooting.md#windows-data-reset). Этот отдельный инструмент удаляет данные; Это не является частью обычного обновления.

</PlatformContent>

| Установка источника | Подтвердите `node --version` и `npm --version`и это `npm install` Закончено. Повторите прерванную установку зависимости. |
| первоначальной настройке | Прочитайте неудавшуюся проверку окружающей среды и устраните ее заявленное требование, прежде чем продолжить. |

## Название продукта после v0.31.0 {/* #product-name */}

Современный интерфейс и новые пакеты используют **Open-Science**. Модернизация сохраняет существующие названия и местоположения установки, данные исследований, учетные данные и настройки. Более старый путь установки, содержащий `Open Science`, сам по себе не является отказом от обновления. не переименовывать и не перемещать свои папки данных в соответствии с новым именем дисплея.

## Обновление до 1.0 и понимание совместимости {/* #version-compatibility */}

1. Завершите активное исследование и резервное копирование каталога конфигурации плюс любое отдельно настроенное местоположение данных. Один экспорт `.science` не является резервной копией всего профиля.
2. Закройте экземпляры рабочего стола / бэкэнда с помощью установки, а затем обновите через официальный установщик. Сохранить оригинальный профиль, данные и хранилище учетных данных ОС.
3. Откройте и проверьте версию, проекты, сессии, файлы, модели и время выполнения, прежде чем продолжить. Бинарное понижение не откатывает данные; Старые двоичные файлы могут не читать новые сохраненные данные.

1.0 сохраняет существующие исторические пути обновления и импорта; номер версии не требует сброса профиля. [Политика совместимости 1.x](https://github.com/aipoch/open-science/blob/v1.3.0/docs/compatibility.md) охватывает документированные интерфейсы автоматизации CLI/SDK и Task, прямой импорт действующих пакетов `.science` и поддерживаемые обновления профиля. Он не гарантирует идентичные ответы на модели, доступность для третьих сторон или детерминированное воспроизведение всей исследовательской сессии или кроссплатформенную передачу учетных данных, защищенных ОС. Решения безопасности нацелены на последний стабильный выпуск.

## Установите CLI с помощью npm {/* #npm-cli */}

Используйте Node.js **22.13 или более поздняя версия** для опубликованного пакета CLI/backend. В терминале установите и проверьте срабатывающую версию:

```bash
npm install --global --include=optional @aipoch/open-science@1.3.3
open-science version --json
open-science help
```

Затем следуйте за [настройка терминала](../reference/cli.md#terminal-setup), чтобы инициализировать профиль, запустить его бэкэнд и настроить модель. Одна только установка не регистрирует вас или не устанавливает Python / R. Если настольная или Homebrew-пусковая установка уже использует одно и то же имя команды, проверьте, какой исполняемый файл выберет ваша оболочка, прежде чем продолжить. Остановить каждый бэкэнд, принадлежащий установке, прежде чем обновлять эту установку; Сохраняйте свой профиль и обновляйте его через исходный менеджер пакетов.

## Следите за обновлениями до установки {/* #update-progress */}

В **Settings → General** прочитайте установленную версию и выберите **Check now**. Просмотрите предлагаемый релиз и состояние загрузки и подготовки диалога обновления. Завершение загрузки не является завершением установки; Проверьте установленную версию после перезапуска.

В поддерживаемых стабильных пакетных установках **Automatically download updates** управляет фоновой подготовкой и включён по умолчанию. Его можно отключить и продолжать проверять и загружать обновления вручную. Автоматическая загрузка требует подтверждённого подключения без ограничений и тарификации по объёму данных, а также достаточного свободного места. Если состояние сети нельзя подтвердить, места недостаточно или каталог недоступен для записи, используйте ручной способ.

| Платформа | Право на автоматическое поведение | Когда использовать ручную установку |
| --- | --- | --- |
| macOS | Соответствующее подготовленное обновление может быть установлено, когда вы выходите из приложения | Объемы только для чтения, Транслокация приложений, неписаные установки или неподдерживаемые каналы |
| Windows | Подготовьте обновление для следующего запуска, как только рабочее пространство будет готово, а рабочий стол простаивает в фоновом режиме. | Подготовка блокируется, канал не поддерживается или вместо него предлагается установщик. |
| Linux Appmage | Подготовить обновление следующего запуска в фоновом режиме; Сохранить существующий путь AppImage | Кэш обновления незаписуем, пространство недостаточно или формат пакета не поддерживается. |

Завершите активную работу и позвольте очистке Notebook завершиться до того, как вы уйдете или перезагрузитесь. Используйте **Restart to update** или **Open installer** в соответствии с диалогом, затем проверьте версию и оригинальные проекты. Linux DEB и автономные установки CLI следуют собственному [канал установки](#manual-update); Веб-рабочее пространство не является автоматическим обновителем рабочего стола.

Если подготовка не удалась или автоматическая установка недоступна, используйте **Installation instructions** и официальный пакет. Не заставляйте приложение закрываться во время очистки.

## Установите обновление вручную {/* #manual-update */}

В диалоге обновления откройте **Installation instructions**. Использовать **Download from website** Если у вас нет пакета. Для подтвержденного загруженного установщика выберите **Show in Finder**, **Show in File Explorer** или **Show in file manager**В зависимости от платформы. Держите эту папку открытой, выходя из приложения.

Сохраните работу и дождитесь завершения активной установки или очистки перед запуском другого установщика. На macOS откройте DMG или отсоедините пакет и замените Open-Science в приложениях. В Windows запустите установщик, используя существующую папку установки. В Linux установите соответствующий DEB или замените AppImage и сохраните исполняемое разрешение. Следуйте инструкциям для вашего фактического формата пакета.

Если установщик отсутствует или изменился, загрузите его снова; раскрытие пакета не запускает его. Открыть открытую науку и проверить **Settings → General**Подтвердите свои оригинальные проекты и данные. При обновлении отдельных файлов CLI сначала [Проверить, что все пострадавшие службы остановлены](../reference/server.md#application-update-behavior).

## Проверьте данные исследования после обновления Windows {/* #windows-update-data */}

Установщик Windows v1.0.6 сохраняет данные исследований, хранящиеся рядом с приложением, и фиксирует установку в глубоких папках. Завершите активную работу, сохраните резервную копию важных проектов, затем используйте официальный установщик для обновления. После повторного открытия, проверьте **Settings → Storage**Откройте существующий проект и подтвердите, что его файлы доступны перед возобновлением задачи.

Исправление сохранения не является резервной копией или разрешением на перемещение управляемых данных вручную. Используйте [Контроль за хранением](storage.md) при изменении своего местоположения.

## Блокаторы подготовки обновлений {/* #update-preparation */}

Завершите активную работу перед установкой обновления. Если при подготовке называется процесс блокировки, закройте соответствующую программу в обычном режиме и повторите. Избегайте принуждения несвязанных процессов к прекращению. v1.0.8 корректирует несколько проверок заполнения macOS и Windows; Оставшийся блокировщик диалога по-прежнему требует внимания.

Если автоматическая установка недоступна, используйте ссылку справки ручной установки в **Settings → General**, загрузите соответствующий официальный пакет и проверьте его контрольную сумму. После перезапуска подтвердите установленную версию и оригинальные проекты. Если восстановление не удается, соберите диагностический журнал от General; Он сохраняет основную ошибку для устранения неполадок.

### Дифференциальная загрузка macOS {/* #differential-updates */}

Из v1.2.0 поддерживаемое обновление macOS может загружать только измененные блоки изображения приложения. Если этот путь недоступен или не может быть проверен, обновитель возвращается к полному пакету. Поэтому более крупная загрузка сама по себе не является неудачей. Пусть загрузка завершится, завершится подготовка обновления и подтвердится установленная версия после перезапуска. Автоматическая установка следует за [Условия платформы и канала](#update-progress).

## Обновление от v1.3.0 при блокировке установки {/* #update-from-130 */}

Если v1.3.0 говорит, что другой процесс использует установку даже после завершения активной работы, его обновитель может ошибочно принять фоновый процесс, принадлежащий приложению, за внешний блокировщик. Загрузите официальный пакет v1.3.1 для своей платформы, полностью прекратите работу с Open-Science и прекратите его фоновый сервис, а затем следуйте за [Шаги ручной установки](#manual-update). Для профиля, управляемого CLI, проверьте [Статус обслуживания и остановка](../reference/server.md#lifecycle-commands) перед заменой файлов.

Откройте приложение, подтвердите v1.3.1 в **Settings → General** и проверьте исходные проекты и местоположение данных. Сохраняются профили и данные исследований. Это исправление относится к обновлениям, начатым с v1.3.1. Недавно загруженный пакет не может изменить обновление, все еще работающее в v1.3.0.
