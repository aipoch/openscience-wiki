# Установка и переключение агентов {/* #installing-and-switching-agents */}

Выберите фреймворк Agent для выполнения диалогов и инструментов, затем настройте совместимого [поставщика моделей](providers.md). Можно сохранить несколько установленных фреймворков. Активный фреймворк в **Settings → Agent** — общая настройка приложения для всех проектов; она применяется к последующим ходам диалога и рабочим процессам.

## Прочитайте страницу агента {/* #read-the-agent-page */}

Открыть **Settings → Agent**. Страница отделяет **Installed** от **Available**. Прочитайте версию, путь и маркер **Active** на установленной карте, прежде чем что-либо менять.

![Обнаружен управляемый приложением Codex](/img/open-science/local-acceptance/agent-codex-active.webp)

| Контроль/статус | Значение и действие |
| --- | --- |
| Установленная карта | Выберите подходящую неактивную карту, чтобы запросить переключатель. Перечисленная установка все еще нуждается в совместимом доступе к модели. |
| Активен | Выбранный бэкэнд в масштабе приложения. Его действие Uninstall отключено. |
| Проверить снова | Обновите открытие после установки или изменения пути. временно обнаруживается; Он не устанавливает отсутствующее программное обеспечение. |
| Не установлен | Для этого фреймворка не было обнаружено пригодного для использования времени выполнения. |
| Установить меню | Выберите источник, предлагаемый для этой структуры, а затем проверьте ход установки. |
| Установить log / Retry | Прочитайте неудачный шаг и повторите попытку после устранения этой причины. |
| Восстановить | Появляется, когда управляемая установка нуждается в ремонте; Проверьте пострадавшее время выполнения, прежде чем подтвердить. |

Проверенная страница предлагала Codex, Claude Agent, OpenCode и CodeBuddy. Доступные источники и требования к аутентификации различаются. Не думайте, что каждый фреймворк предлагает один и тот же установщик или метод входа.

## Установка и проверка {/* #install-and-verify */}

1. Выберите **Установка &#91;кадры&#93;** и просмотрите предлагаемый источник. Управляемая установка остается под контролируемым приложением хранилищем; ручная установка должна быть обнаружена приложением.
2. Следуйте за прогрессом и прочитайте журнал установки, если шаг не удается. Решите условия среды / сети перед повторным использованием.
3. Используйте **Re-detect** после ручной установки. Подтвердите ожидаемую версию и путь, а не полагаясь на наличие команды в другом терминале.
4. Выберите готовую карту. Просмотрите диалог переключателей, затем подтвердите предполагаемый бэкэнд.
5. Проверьте **Settings → Model**, запустите небольшой запрос и проверьте фактический результат ответа / инструмента.

Для OpenCode **Install → App-managed download (recommended)** загружает автономный режим выполнения. На странице отображается Разрешение, прогресс загрузки, а затем Установленная карта с ее версией и маршрутом. Выберите эту карту, подтвердите **Переход на OpenCode?** и выберите совместимую модель. Пример локального соединения возвращает завершенный ответ; См. [Создание локального провайдера](./providers.md#connect-a-local-model-endpoint) для его API и пределов токенов.

Для Codex нативный адаптер времени выполнения и ACP должен проходить обнаружение в качестве совместимой пары. Установка только одного компонента не эквивалентна готовому бэкэнду. Логин подписки провайдера указан в [Настройка поставщика](./providers.md).

В v0.33.0 для **Claude Agent** требуется Claude CLI **2.1.118 или более поздняя версия**. Если обнаружение сообщает о неподдерживаемой версии, обновите обнаруженную установку с помощью метода установки, затем используйте **Re-detect** и проверьте готовность перед началом сеанса. Обновление другого CLI на вашем пути не восстанавливает установку, показанную на карте.

## Обновление приложения Codex Runtime {/* #update-codex */}

Откройте **Settings → Agent** и прочитайте версии **Codex CLI** и **ACP** на карте Codex отдельно. Если предлагается обновление тестируемой пары, завершите или закройте сеансы с использованием этого времени выполнения, выберите действие обновления и дождитесь завершения обнаружения. Подтвердите новые версии и готовность, затем отправьте небольшой запрос в сеансе.

Обновление, управляемое приложением, заменяет время выполнения, принадлежащее приложению; Внешний CLI должен быть обновлен с помощью оригинального метода установки, за которым следует **Re-detect**. Приложение отказывается от замены, в то время как запущенный приложением процесс Codex использует цель. Эта операция не обновляет сам Open-Science и не мигрирует в полете.

## Переключитесь, не путая сохраненную историю с живым государством. {/* #switch-without-confusing-retained-history-with-live-state */}

Перед переключением завершите или остановите текущую операцию. Изменение применяется к последующим ходам диалога и рабочим процессам всех проектов. Уже запущенные задачи используют прежнюю среду до завершения; неактивные диалоги подключаются заново при следующем использовании. Сохранение истории не переносит выполняющийся процесс инструмента и не гарантирует сохранения переменных интерпретатора. Перед продолжением вычислений проверьте файлы, Notebook и разрешения.

После переключения проверьте модель, выбранную для разговора. Подписка на Codex поддерживает [Side Chat](./delegation.md); Операции или восстановление сеанса могут временно предотвратить его открытие. Следуйте за сообщением, показанным входом.

## Ремонт и удаление {/* #repair-and-removal */}

Используйте поток восстановления приложения для сломанного управляемого времени выполнения; Не удаляйте его каталоги во время запуска установщика. Если показана внешняя установка, отремонтируйте эту установку и повторно обнаружите ее. Чтобы удалить управляемый бэкэнд, сначала активируйте другой готовый бэкэнд, откройте **Uninstall** и прочитайте список компонентов подтверждения. Удаление — это не шаг очистки, необходимый только для смены моделей.


### Удалить и переустановить время выполнения, управляемое приложением {/* #uninstall-and-reinstall-an-app-managed-runtime */}

1. Держите другой бэкэнд **Active**. В этом примере Codex оставался активным, в то время как OpenCode был удален.
2. На неактивной карте OpenCode выберите **Uninstall**. Подтверждение относится к копии, загруженной и управляемой этим приложением; Отдельно установленная копия не затрагивается.
3. Подтвердите **Uninstall**, затем выберите **Re-detect**. OpenCode должен перейти на **Available** с **Not installed**.
4. Выберите **Install OpenCode → App-managed download (recommended)**. Подождите **Installed**, затем выберите его и подтвердите **Switch**.
5. Проверьте **Active**, путь выполнения и выбор совместимой модели. Переустановка бэкэнда не настраивает для него поставщика моделей.

![Область применения OpenCode Uninstall](/img/open-science/priority-completion/01-opencode-uninstall.webp)

Перед удалением бэкэнда переключитесь на другой доступный бэкэнд; Активный бэкэнд не может быть удален с помощью этого контроля. После переустановки, повторного обнаружения и активации, откройте существующий проект и запустите небольшой запрос для проверки соединения.

![OpenCode снова установлен и выбран](/img/open-science/priority-completion/03-opencode-reinstalled.webp)

Если действия установки отключены, проверьте наличие другой установки / переключателя в процессе и указанную ошибку предварительного условия. Если обнаружение увенчалось успехом, но запросы не увенчались успехом, проверьте аутентификацию модели и совместимость с фреймворком / API отдельно.
