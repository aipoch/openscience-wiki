# Notebook и доказательства казни {/* #notebook-and-execution-evidence */}

Используйте Notebook для проверки исполняемого кода, запуска команды в текущем ядре и отслеживания фоновой работы. Для сохраненного файла откройте **Provenance**, чтобы проверить исполнение и доказательства, связанные с этой версией файла.

Перед запуском Python или R, [Включите совместимое время выполнения](runtimes.md). Для полного анализа данных используйте [рабочий процесс с публичными данными](../workflows/data-quality.md).

## Открыть сеанс Notebook {/* #open-a-session-notebook */}

1. Откройте проект и разговор, содержащий расчет, который вы хотите проверить. Если вы только начинаете, попросите агента выполнить небольшой расчет в **Сессия Notebook**.
2. Выберите **Open notebook** или используйте меню **View notebook**.
3. Выберите вкладку **Notebook**, когда активен предварительный просмотр файла.
4. Используйте **Agent** для выбора владельца исполнения, а **Python / R / Баш** для выбора языка.
5. Откройте пронумерованный прогон и прочитайте его выход и состояние завершения. копируемая активность с пометкой **code shown** содержит отображаемый код; Проверить оригинальную производственную сессию на предмет ее исполнения.

</PlatformContent>

| Контроль | Меры | Результат |
| --- | --- | --- |
| Агент | Выберите Main или детский агент | Отображает записи владельца; Агенты могут иметь отдельные ядра |
| Язык | Выберите доступный язык | Изменяет записи и консоль; Установка отсутствующих языков в Runtimes |
| Номерной пробег | Выберите записанное исполнение | Открывает свой код, выход и статус |
| Скопировать в буфер обмена | Копии выбранного кода | Сохраняет внешние пути и зависимости, как написано |
| Скрытый выход / Show output | Коллапс или расширение производства | Изменяет вид без повторного кодирования |
| Запуск кода в этом ядре... | Введите и отправьте код | Исполнители в выбранном живом ядре |
| Обсуждение Close/Collapse | Вернуться к разговору | Хранит записанную историю казни |

Проверяйте **Входные данные / Inputs** при наличии. Сопоставьте отображаемый файл и версию с вашим запросом. Если ссылка недоступна, повторно откройте или прикрепите предполагаемый ввод через приложение перед повторным использованием.

## Проверка кода перед запуском {/* #execution-review */}

Из v0.36.0 перед отправкой проверяется код Notebook, представленный агентом. Поддерживаемые обычные чтения и анализ продолжаются без дополнительного риска. Операции, которые могут привести к необратимым изменениям или которые не могут быть полностью проанализированы, требуют единовременного решения. Код, введённый непосредственно в ручную консоль, не покрывается этим этапом утверждения Агента; Проверяйте его самостоятельно перед отправкой.

1. При появлении **Review risky code** проверьте окружение и запрашиваемую операцию. Расчеты ждут вашего решения.
2. Выберите **Line** рядом с находкой, чтобы проверить его местоположение в полном коде. Проверяйте пути, файлы и команды, в том числе любые операции, которые анализ не мог решить.
3. Если действие является ненужным или его цель неправильная, отклоните его и попросите агента для более безопасного пересмотра. Утвердить один раз только тогда, когда вы намерены отображать операцию; Запрос не дает постоянного разрешения на будущий рискованный код.
4. После принятия решения проверьте зарегистрированное решение и статус запуска Notebook. Одобрение само по себе не является доказательством завершения. Отклоненный запрос не выполняет этот код.

<p className="example-label"><strong>Практический пример</strong> Проверить внешний запрос процесса Python</p>

Изображенный вычисление только добавляет числа, но он запускает другой интерпретатор через `subprocess.run`. Это вложенное исполнение не может быть полностью проверено, поэтому запрос приостанавливается для рассмотрения. Уведомление не означает, что код является вредоносным. Этот пример выбирает **Deny**. Пробег записывается как прерванный без выполнения детского процесса.

![Карта обзора Notebook с окружением, исходной линией, Разрешить один раз и Отказать](/img/open-science/v0360/notebook-risk-review.webp)

Этот экран проверяет риск исполнения; не подтверждает статистический метод или результат. **Auto-review** и [Рецензент](../specialists/reviewer.md) оценивают выполненные работы отдельно. v0.36.0 также улучшает захват зависимостей Python/R; использовать [Provenance и повторная проверка](reproducibility.md) для проверки фактических входов и выходов результата.

## Работа в живом ядре {/* #work-in-the-live-kernel */}

### Проверь себя в живом ядре {/* #run-a-check-yourself-in-the-live-kernel */}

Выберите **Python**, нажмите **Запуск кода в этом ядре...** и введите следующую автономную команду. Для этого не требуется набор данных, сторонний пакет или переменные из более раннего разговора:

```python
import sys
print("Python:", sys.version.split()[0])
print("Executable:", sys.executable)
```

Нажмите **Входить** для выполнения; Используйте **Сдвиг + вход** для новой линии. Откажитесь от открытого меню автозаполнения с **Побег** перед отправкой. Подтвердите номер **Python - ты** и информацию о переводчике на выходе. Исполняемый файл должен принадлежать выбранному вами времени выполнения.

Для R выберите **R** и отправьте:

```r
cat(R.version.string, "\n")
cat("R home:", R.home(), "\n")
```

Проверьте запись R и его выход. Python и R имеют отдельные переменные. `NameError` или `object not found` обычно означает, что названный объект не был создан в этом ядре. Проверьте свой код перед повторным использованием команды из другого сеанса.

Для проверки работы переводчика и сохранения результатов откройте [Python и R Runtimes](runtimes.md) и выберите **Windows** в верхней части страницы.

### Проверить живые переменные {/* #inspect-live-variables */}

1. Выберите **Inspect variables** после выполнения, которое создает переменные.
2. Читайте **Name**, **Type**, **Size / Shape** и **Preview**.
3. Введите имя из собственного кода в **Filter variables**. Для примера скриншота `sha` фильтрует перечисленные хеш-варианты; Выберите имя, которое существует в вашем ядре.
4. Используйте **Refresh variables** для чтения текущего пространства имен и **Show private variables**, если имя, которое вам нужно, скрыто.
5. Выберите **Close**, чтобы вернуться в Notebook.

<PlatformContent platform="macos">

![Фильтрация списка переменных по имени](/img/open-science/guides-walkthrough/47-notebook-variable-filter.webp)

</PlatformContent>

Предварительный просмотр может сократить значение; Распечатайте необходимое поле в консоли, чтобы полностью осмотреть его. **Variable tracking is limited** означает, что график зависимости неполный. Для отслеживаемого результата **несвежий** указывает на изменение зависимости; **unknown** означает, что отношения не могут быть установлены. Перезагрузка затронутого кода перед использованием устаревшего результата.

### Продолжить после изменения ядра {/* #continue-after-a-kernel-change */}

Изменение или восстановление времени выполнения может остановить его ядро. Сохраненные файлы и записи исполнения остаются отдельными от переменных в памяти. После изменения запустите проверку интерпретатора выше, воссоздайте требуемые переменные, повторив их код создания и снова откройте сохраненные файлы, которые вам нужны.

Используйте [Среды выполнения](runtimes.md#maintain-and-repair-environments) для отмены установки и переустановки. Восстановление рабочего времени, нормальный перезапуск ядра и восстановление фоновой работы - это разные операции; Проверяйте статус соответствующей операции, а не предполагайте, что они восстанавливают идентичное состояние.

## Справочные задачи и доставка результатов {/* #background-tasks-and-result-delivery */}

Запросите выполнение фона, когда поддерживаемые Python, R, постоянные задачи REPL или оболочки должны продолжаться, пока вы работаете в другом месте. Включите в запрос входные данные, выходные данные и состояние остановки.

1. После входа откройте запись разговора **Background tasks**. Он группирует локальные пробеги и удаленные вычислительные работы; Беседа без задач может не показать этого.
2. Прочитайте идентичность задачи, окружающую среду, статус и прошедшее время.
3. Выберите **Open**, чтобы проверить соответствующий запуск Notebook или вычислить работу.
4. Чтобы остановить задачу, выберите ее **Cancel**-контроль и дождитесь, пока статус будет урегулирован. Проверяйте файлы, которые уже были сохранены до их использования или удаления.
5. После завершения проверьте доставленное сообщение о результате и откройте сохраненные выходы.
6. После прерывания или перезагрузки приложения проверьте существующую задачу и любое сообщение о восстановлении, прежде чем отправлять другую копию.

<PlatformContent platform="macos">

![Справочное состояние задачи и ее открытый контроль](/img/open-science/v0.27.0/13-background-task-completed.webp)

</PlatformContent>

| Состояние | Что проверить |
| --- | --- |
| Бег / Running | Избранное окружение и прогресс; Работа с оболочкой может подождать слота для исполнения |
| Отмена / Cancelled | Является ли отмена все еще обрабатывается или решено |
| Завершено | Результат выхода и сохраненные выходные файлы |
| Неудачный / Timed Out / Interrupted | Первая ошибка, сохраненный выход и предложенные действия по восстановлению |
| Результат недоступен | Существующие записи о работе и детали восстановления |

Закрытие списка задач оставляет задачу запущенной. Завершение вычисления и доставка его итогового сообщения являются отдельными этапами. Дистанционные рабочие места также нуждаются в условиях хоста и планировщика в [Дистанционные вычисления](remote-compute.md).

| частичный | Некоторая информация об окружающей среде отсутствует или неподтверждена. Запись необходимых зависимостей перед повторным использованием. |

Редактирование отчета создает другую версию файла; Он не повторяет вычисления, которые произвели отдельный CSV. Смотрите [Файлы и версии](files.md).

Чтобы проверить обзор, выберите **Review** для требуемой версии, расширьте его проверки и используйте **Go to transcript** для проверки цитируемой деятельности. **No issues found** применяется к этим проверкам и этой версии; Он не заполняет отсутствующие доказательства казни или окружающей среды. Если обзор был прерван, откройте его запись **Review error** и выберите **Re-run review**. После завершения вернитесь на вкладку **Review** и подтвердите новый результат. Неудавшаяся попытка может остаться заметной в разговоре.

## Воспроизводимость {/* #reproducibility */}

Чтобы повторить полученный результат, сравнить результаты и сохранить запись проверки, следуйте [Руководство по воспроизводимости](reproducibility.md). Эта глава охватывает выполнение Notebook, проверку происхождения и экспорт кода.

## Экспорт и повторное использование кода {/* #export-and-reuse-code */}

Выберите экспорт, который соответствует вашей цели:

| Цель | Вступление | Содержание |
| --- | --- | --- |
| Прочитайте записанный код производителя | **Code → Captured producer block → Download** | Захваченный источник с его оригинальными путями и зависимостями |
| Храните записанные ячейки Notebook | **Execution Log → Download notebook** | Экспорт Notebook для выбранного результата/версии |
| Подготовьте портативный скрипт | **Code → Generate script** | Модельная реконструкция для проверки и испытания |

<PlatformContent platform="windows">

### Скачать захваченный код Python на Windows {/* #download-captured-python-code-on-windows */}

1. Откройте предполагаемую версию сохраненного отчета, а затем **Provenance → Code**.
2. Под **Captured producer block** выберите **Download**. Проверьте имя файла `.py` и пункт назначения в диалоге сохранения, затем выберите **Save**.
3. Откройте сохраненный файл и сравните его с отображаемым кодом. В PowerShell запустите его с тем же интерпретатором Python. используйте оператор вызова `&` перед указанным исполняемым путем.
4. Сравните результаты с Notebook и сохраненным отчетом. Храните все необходимые файлы ввода вместе с кодом.

<Screenshot src="/img/open-science/windows/captured-code-download.webp" alt="Windows захватил код производителя и его контроль загрузки" width={1920} height={1017} windowBounds={[1157, 0, 763, 416]} href="/docs/img/open-science/windows/captured-code-download.webp" linkLabel="Откройте полный скриншот Windows" />

Это загружает записанный код. **Generate script** — это отдельная операция по реконструкции. Если генерация терпит неудачу, сохраняйте ее полную ошибку. Загрузка захваченного кода не означает, что реконструкция прошла успешно.

</PlatformContent>

### Создайте автономный сценарий {/* #generate-a-standalone-script */}

1. Откройте предполагаемую версию **Provenance → Code**. Проверьте **Inputs** и **Execution Log**.
2. Выберите совместимую модель по умолчанию в **Settings → Model → Main model**. Эта вспомогательная функция использует ту политику, которая может отличаться от выбора модели разговора.
3. Выберите **Generate script** и дождитесь окончания **Generating…**.
4. Прочитайте этикетку **Реконструкция, сгенерированная LLM**. Проверяйте пути ввода, зависимости и места вывода перед выбором **Download script**.
5. В системе сохраняют диалог, выбирают отдельный каталог, проверяют имя файла `.py` и подтверждают **Save**. Откройте сохраненный файл, чтобы подтвердить, что он содержит отображаемый код.
6. Предоставьте входные данные, используя точные имена файлов, ожидаемые скриптом, подготовьте его зависимости, а затем запустите его за пределами приложения. Сравните выходные поля и контрольную сумму входа с сохраненным результатом. Завершенная загрузка сама по себе не проверяет расчет.

### Скачать код, когда генерация скриптов недоступна {/* #download-code-when-script-generation-is-unavailable */}

Если приложение возвращает **Реконструкция кода Artifact недоступна при аутентификации подписки Codex.**, используйте совместимого провайдера для этой вспомогательной операции или загрузите захваченный код производителя. Эта ошибка касается реконструкции сценария, а не обычного выполнения Codex Notebook.

Для **РЕЗУЛЬТАЦИЯ_БЕЗОПАСНОСТЬ** проверьте недостающие входы или доказательства выполнения. Загрузка захваченного кода сохраняет доступный код; Он не может восстановить шаги, которые никогда не были захвачены.

### Экспорт и повторное использование Notebook {/* #export-and-reuse-the-recorded-notebook */}

Выберите **Provenance → Execution Log → Download notebook**, выберите местоположение и сохраните. Откройте экспорт и проверьте его язык, ячейки и выходы.

Перед внешним повтором подготовьте входные файлы, записанные зависимости и каталог записываемого вывода. Замените пути, управляемые приложением, только в рабочей копии, сохраняя оригинальный экспорт нетронутым. Экспорт не объединяет учетные данные или полную среду применения. Примеры экспорта можно найти в [Примеры данных](../reference/example-data.md).

## Толкование ошибок и предупреждений {/* #interpret-errors-and-warnings */}

| симптом | Следующее действие |
| --- | --- |
| Недостающая переменная | Перезапуск кода, который определяет его на выбранном языке/ядре |
| Недостающий пакет | Проверьте пакеты Runtime и следуйте [Среды выполнения](runtimes.md) |
| Вводная версия недоступна | Откройте или прикрепите намеченный текущий ввод; Установить его личность с помощью приложения |
| Ошибка / доступ запрещен | Проверить запрашиваемый файл и объем разрешения; Сообщать о постоянных сбоях доступа с использованием [устранение неполадок](troubleshooting.md) |
| Ошибка сети/установщика | Следуйте за мной [Сеть](network.md) использование имени хоста и полной ошибки |
| Предупреждение с завершенным пробегом | Прочитайте, на что влияет предупреждение, а затем проверьте сохраненный результат, прежде чем решить, следует ли повторно использовать его. |

При сообщении о проблеме сохраняйте первую неисправную строку, выбранное время выполнения, идентификатор файла и состояние задачи. Связь сохранила выход к его фактическому производству.
