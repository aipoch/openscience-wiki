# Сессии и отделения {/* #sessions-and-branches */}

Проектные группы, связанные с источниками и работой. Сеанс — это один разговор внутри него. Используйте новую сессию для отдельного вопроса и ветку, когда новый вопрос должен сохранить выбранную историю разговора. Также не является заменой для проверки того, какие файлы и записи выполнения нового разговора могут фактически получить доступ.

## Создайте, назовите и вернитесь на сеанс {/* #create-name-and-return-to-a-session */}

Откройте проект, выберите **New** в разделе Сеансы, введите запрос и отправьте его. Сначала проверьте название проекта: новая сессия принадлежит этому проекту. Выберите строку сеанса, чтобы вернуться к ней; Прочитайте его статус, прежде чем принять решение о завершении задания.

<p className="example-label"><strong>Пример</strong> Назовите сеанс проверки качества RNA-seq</p>

Для завершения работы с GSE60450 мы использовали **Edit…** для сохранения этой информации:

| Полное поле | Примерное значение | сдержанность |
| --- | --- | --- |
| Название | `RNA-seq count matrix - validation and sample QC` | до символов 80; Редактор показывает счет |
| Описание | `Validate the public GSE60450 matrix and retain descriptive QC outputs with source integrity checks.` | До персонажей 1,000 |
| Сохранить | Сохраняйте изменения | Проверьте заголовок боковой панели после закрытия |
| Отменить/закрыть | Отпуск без применения проекта | Это не отменяет исследовательской работы |

![Заголовок сессии и редактор описания](/img/open-science/guides-walkthrough/40-session-edit.webp)

Выберите **Pin** из меню строки, чтобы сохранить сеанс в группе Pinned. **Unpin** возвращает его в обычный список. Пиннинг организует доступ; Он не сохраняет ядро живым или не защищает сеанс от удаления.

Наведите курсор на сеанс, чтобы проверить его номер, а также название и проект. Это число помогает различать разговоры с похожими именами. Подтвердите выбранную строку перед ее редактированием или удалением.

## Сохранить закладку для чтения {/* #save-a-reading-bookmark */}

Используйте [Частные закладки для чтения](bookmarks.md) для сохранения пассажа или области PDF с помощью примечания, а затем вернитесь к нему из **Bookmarks** в этой сессии. Сохранение закладки не отправляет проход агенту.

## Прочитайте меню сеанса правильно {/* #read-the-session-menu-correctly */}

![Действия, относящиеся к сессии RNA-seq](/img/open-science/guides-walkthrough/41-session-actions.webp)

| Меры | Результат | Проверить |
| --- | --- | --- |
| Изменить… | Изменить название/описание | Правильная строка и сохраненная этикетка |
| Скачать все артефакты | Откройте поток выбора / загрузки артефакта | Сохраненные файлы этой сессии и запрошенный выбор |
| Просмотр Notebook | Откройте представление о ходе работы сессии | Владелец, язык и фактические пробеги |
| Экспортировать диалог… | Экспорт беседы через предлагаемый формат/варианты | Экспорт транскрипта отличается от пакета artifact/Notebook |
| Архив | Скрыть сеанс от активной навигации | Восстанавливается в Settings → Архивировано |
| Удалить | Открыть подтверждение о постоянном удалении | Прочитайте, какие именно данные затронуты; Отмена сохраняет его |



## Отделение после завершенного результата {/* #branch-after-a-completed-result */}

<p className="example-label"><strong>Практический пример</strong> Отделение завершенной сессии КК для аннотации образца</p>

Предположим, вы хотите обсудить аннотацию образца вниз по течению, сохраняя при этом завершенный разговор QC с необработанным счетом.

1. Откройте готовый ответ в оригинальной сессии.
2. Выберите **Branch in new session** под этим ответом.
3. Подтвердите появление нового сеансового ряда. Первоначально он может делиться оригинальным названием.
4. Переименуйте его в `GSE60450 - follow-up interpretation` с **Edit…**.
5. Проверить унаследованную стенограмму перед подачей следующего запроса. Ссылка на оригинальные артефакты проекта явно там, где это необходимо.

![Самостоятельно названная ветвь рядом с прикрепленным оригиналом](/img/open-science/guides-walkthrough/57-session-branch.webp)

Ветвь сохраняет выбранную историю разговора, но не воссоздает оригинальное живое ядро. Для скопированного действия с пометкой **code shown** или заблокированной исторической ссылкой откройте оригинальный артефакт с панели Files проекта и проверьте его производственную сессию.

Доступность филиала зависит от состояния сообщения и фреймворка. [Side Chat](delegation.md#side-chat-availability) является отдельным. Новая сторона дискуссии наследует текущую модель и аргументацию этого разговора. Вы можете выбрать другую модель для следующей отправки.

## Пересмотреть предыдущее сообщение {/* #revise-an-earlier-message */}

**Edit message** по более раннему запросу пользователя создает исправление сообщения, а не стирает всю историю. Прочитайте пересмотренный текст и приложения перед отправкой. Используйте **Предыдущая/Следующая версия сообщения** там, где это возможно, чтобы проверить альтернативные варианты. Более поздний видимый контекст зависит от выбранного пути. Старый ответ не должен рассматриваться как ответ на недавно отредактированный запрос.

<p className="example-label"><strong>Практический пример</strong> Пересмотреть запрос на определение метрики QC</p>

Для этого примера QC выберите **Edit message** по завершенному вопросу, замените запрос с одним предложением четырьмя определениями и выберите **Send**. Ревизионные элементы управления недоступны, пока работает новый ответ. После завершения **Previous message revision** возвращается в `1/2` с исходным вопросом и ответом. **Next message revision** возвращается к пересмотренному ответу. Дальнейшая коррекция в точные названия полей CSV произвела `3/3`. В этом сеансе подписки Codex два отчета, сохраненные до того, как пересмотренное сообщение осталось доступным, и их загруженные байты были неизменными.

Тот же путь пересмотра был также реализован с OpenCode и местной моделью: пересмотренный запрос произвел новую фразу, Предыдущий восстановил первоначальный ответ, а Следующий восстановил пересмотренный ответ. Этот пример только для соединения не устанавливает обратного состояния инструмента или внешних побочных эффектов.

![Контроль за переключением пересмотра исторического сообщения](/img/open-science/local-todo-batch/18-message-revision.webp)

**Cancel** уходит без редактирования. **Send** запрашивает новый ответ Проверьте это, прежде чем продолжить. Используйте последующее наблюдение, чтобы исправить следующее действие или отделение для отдельно названного расследования.

## Исследовательские пакеты {/* #research-packages */}

Чтобы передать ветви разговора, файлы и доказательства вместе, используйте [Исследовательский пакет .science](research-packages.md). Руководство охватывает варианты экспорта, импорта и инспекции, только для чтения и восстановления передачи.

## Экспортные разговоры и исследовательские файлы {/* #export-conversations-and-research-files */}

Выберите **Export → Export conversation…** из меню строки сеанса, чтобы поделиться обсуждением исследования. Во-первых, используйте **Edit…**, чтобы дать сессии краткий заголовок: PDF экспорт использует этот заголовок, а длинный автоматический заголовок может потреблять большую часть первой страницы.

| Контроль | Действия и результаты |
| --- | --- |
| Формат: PDF / Markdown | PDF для чтения и печати; Markdown для дальнейшего редактирования |
| Весь диалог | Экспорт текущего разговорного отделения |
| Выбрано | Показать флажок поворота, изначально пустой; Счетчик следует за вашим выбором |
| Выбрать все | Выберите каждый перечисленный поворот |
| Экспорт PDF/Export Markdown | Откройте систему сохранения диалога; Недоступно, когда не выбраны повороты |
| Отмена | Закрыть, не создавая экспорт |

<p className="example-label"><strong>Практический пример</strong> Экспортировать можно только окончательные определения GSE60450 QC</p>

![Выбор окончательных определений QC для экспорта PDF](/img/open-science/local-todo-batch/20-selected-conversation-export.webp)

В **GSE60450 — Methods and claim audit**, выбрав конечный поворот, был получен одностраничный PDF, содержащий только этот запрос и его четыре метрических определения. Ранее обсуждение отсутствовало. Весь разговор PDF также был вновь открыт и проверен. Ранее выбранный экспорт Markdown начался с выбранных последующих шагов. Поворот может содержать несколько сообщений-помощников, поэтому при выборе одного поворота не нужно экспортировать ровно два сообщения.

Экспорт беседы не заменяет загрузку исследовательского файла. Ссылки на результаты могут относиться к внутренним записям приложений, которые получатель не может открыть. Загрузите CSV, цифры или отчеты отдельно, когда эти файлы являются частью передачи.

### Скачать артефакты сессии {/* #download-session-artifacts */}

Выберите **Download all artifacts**, выберите файлы, выберите **Скачать N Артефакты** и выберите папку назначения. Эта запись сохраняет отдельные файлы. Два загруженных метода и файлы Markdown для проверки претензий были вновь открыты и сопоставлены с сохраненными артефактами байт за байтом.

![Выбор двух сохраненных докладов в ходе сессии](/img/open-science/local-todo-batch/21-session-artifact-selection.webp)

### Скачать файл Project File Pack {/* #download-a-project-file-bundle */}

Откройте меню проекта в верхнем левом углу → **Download artifacts…**. Файлы сгруппированы под **Generated** и **Uploads**. Все они изначально отобраны. Используйте **Uncheck all**, выберите файлы для передачи и сохраните ZIP.

![Выбор отчетов, таблицы QC и исходных данных для подсчета из проекта](/img/open-science/local-todo-batch/22-project-artifact-selection.webp)

Выберите **Cancel** в диалоге сохранения системы, чтобы отказаться от этого сохранения. Выбор файла остается доступным. Как только начинается запись, приложение отключает отмену и закрытие. Ждать результата; Отмена диалога назначения отличается от остановки записи в процессе.

Если загружены только некоторые файлы, восстановите доступ к недоступным исходным файлам, затем выберите полную предполагаемую передачу и загрузите снова. Сохранение на том же ZIP-имя заменяет предыдущий архив. Выбор только неисправных файлов создает новый пакет, содержащий только эти файлы. Не добавляйте их к более раннему ZIP.

Откройте загруженный ZIP и сравните количество файлов, имена и содержимое в `generated/` и `uploads/` с вашим выбором перед обменом. Этот пакет не является резервной копией полного проекта, истории разговоров, ядра Notebook или времени выполнения.

## Архив и восстановление готовой ветки {/* #archive-and-restore-a-finished-branch */}

Выберите **Archive** в предполагаемой ветке, затем откройте **Settings → Archived → Sessions**. Проверяйте проект и время архивирования перед выбором **Restore**. Подтвердить, что ветка возвращается к активной навигации и ее сохраненное содержимое открыто; Оригинальный разговор раздельный.

Для архивного проекта используйте запись **Manage** и проверьте сеансы проекта. См. [Хранение и архивная работа](storage.md) для разницы между архивом, восстановлением, удалением и перемещением хранилища. Исчезновение сессии из активного списка не является доказательством того, что дисковое пространство было восстановлено.

Источники: [Сессионный редактор](https://github.com/aipoch/open-science/blob/v0.26.0/src/renderer/src/pages/workspace/EditSessionDialog.tsx), [Осуществление рабочей области](https://github.com/aipoch/open-science/tree/v0.26.0/src/renderer/src/pages/workspace).

## Вилка существующей сессии {/* #fork-session */}

Используйте **Fork**, когда вам нужна независимая рабочая копия локального или импортного сеанса. **Branch in new session** начинается с выбранного сообщения. Вилка копирует полную историю исследований сессии, включая ее филиалы, записи Notebook, версии файлов, литературу, аннотации и частные закладки. Сессия источника остается неизменной. Копирование записи не повторяет ее или не устанавливает, что ее среда готова на этом компьютере.

1. В настольном приложении завершите или остановите текущую задачу. Дождитесь, пока завершится передача пакета.
2. Откройте строку сеанса и выберите **Fork**. Приложение показывает прогресс передачи; **Run in background** скрывает это окно, не отменяя его.
3. Подождите **Fork completed** и откройте новую сессию. Откройте заголовок для проверки **Source session** и нового номера сессии.
4. Откройте унаследованный файл и проверьте его содержимое. Проверить выбранную модель и время выполнения перед продолжением; Старые пути или разрешения машин могут потребовать внимания.
5. Отправьте следующее задание в копию и проверьте его новый вывод. Сохраните оригинал в качестве справочной записи.

![Вилка в меню действий сессии](/img/open-science/v0311/fork-menu.webp)

![Новая информация о сеансе, показывающая его источник и унаследованный файл QC](/img/open-science/v0311/fork-info.webp)

Fork доступен в настольном приложении. Импортированные сеансы остаются только для чтения, пока вы не будете работать в их вилке. Настройки и память проекта не являются отдельным скопированным проектом. Старые записи обзора или проверки описывают их записанные версии; Проверьте любой устаревший статус, прежде чем рассматривать их как текущие проверки.

### Продолжить расчет QC в копии {/* #continue-a-qc-calculation-in-the-copy */}

<p className="example-label"><strong>Практический пример</strong> Вилка локальной сессии в v0.31.1</p>

В проекте GSE60450 разветвляют существующую сессию QC и открывают унаследованный `gse60450-qc-summary.csv`. Проверьте образцы **12** и общее количество сырых **269,027,617**. В копии попросите агента прочитать этот файл с Python, проверить оба значения, вычислить средние значения на образец и сохранить отдельный `fork-qc-check.csv`. Результатом является **22,418,968.083333…**. исходные и унаследованные файлы имеют одинаковое содержание; Новый расчет представляет собой отдельный файл. Это означает продолжение, а не нормализацию выражения.

## Прочитайте информационную карту сессии {/* #session-information */}

Выберите заголовок сессии, чтобы увидеть его номер, описание, источник, время создания / обновления, количество сообщений для текущей ветви и количество артефактов. Используйте **Pin**, чтобы сеанс был легко найти, или **Изменить сессию**, чтобы изменить его название и описание. Разделитель **Продолжение чата** связывается с зарегистрированным поворотом источника.


## Диагностика экспортных сессий {/* #session-diagnostics */}

Используйте управление **Export diagnostics…** заголовка сессии или **Export → Export diagnostics…** меню сессии для сбора выбранных диагностических источников в локальном архиве. Журналы приложений могут включать метаданные за пределами выбранного сеанса. Просмотрите список источников, сообщение о завершении и содержимое архива перед обменом; См. [Диагностические экспортные шаги](troubleshooting.md#session-diagnostics).
