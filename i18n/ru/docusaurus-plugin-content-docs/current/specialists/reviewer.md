# Рецензент и Auto-review {/* #reviewer-and-auto-review */}

Встроенный Рецензент проверяет готовый ответ на запрос и имеющиеся у него доказательства. Он отделен от пользовательского Specialist, чье имя содержит «Рецензент», и отдельно от разрешения.

Для сравнения результатов на основе исполнения используйте [Воспроизводимость](../guides/reproducibility.md). Оценка рецензента и воспроизводимый результат являются отдельными записями.

## Обзор сеанса против обзора артефакта {/* #session-review-versus-artifact-review */}

Обзор разговора и вкладка **Review** панели происхождения артефакта - это разные записи. Проверьте точную версию артефакта, которой вы собираетесь поделиться. Если на нем написано **No review for this version**, сохраните этот ярлык, даже если был рассмотрен другой ответ. Аналогичным образом, улавливание среды **partial** и доказательство **ограниченный** остаются частичными и ограниченными после того, как модель выражает уверенность.

Для ошибок ввода прикрепите доступный текущий вход или устраните его фактическую версию через приложение. Наличие локального файла не гарантирует, что ядро каждого ребенка/рецензента может его прочитать. [Notebook](../guides/notebook.md), [Делегирование](./delegate.md) и [устранение неполадок](../guides/troubleshooting.md).

Осмотрите выбранную версию артефакта при повторном открытии исторического обзора. После отмены обзора или исправления прочитайте окончательное состояние и сохраните результаты, прежде чем решить, следует ли повторно повторить. Отмена не создает успешного обзора.

## Выберите результат, который вы можете проверить {/* #choose-a-result-you-can-check */}

Для первого обзора заполните [встроенная проверка таблицы](delegate.md#verified-example-twelve-sample-invariants): предоставьте полную таблицу выборки-QC и попросите один арифметический результат на образец. Это обеспечивает точный критерий: двенадцать уникальных идентификаторов выборки, двенадцать строк и нулевой счет плюс обнаруженные гены, равные общей сумме генов для каждого ряда.

Перед просмотром откройте результат ребенка и его Notebook выведите самостоятельно. Затем попросите пересмотреть этот ответ. Сравните результаты проверки с этими критериями; Если строка или выполненный результат отсутствует, удалите этот вывод перед использованием результата. Результаты обзора зависят от ответа и имеющихся доказательств; Это упражнение не обещает значок нулевого поиска.

## Запросить пересмотр {/* #request-a-review */}

1. Завершите разговор с рабочей моделью.
2. Откройте композитора **+ menu → Request review**. Меню изменяется на **Reviewing…** во время просмотра.
3. Откройте полученную карту **Reviewer**. Прочитайте количество выводов и проверок, а затем расширьте объяснение каждой проверки.
4. Выберите **Go to transcript**, чтобы открыть **Session Reviewer**. Проверьте модель, временную метку, заявления PASS/FAIL, ссылки на доказательства и **Reviewer log**.
5. Если запрашиваются исправления, проверьте наблюдение агента Main и любые запросы на разрешение ребенка. Проверка не позволяет автоматически выполнять эти операции.
6. Используйте **Re-run review** после устранения выявленной проблемы. Сохраняйте неразрешенные результаты, если требуемый вход или операция все еще недоступны.

## Автоматический контроль обзора {/* #auto-review-controls */}

Откройте **Agent controls → Auto-review**, чтобы настроить обзор после будущих ответов. Предпочтение для разговора; Он отличается от **Ask for approval** и **Delegation**. Встроенная строка Рецензента в Настройках не имеет обычных элементов управления редактированием/удалением/включением и исключена из обычного набора Specialist.

| Состояние или контроль UI | Значение |
| --- | --- |
| Просмотр запроса недоступен | Проверить наличие активного ответа/обзора, отсутствующего приемлемого завершенного ответа или недоступной настройки модели. |
| Проверка... | Обзор все еще работает; Не относитесь к нему как к полному. |
| Рецензент · n выводов · n проверок | Открывает чеки и их доказательства. Результат нулевого поиска по-прежнему ограничен тем, что было проверено. |
| Запрошены исправления | Агент Main может выполнять цикл последующей коррекции. Проверка новых операций и их результатов. |
| Обнаруженные проблемы / предел исправления достигнут | Обзор не решил все вопросы. Прочитайте последнее объяснение, прежде чем начинать новую попытку. |
| Перейти к транскрипту | Откройте специальную страницу Session Reviewer. |
| Обсуждение Collapse Reviewer log | выявляет или скрывает свой журнал операций; Усеченный журнал не является полным доказательством. |
| Повторное выполнение проверки | запросить другой обзор; Это не кнопка «принять все выводы». |

### Запустите автообзор с отдельной моделью {/* #run-auto-review-with-a-separate-model */}

1. Под **Settings → Model → Reviewer** выберите доступную фиксированную модель. Используется `gpt-5.6-sol` для Main и `gpt-5.6-luna` для Reviewer.
2. Откройте **Agent controls → Auto-review** в целевом разговоре, подтвердите **On**, затем отправьте следующий запрос.
3. После ответа расширьте автоматически созданную карту **Reviewer**. Проверьте его модель, критерий, доказательства и результат.
4. При появлении **Corrections requested** проверьте коррекцию Main и последующий обзор, прежде чем решить, решен ли вывод.

От v0.30.2 Auto-review сохраняет настройки при начале разговора, а связанные повороты коррекции сохраняют обратную связь обзора, необходимую для цикла коррекции. Включите его перед отправкой, а затем проверьте фактическую карту Рецензента и пересмотренный выход Main. Сохранение контекста не означает, что находка была исправлена. Прочитайте последующий обзор и оставшиеся выводы.

### Что устанавливает «решенный» {/* #what-resolved-establishes */}

Проверка может быть решена, потому что была предпринята запрошенная попытка, и ее разрешение было точно сообщено. Это не означает, что файл был читаемым или его вычисления прошли. Прочитайте критерий, результат инструмента и оставшиеся результаты вместе. Если доступ остается заблокированным, следуйте за [File-handoff известная проблема](delegate.md), прежде чем начинать другой обзор.
