# Создайте Skill и поддерживающие его файлы {/* #create-a-skill-and-its-supporting-files */}

Превратите повторную проверку RNA-seq в многоразовый метод с использованием [публичный пример](../reference/example-data.md). Этот метод проверяет необработанные подсчеты; Не проводит дифференциально-экспрессионное тестирование.

В примерах используются два независимых названия пакетов:

| Путь создания | Скачать Skill ID | повторно использовать его с |
| --- | --- | --- |
| **Save as skill** из завершённого разговора | `rnaseq-descriptive-qc` | Выберите публикацию Personal Skill в новой беседе |
| Ручной пакет ниже | `rnaseq-count-qc` | Выберите созданный вручную Skill с этим точным идентификатором |

Следуйте по любому маршруту через публикацию, поиск и повторное использование. Используйте имя, которое вы сохранили. Эти два документа не являются псевдонимами. Если вы переименуете пакет, используйте его новую сохраненную личность в следующем запросе.

## Выберите маршрут создания {/* #choose-a-creation-route */}

| Начальная точка | Используйте эту запись | Что происходит |
| --- | --- | --- |
| Завершенный разговор содержит процедуру, которую стоит повторить. | Диалог **+ → Save as skill** | Агент перегоняет активную ветвь и использует Customize/Skill Creator для подготовки многоразового пакета. |
| Вы хотите описать новый метод в разговорной речи | Настройки **Add skill → Chat with agent**или **Customize** | Работайте с агентом, чтобы разработать метод и проверить его до публикации. |
| У вас уже есть инструкции и вспомогательные файлы. | Настройки **Add skill → Write from scratch** | Введите пакет напрямую с помощью редактора ниже. |
| У вас уже есть пакет или репозиторий | **Навыки загрузки / Импорт с GitHub / Импорт установленных навыков** | Проверка и импорт существующих ресурсов; смотреть [Управляйте Skills](./manage.md). |

## Сохраните как навык: превратите завершенный разговор в метод {/* #save-as-skill-turn-a-completed-conversation-into-a-method */}

Используйте это после того, как повторяемая процедура действительно сработала, например, проверяя исходную матрицу подсчета RNA-seq, сохраняя ее идентификаторы, вычисляя метрики выборки и вновь открывая выходы. **Save as skill** использует **Активный разговорный филиал**, включая его цель, инструменты, шаги и исправления пользователей. Он просит агента извлечь многоразовую процедуру, а не скопировать транскрипт. Если ветвь не имеет установленной процедуры, которую стоит повторно использовать, агент может объяснить это и остановиться, не создавая Skill.

1. Откройте соответствующий разговор и выберите ветку, содержащую процедуру, которую вы хотите сохранить.
2. Завершите текущую реакцию и любую субагентскую работу. Решите невыполненные утверждения, прерванные повороты или ошибки сеанса. Отделение должно закончиться полным ответом Агента.
3. Откройте **+ menu → Save as skill** композитора. Наведите курсор на предмет с ограниченными возможностями, чтобы прочитать его конкретную причину.
4. Изделие изменяется на **Saving as skill…**, пока агент работает. Это запускает модельную операцию в разговоре. Он не открывает ручной редактор Name/Description или мгновенно сохраняет ZIP.
5. Осмотрите имя Skill, инициируя описание, шаги, вспомогательные файлы и результат проверки. Отвечать на уточнения или разрешения на эксплуатацию, если они показаны. **Customize** остается включенным; Активная роль должна иметь соответствующий доступ к возможностям.
6. Просмотрите проект до принятия публикации. Удалить специфичные для исследования пути, временные идентификаторы, учетные данные и неподтвержденные выводы; Сохранение требований к многоразовым входам и проверкам. Существующий персональный Skill не должен быть перезаписан без явного решения о замене.
7. После публикации, откройте **Resource center → Skills**, просмотрите имя и проверьте **Files**, сохраненную доступность SKILL.md и Main Agent. Экспортируйте его, если вам нужно проверить полный пакет.
8. Запустите отдельный ограниченный запрос с сохраненным Skill. Успешно сохраненный пакет не является доказательством того, что второй набор данных или более поздний вызов прошли.

### Сохранить метод исследования {/* #save-the-research-method */}

<p className="example-label"><strong>Практический пример</strong> Сохранить метод RNA-seq как Skill</p>

После завершения GSE60450 QC в новой сессии выберите **+ → Save as skill** и запросите отдельный пакет **rnaseq-описательный-qc**, сохранив существующие пакеты. Нативный рабочий процесс создал черновик, содержащий один **SKILL.md**. Валидация не вернула ошибок или предупреждений.

Затем используйте **Resource center → Skills → Search skills**, откройте сохраненные инструкции и проверьте **Availability** и **Files**. Скачайте фактически опубликованный <ExampleDownload path="/examples/capabilities/rnaseq-descriptive-qc/SKILL.md">SKILL.md</ExampleDownload>.

### Почему кнопка не доступна {/* #why-the-button-is-unavailable */}

Набор инструментов идентифицирует первое условие блокировки. Устранение его может выявить второе условие. **Дождитесь окончания текущей агентской деятельности.** может появиться, когда сеанс не простаивает, включая состояние ошибки; Это не надежное обещание, что только ожидание решит проблему. Проверьте любой баннер ошибки и ожидание взаимодействия в разговоре. Для прерывания ответа, разрешения или возобновления этого ответа с помощью предложенного приложения действия, затем дождитесь завершения, прежде чем сохранить метод.

| Точный инструментарий | Что проверить |
| --- | --- |
| Откройте разговор, прежде чем сохранить его как Skill. | Откройте существующий разговор с процедурой, которая вам нужна. |
| Настройка Skill недоступна для активного Specialist. | Осмотрите активную роль и доступ к ее возможностям. Настройка остается глобально включенной; Этот инструментарий относится к текущему Specialist. |
| Подождите, пока история разговоров завершится загрузкой. | Пусть выбранная ветка завершает погрузку. |
| Близкий чат перед сохранением этого разговора как Skill. | Сохраните полезные советы в первую очередь. подтверждающий [Закрыть боковой чат](../guides/delegation.md) останавливает его и удаляет сохраненный разговор; Вернемся к Main. |
| Ожидайте завершения всех субагентов. | Проверяйте выдающиеся детские задания и их одобрение. |
| Спасай, как бегут навыки. | Прочитать существующий пробег создания; Не начинайте другой. |
| Решить текущую операцию по сессии сначала. | Завершите восстановление, ожидая повторения/перезагрузки контекста, цикла коррекции или уплотнения. |
| Дождитесь окончания текущей агентской деятельности. | Решите активную работу, ожидающее взаимодействие или бездейственную/ошибочную сессию; Проверьте фактический статус. |
| Сначала устраните ошибку синхронизации ветви разговора. | Устраните отображаемую ошибку синхронизации перед повторным использованием. |
| История разговорной ветви недоступна. | вновь открыть предполагаемый доступный филиал; Сохранить ошибку, если ее история не может загрузиться. |
| Дождитесь ответа от агента. | Отделение должно закончиться полным ответом; Пустой ветви или конечного сообщения пользователя недостаточно. |

Восстановление и ожидающие операции сеанса все еще могут блокировать действие. Используйте отображаемую причину вместо того, чтобы повторно запускать новый запрос на создание. Они отделены от аутентификации службы: если запуск создания начинается, но запрос модели не выполняется, следуйте возвращенной ошибке модели / службы в [устранение неполадок](../guides/troubleshooting.md).

## Пишите с нуля: создайте в редакторе {/* #write-from-scratch-create-in-the-editor */}

Используйте **Write from scratch**, когда у вас уже есть инструкции по методу и вспомогательные файлы. Нижеприведенные шаги используют `rnaseq-count-qc`.

Ссылка определяет выборочные метрики и их интерпретацию. хранить данные исследования в проекте; Используйте Skill для правил многоразового использования, а не встраивайте частный набор данных в портативный пакет.

### Заполните поля и опубликуйте {/* #complete-the-fields-and-publish */}

1. Открыть **Resource center → Skills → Add skill → Write from scratch**.
2. Загрузите SKILL.md в **Skill body**. Его фронтматер YAML заполняет **Name** и **Description**.
3. Подтвердите, что имя `rnaseq-count-qc`. Прочитайте отредактированный/тело контент перед сохранением; Одно только действительное название не подтверждает научный метод.
4. Откройте **Advanced settings → Add reference files** и выберите `sample-metric-schema.md`. Редактор размещает этот ресурс под `references/`.
5. Проверьте количество ссылок и размер пакета, затем выберите **Publish**.
6. Найдите новый Личный ряд и откройте его заново. Подтвердить инструкции, доступность и файлы; экспортировать пакет для проверки обоих входов.

![Тело RNA-seq Skill и поддерживающий файл](/img/open-science/capabilities-walkthrough/01-skill-create.webp)

| Поле или кнопка | Что вводить или проверять |
| --- | --- |
| Имя | Идентификатор узнаваемого метода. Бланковый вход показывает **Name is required.** |
| Описание | Скажите, когда следует выбрать метод, а не только к какому полю он относится. |
| Запись/загрузка | Введите текст напрямую или выберите файл в качестве источника тела. |
| Содержимое навыка | Полные рабочие инструкции: входы, проверки, выходы и условия остановки. |
| Расширенные настройки | Открывает элементы управления вспомогательными файлами и использование пакетов. |
| Добавить справочные файлы | Добавляет схемы многоразового использования, примеры или сценарии; Убедитесь, что пути, используемые в организме, соответствуют сохраненной упаковке. |
| Удаление справочного файла | Удалить этот проект ресурса; Проверяйте наличие неработающих ссылок в организме после этого. |
| Отмена / Возвращение к навыкам | оставляет редактора; Отменить, чтобы отбросить проект. |
| Издательство / Сохранение... | Создает персональный пакет; Дождитесь завершения и проверьте сохраненный ряд. |

Редактор позволяет использовать **Справочные файлы 16,383** в рамках пакетного бюджета **128 MB**. Импорт также должен пройти проверку архива; См. [Управляйте Skills](./manage.md).

## Напишите инструкции, которые можно проверить {/* #write-instructions-that-can-be-checked */}

Пример требует, чтобы агент сохранял полные идентификаторы гена/образца, отделял `EntrezGeneID` и `Length` от подсчетов, отклонял неправильно сформированные строки и недостающие значения и сравнивал хэши до/после. Он определяет четыре метрики выборки и отдельные выходные файлы. Эти требования делают неправильный или неполный результат видимым.

Включите четкое условие остановки: если источник не может быть прочитан или счет отсутствует, сообщите об этой проблеме ввода. Метод многоразового использования не должен молча изменять набор данных или заменять запрашиваемый анализ.

## Проверка и повторное использование Skill {/* #verify-and-reuse-the-skill */}

Для ручного маршрута `rnaseq-count-qc` используйте подсказку в [Skills](./overview.md). Откройте сгенерированный отчет и запись Notebook, а затем проверьте вход, размеры, метрические определения и выход по [Примеры данных](../reference/example-data.md).

Для последующего редактирования откройте **Actions → Edit** Личного пакета, измените метод, сохраните, а затем выдайте новый запрос. Сравните пересмотренный результат с предыдущим результатом. Отключение или редактирование пакета не перематывает инструкции, уже прочитанные в рабочем повороте.

Для составления проекта с помощью агента используйте **Add skill → Chat with agent** или запись **Customize**. Проверить предлагаемые инструкции и зачитать опубликованный пакет с теми же чеками; Ответ чата, описывающий Skill, не является сохраненным пакетом.

### Повторное использование Skill в новой сессии {/* #reuse-the-published-skill-in-a-new-session */}

1. Начните новую сессию и прикрепите исходную публичную матрицу GSE60450.
2. Запрос **rnaseq-описательный-qc** по имени. Попросите четыре метрики на выборку, неизмененный вход, CSV и краткий отчет.
3. Проверьте выполнение Notebook и откройте оба сгенерированных файла. Проверяйте сохраненные результаты по сравнению с исходным вводом, а не полагаясь только на сообщение о завершении.

Откройте новый CSV и сравните его по полному идентификатору с [Общий базовый уровень](../reference/example-data.md). Проверьте входной хэш. При применении Skill к другому исследованию, повторите эти проверки против собственного вклада и экспериментального дизайна этого исследования.
