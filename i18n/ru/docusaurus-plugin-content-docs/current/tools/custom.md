# Подключите пользовательский инструмент MCP {/* #connect-a-custom-mcp-tool */}

<p className="example-label"><strong>Практический пример</strong> Запрос общедоступной таблицы QC через локальный сервер MCP</p>

Этот пример показывает существующую общедоступную таблицу RNA-seq QC через небольшой локальный сервер MCP. Считывает фиксированный CSV и предлагает две операции. Он не запрашивает сеть, не устанавливает пакеты и не изменяет набор данных.

<PlatformGuide />

## Скачать реальный пример {/* #download-the-actual-example */}

- <ExampleDownload path="/examples/capabilities/qc-mcp-server.py">qc-mcp-server.py</ExampleDownload>
- <ExampleDownload path="/examples/gse60450/rnaseq-sample-qc.csv">rnaseq-sample-qc.csv</ExampleDownload>

Сохраните оба файла локально и отметьте их полные пути. Сервер использует стандартную библиотеку Python. Он считывает выбранный CSV при запуске, поэтому перезагрузите / подключите его намеренно, если вы замените этот ввод.

## Добавить в Open-Science {/* #add-it-in-open-science */}

1. Открыть **Settings → Connectors → Add connector → Local command**.
2. Установите **Display name** на `GSE60450 QC`.
3. Выберите **python3 — script file** как **Command** или **Other…** с фактическим исполняемым путем Python на Windows.
4. Открыть **Advanced settings**. Установите имя разъема/ID на `gse60450-qc` и опишите его как доступ только для чтения к сохраненной таблице QC.
5. В **Arguments** поставьте абсолютный путь сценария на первую строку, а абсолютный путь CSV — на вторую. Каждая строка — это один аргумент. Не добавляйте кавычки вокруг пути только потому, что он содержит пробелы.
6. Оставьте окружающую среду пустой для этого примера. Просмотрите скрипт сервера, проверьте **I trust this connector**, затем **Add**.
7. Найдите `GSE60450` и подтвердите наличие **Connected** и Main Agent.

<PlatformContent platform="windows">

На Windows используйте **Other…**, чтобы войти в полный путь к установленному `python.exe`; Предустановка `python3` не устанавливает, что команда существует. Подтвердите путь переводчика в [Среды выполнения](../guides/runtimes.md). Сохраняйте путь сценария и CSV на двух отдельных строках **Arguments**, даже если их имена папок содержат пробелы. Не объединяйте исполняемый и аргументы в одну команду оболочки.

</PlatformContent>

## Инструментальные входы и проверенные выходы {/* #tool-inputs-and-verified-outputs */}

| Инструмент | Ввод | Реальный ожидаемый контент |
| --- | --- | --- |
| get_dataset_summary | Пустой объект | GSE60450, URL-адрес источника, имя файла ввода, строки 12 и идентификаторы полного образца |
| get_sample_qc | `sample_id` струна | Четыре количественных метрики QC выбранной выборки |

Спросите у агента:

> Используйте подключенный gse60450-qc Connector. Звоните get_dataset_summary, затем get_sample_qc для MCL1-DG_BC2CTUACXX_ACTTGA_L002_R1. Сообщайте только реальные ответы и сохраняйте CSV.

В этом примере нативное приложение вернуло **Общие подсчеты 23,227,641, гены нулевого счета 8,664, гены, обнаруженные 18,515, и медиана 237** для этого образца. Звонок набора данных-резюме возвращал строки 12. Они соответствуют оригинальному сохраненному столу QC.

## Проверить поведение сервера и ошибки {/* #inspect-the-server-and-error-behavior */}

Сервер реализует инициализацию MCP, ping, обнаружение инструментов и вызовы через stdio. Его две схемы инструментов определены в загружаемом скрипте. Стандартным выходом является протокольный канал; Добавление обычных отладочных отпечатков может нарушить соединение. Локальная диагностика проводится по стандартной ошибке.

**Известная карта ошибок:** - недействительное имя выборки может отображаться как **connector_unavailable** в приложении, даже когда пользовательский сервер возвращает ошибку, специфичную для домена. Проверьте журнал сервера и валидируйте идентификатор образца перед повторным подключением. Сообщайте о постоянных несоответствиях с использованием [устранение неполадок](../guides/troubleshooting.md).

Приложение обнаруживает серверные инструменты во время подключения. Использовать обнаруженные имена операций при вызове через `host.mcp`; Протокол `tools/list` не является бизнес-инструментом Проверьте загружаемый скрипт для схемы ввода.

## Экспорт и переезд на другой компьютер {/* #export-and-move-to-another-computer */}

Выберите строку **Actions → Export**, выберите нужный формат и проверьте предварительный просмотр конфигурации. Реальный экспорт предупредил, что оба пути аргументации были локальными. **Save configuration** экспортирует настройки, а не интерпретатор Python, скрипт или CSV. Скопируйте эти файлы отдельно, обновите пути, подтвердите локальное доверие и повторите оба успешных вызова.

<PlatformContent platform="windows">

Для **MCP client config** проверьте `mcpServers`: этот пример экспортирует один сервер с `command` и два `args`. Дисплеи JSON избежали обратных слэшей в Windows дорожках. На другом компьютере обновите все три пути к реальным файлам и повторите оба вызова. Экспортируемая конфигурация не устанавливает, что компьютер назначения подключен.

</PlatformContent>

| неудача | Проверить |
| --- | --- |
| Командование не может начаться | Исполняемый путь, путь сценариев и разрешения файлов |
| CSV нельзя читать | Второй аргумент и фактическое местоположение файла |
| Подключенный, но инструмент недоступен | Задание агента, текущий каталог и точное название инструмента |
| Плохой вход | Обязательное `sample_id` оригинального полного идентификатора, а не компактной этикетки |
| Ошибка Connector после неудачного звонка | Проверять данные об ошибках сервера/приложения и повторно подключаться, когда это необходимо |
| Работает в терминале, но не в приложении | App-visible executable/environment and protocol-only stdout (недоступная ссылка) |

Чтобы расширить пример, определите небольшую схему ввода, идентификаторы возврата источника и проверьте нормальные, пустые и недействительные входы перед раскрытием инструмента. Держите эти операции достаточно узкими, чтобы пользователь мог проверить, что будет читать или изменять вызов.

Ссылка на осуществление: [ConnectorAddForm.tsx](https://github.com/aipoch/open-science/blob/v0.26.0/src/renderer/src/pages/settings/ConnectorAddForm.tsx), [Service.ts](https://github.com/aipoch/open-science/blob/v0.26.0/src/main/connectors/service.ts).

Для управления той же пользовательской конфигурацией MCP из скриптов используйте [Команды Connector CLI](../reference/cli.md#manage-connectors-and-credentials) или [Методы SDK](../reference/api.md#connector-management-methods). Успешный тест на подключение обнаруживает инструменты; Проверить отдельный ограниченный бизнес-звонок, прежде чем вызывать операционную интеграцию.
