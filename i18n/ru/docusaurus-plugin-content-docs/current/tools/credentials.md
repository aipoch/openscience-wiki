# Сертификаты службы {/* #service-credentials */}

Настройте учетные данные в **Settings → Credentials** для службы, фактически выполняющей запрос. Работающая подписка Codex обеспечивает доступ к модели; Он не предоставляет OpenAlex, GitHub или пользовательский аккаунт MCP.

## Встроенные служебные записи {/* #built-in-service-entries */}

| Услуги | Поля и цели | Как проверить |
| --- | --- | --- |
| GitHub | Личный токен доступа для обнаружения / импорта Skill | Используйте Connect/Manage и элементы управления токенами; Затем проверьте предполагаемую операцию репозитория. |
| Доступ к литературе | Контактная электронная почта и дополнительный ключ NCBI API | Сохранить контактную информацию; Ключ NCBI является необязательным для поддерживаемых запросов. |
| OpenAlex | Опциональный ключ API для операций OpenAlex в литературе | Проверяйте введенный ключ, сохраняйте его и делайте ограниченный запрос. |
| Unpaywall | Контактная электронная почта для полнотекстового поиска местоположения | Использует настроенную литературу контактной электронной почты; Не придуманный адрес. |

**Connect** открывает неконфигурированный сервис; **Manage** открывает уже существующий. **Desktop only** означает, что для работы с учетными данными необходим контекст рабочего стола. Индикатор сохраненного ключа сам по себе не является секретным значением.

## Настройка дополнительного ключа OpenAlex {/* #openalexs-actual-missing-key-flow */}

из v0.33.1Запросы OpenAlex больше не требуют API Ключ. Начните с небольшого запроса; По-прежнему применяются ограничения тарифов, политики аутентификации и доступа к услуге. Разрешение запроса без ключа не обещает неограниченного использования или успешного ответа.

Чтобы использовать свой собственный ключ, откройте **Settings → Credentials → OpenAlex** (также доступный из Графа литературы через **Manage credentials**), введите **API key**, выберите **Validate**, затем **Save** после успешной проверки. Ключ используется только для `api.openalex.org`. **Remove key** удаляет существующий ключ. Поле замены не раскрывает хранимую тайну.

Решите ошибки хранения учетных данных перед сохранением. Для ответов 429 проверьте квоту службы и руководство по повторному использованию, вместо того, чтобы предполагать, что ключ является обязательным.

## Полномочия для пользовательских коннекторов {/* #credentials-for-custom-connectors */}

Создайте учетные данные здесь, а затем выберите его имя в [Конфигурация коннектора](../guides/connectors.md). Проверяйте потребителей перед изменением или удалением общих учетных данных.

### Новые учётные данные {/* #new-credential */}

| Поле или кнопка | Операция |
| --- | --- |
| Имя | Дайте верительные грамоты узнаваемой местной этикетке. |
| Тип | Выбрать **API key**, **Access token**или **OAuth**. |
| Значение | Введите секрет в поле маски для ключа/токена. Пустые поля сохраняют инвалидность. |
| OAuth → URL ресурса | Предоставьте точную конечную точку ресурса. Соответствие Connector зависит от URL-адреса ресурса, транспорта и регистрации. |
| Продвинутый транспорт | Выберите транспорт, требуемый службой OAuth; Потоковый HTTP был проверяемым по умолчанию. |
| Области доступа | Введите области, разделенные пространствами или запятыми. |
| Используйте предварительно зарегистрированного клиента | Показать **Authorization server URL**, **Client ID**, **Callback URL**и **Client secret**. |
| Callback URL / Копия | Проверенный дефолт был `http://127.0.0.1/oauth/callback`; скопируйте его для регистрации службы или расширьте опцию пользовательского вызова. |
| открытие | Когда это применимо, найдите метаданные сервера; Это не является успешным само по себе. |
| Отменить / Сохранить | Отбросьте проект или сохраните действительную конфигурацию учетных данных. |

![Поля расширенной регистрации OAut](/img/open-science/walkthrough-2026-09-08/33-credential-oauth-advanced.webp)

В пользовательском Connector свяжите учетные данные с заголовком, переменной среды или селектором OAuth. Имя является ссылкой; Не размещайте секретные значения в описаниях или инструкциях проекта. Экспортируемые портативные конфигурации заменяют секреты на заполнители. Сохраненные учетные данные по-прежнему нуждаются в фактическом тесте службы / Connector, чтобы убедиться, что он работает.

## Проверка и устранение неполадок {/* #verify-and-troubleshoot */}

После экономии повторите одну небольшую операцию и проверьте ее реакцию. Использовать `credential_required` для отсутствующего сконфигурированного секрета, 401 для неисправности проверки подлинности и 403 для отказа в доступе/политике для расследования; a 403 не является универсально фиксированным путем замены ключа. 429 относится к ограничениям скорости/использования. Прочитайте фактическое тело службы и посмотрите [устранение неполадок](../guides/troubleshooting.md).

Удаление учетных данных может повлиять на каждый Connector, связанный с ним. Экспорт Connector и Specialist намеренно исключает готовые к использованию секреты/доверие; Настройте их снова на приемном устройстве. Никогда не вставляйте секрет в Skill, подсказку, скриншот или отчет о проблеме.

Ключ OpenAlex является необязательным. OAuth Connectors по-прежнему требует завершения регистрации названной службы. Устраните отображаемую ошибку аутентификации перед повторным повторением того же небольшого запроса.

Ссылка на осуществление: [Разработчик:Panel.tsx](https://github.com/aipoch/open-science/blob/v0.26.0/src/renderer/src/pages/settings/CredentialsPanel.tsx), [ConnectorAddForm.tsx](https://github.com/aipoch/open-science/blob/v0.26.0/src/renderer/src/pages/settings/ConnectorAddForm.tsx).

[Управление учетными данными CLI/SDK](../reference/cli.md#manage-connectors-and-credentials) может создавать / обновлять общие учетные данные через аутентифицированный локальный доступ. Установки без головы Linux могут явно выбирать [незашифрованное хранилище файлов](../reference/server.md#credential-storage-on-headless-linux); Десктопные учетные данные сохраняют свое нормальное поведение при хранении ОС. Эта опция не решает проблему хранения паролей или не инициирует первый вход в систему OAuth.

## Откройте официальную ключевую страницу API {/* #official-api-key-page */}

Учетные данные OpenAlex и NCBI ссылаются на их официальные ключевые страницы. Заполните шаги учетной записи с помощью сервиса, вернитесь к форме, затем проверьте и сохраните предполагаемый ключ. Открытие ссылки не сохраняет ключ или не выполняет запрос; Требуется ли ключ, зависит от сервиса и работы.
