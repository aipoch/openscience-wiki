# 변경 로그 · v1.3.4 {/* #changelog--v134 */}

**2026-11-23 UTC의 경우** 출시 [공식 출시 노트](https://github.com/aipoch/open-science/releases/tag/v1.3.4).

## tracing를 가진 붙박이 대리인을 검열하십시오 {/* #tracing */}

프로젝트에 **Agent tracing**이 추가되었으며, 기본적으로 꺼져 있습니다. 켜면 대화 턴, 모델 요청, MCP 도구 호출을 연결한 기록을 운영자가 설정한 OTLP/HTTP 수신 대상으로 보냅니다. 일반 Collector와 Langfuse를 지원합니다. Open-Science는 자체 수집 서비스를 제공하지 않습니다. 콘텐츠 수집 설정 네 항목은 생략하면 켜지므로, 활성화 전에 확인하세요.[프로젝트 사용 방법](../guides/projects.md#agent-tracing) · [수신 대상 및 수집 설정](../reference/diagnostics.md#agent-tracing).

1개의 뛰기를 위해, CLI `--otel-traces` 또는 SDK `otelTraces: true`는 프로젝트 스위치가 떨어져 있을 때도 tracing 가능하게 합니다. 저장된 프로젝트 또는 세션 설정을 변경하지 않습니다. [CLI](../reference/cli.md#otel-traces) · [SDK](../reference/api.md#otel-traces).

## Windows 업데이트 및 Notebook 응답 {/* #updates */}

Windows 업데이트 준비는 앱의 내장 에이전트 및 이미지 돕기, 외부 차단제로 치료하여 발생되는 고정 축을 인식합니다. 안정적인 Windows 업데이트 regain 컴팩트 설치 deltas; v1.3.3는 가득 차있는 설치자를 사용했습니다. [업데이트 및 복구 단계](../guides/installation.md#windows-134).

긴 Notebook 역사 사용 몇몇 반복된 읽기 및 배치는 튼튼한 검문소로 전환합니다. 첫 번째 Windows Python 플로우는 더 이상 관련 커널 회수 울타리에 넣지 않습니다. Compute 메모리 사용은 macOS에 캐시를 제외합니다; Windows은 신체적 사용과 함께 한계에 대한 최적의 메모리를 보여줍니다. [메모리 요약](../guides/notebook.md#memory-summary).

## 모델과 더 명확한 작업 결과 {/* #models-recovery */}

- CodeBuddy은 모델당 지원되는 이유를 발견하고, 재시작 세션에서 선택한 모델과 토큰 사용 업데이트를 복원하고, 첫 번째 영화 사용 요청을 수정합니다. Zhipu는 GLM-5.4을 추가합니다. [공급자 선택](../guides/providers.md#codebuddy-reasoning).
- denied 도구 작업은 유지 된 설명 끝; denied 호출은 완료된 작업에서 구별됩니다. [인증 및 인증](../guides/approval-modes.md#denied-action).
- 충분한 균형과 같은 Explicit 공급자 HTTP 402 응답은 그들의 상태 및 유용한 청구 세부사항을 유지합니다. [의욕구](../guides/troubleshooting.md#provider-balance).
- 영화는 Active에서 대화를 계속합니다. 막힌 영화 대화 상자는 일을 소유하는 대화를 열 수 있습니다. [필름 진행](../guides/research-films.md#film-recovery).
- 출판 중에 편집 된 이미지 버전이 열리고, 이미지 초안이 활성화된 동안 Provenance 역사가 접근할 수 있습니다. [Image 편집](../guides/image-generation.md#edit).
- 내장 에이전트 사이드 채팅은 자신의 프로필의 체크 포인트를 사용합니다; null identity 필드를 가진 공구 continuations는 더 이상 차례로 실패하지 않습니다.

[설치 및 업데이트](../guides/installation.md) 및 [v1.3.3](v1.3.3.md)을 참조하십시오.
