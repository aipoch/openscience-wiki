# 작업 위임과 Side Chat {/* #delegation-and-side-chat */}

현재 작업을 진행하면서 별도의 질문을 논의하려면 Side Chat을 사용하세요. 다른 에이전트에게 독립적인 작업을 맡기려면 작업 위임을 사용하세요. 전체 대화를 다른 방향으로 이어 가려면 [세션 분기](sessions.md)를 사용하세요.

## Side Chat {/* #side-chat-availability */}

### 사용 상황 {/* #when-to-use-it */}

분석 결과에 나온 용어를 확인하거나 두 가지 접근법을 비교하고, 보고서의 표현을 논의할 때 Side Chat을 사용하세요. 논의를 마친 후 필요한 조언을 주 대화인 Main으로 전달하세요.

### 사용 방법 {/* #how-to-use-it */}

1. 기존 세션에서, 보낸 버튼 옆에 **More send options → Side chat**을 엽니다. 빈 Composer로 열 수 있습니다. 새로운 Side Chat 초안이 즉시 나타납니다. 질문은, 모형을 검사하고 노력하는 것을, 그 후에 그것을 보내십시오.
2. 독립된 **Side chat** 미리보기 탭에서 답변을 읽으세요. 추가 질문은 **Side chat follow up**으로 보낼 수 있습니다. 같은 세션에 여러 보조 대화를 유지하고, Main에서 작업을 계속하면서 각 탭을 전환할 수 있습니다.
3. Main에 조언을 전달하려면 Side Chat에 전달을 명시적으로 요청하세요. 예를 들어 “이 조언을 Main에 전달해 줘: 보고서에서 결측값 처리 방법을 별도 항목으로 설명해 줘.”라고 요청합니다. Main에서 **Side chat**으로 표시된 메시지가 도착했는지 확인하세요. Main이 대기 중이면 다음 요청을 보내 작업을 이어 가세요.
4. 현재 답변을 중지하려면 **Cancel Side chat response**를 사용하세요. Main으로 돌아가려면 탭을 전환하거나 미리보기 영역을 접으세요. 앱을 다시 시작한 뒤에도 필요한 내용은 다시 시작하기 전에 Main으로 전달하거나 보고서에 저장하세요.

텍스트 또는 주석을 포함하는 초안은 전환보기를 살아. 비접촉되지 않은 빈 초안은 당신이 그것을 떠나 때 버려집니다; 혼자 초안을 열어 모델 요청을 보내지 않습니다.

### 주석을 올바른 초안으로 이동하기 {/* #move-an-annotation-to-the-right-draft */}

선택한 문단이나 영역의 주석에서 **Move to Side chat…**을 선택한 다음, 기존 보조 대화나 새 대화를 선택하세요. Main과 Side Chat 초안 사이에서 주석을 끌어다 놓을 수도 있습니다. 전송 전에 대상과 옮겨진 내용을 확인하세요. 주석을 옮기는 것은 초안만 준비하며 요청을 전송하지는 않습니다.

개인용 **For me** 북마크는 별도의 읽기 도구입니다. [독서 bookmarks](bookmarks.md)를 참고하세요.

### 주의 사항 {/* #things-to-know */}

- **모델 설정:** 새로운 Side Chat는 현재 주요 대화의 모델과 소싱 노력에 상속합니다. Side Chat에서 변경할 수 있습니다. 선택은 다음의 전송에 적용됩니다. Codex 구독이 지원됩니다. 전송하기 전에 selector를 확인합니다.
- **전달 및 작업:** 일반 답변은 Main으로 자동 전송되지 않습니다. Side Chat에서 Main의 작업 권한을 승인할 수도 없습니다. 내용이 전달되었는지 확인한 후 Main에 작업을 요청하세요.
- **탭 닫기:** 확인 전에 **Close Side chat?** 안내를 읽으세요. 닫으면 해당 Side Chat이 중지되고 대화가 삭제됩니다. 유지하려면 **Cancel**을 선택하세요. Main으로 돌아가기만 하려면 탭을 전환하거나 미리보기 영역을 접으세요. 정리에 실패하면 오류와 함께 탭이 다시 나타납니다.
- **앱 다시 시작:** Side Chat 대화와 Main에 아직 전달되지 않은 조언은 현재 앱 실행 중에만 유지됩니다. 화면을 새로 고치거나 프로젝트를 전환하면 메모리에 남아 있는 상태에 다시 연결할 수 있습니다. 앱을 완전히 다시 시작하면 이 상태가 지워집니다. 종료 전에 필요한 내용을 Main에 전달하거나 보고서로 저장하세요. Main에 이미 저장된 메시지는 유지됩니다.
- **가용성:** v0.30.2에서, Main 실행 또는 승인에 대 한 대기 자체 블록 Side Chat에 의해 하지 않습니다. Main의 최소 한 메시지 보내기. 읽기 전용 수입 세션 및 사용 가능한 부모 세션은 Side Chat을 열 수 없습니다. Side Chat은 파일 첨부 파일을받지 않습니다. 실제 버튼 설명을 따르십시오; 연결 문제는 [문제 해결](troubleshooting.md)에서 덮습니다.

## 작업 위임 {/* #task-delegation */}

### 사용 상황 {/* #when-to-use-it-1 */}

문헌 출처 확인, 데이터 파일 검사, 분석 결과 검토처럼 독립적으로 처리할 수 있는 작업을 위임하고, 주 에이전트가 결과를 종합하도록 할 수 있습니다. 역할이 정해진 보조 에이전트를 재사용하려면 [Specialist 위임](../specialists/delegate.md)을 참고하세요.

### 사용 방법 {/* #how-to-use-it-1 */}

1. Composer의 **Agent controls**에서 **Delegation**을 확인하세요.
2. **Settings → Model → Subagent**에서 주 모델의 설정을 상속하거나, 호환되는 별도 모델과 추론 수준을 설정하세요.
3. 요청에 위임할 작업, 입력 파일, 예상 결과와 완료 판단 기준을 구체적으로 적으세요.
4. 활동 기록에서 하위 작업의 상태를 확인하고 권한 요청이 나타나면 응답하세요.
5. 반환된 파일이나 출처 링크를 열어 결과를 확인하세요. 실행 기록을 보려면 Notebook의 **Agent** 필터에서 해당 작업을 수행한 에이전트를 선택하세요.

### 주의 사항 {/* #things-to-know-1 */}

- 사용 가능한 기능은 에이전트 프레임워크와 설정에 따라 다릅니다. Delegation을 켠 후 활동 기록에서 하위 작업이 실제로 시작되었는지 확인하세요.
- 하위 에이전트가 Main의 모든 대화 맥락이나 Python 변수를 공유하는 것은 아닙니다. 작업에 필요한 파일과 지침을 제공하세요.
- Main의 계획을 승인해도 하위 에이전트의 모든 작업이 자동으로 승인되지는 않습니다. 권한 요청이 나타나면 구체적인 작업과 허용 범위를 확인하세요.
- **Release**을 사용할 수 있다면 이를 통해 하위 작업을 종료하거나 리소스를 해제하세요. Main의 실행 증거는 유지됩니다.
