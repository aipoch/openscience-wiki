# 원격 브라우저 액세스 {/* #remote-browser-access */}

원격 브라우저 액세스는 다른 장치가이 컴퓨터의 실행 작업 공간을 작동하도록합니다. 프로젝트, 에이전트, 파일 및 노트북 런타임은이 컴퓨터에서 계속 실행합니다. 그것은 분리됩니다 [먼 compute](./remote-compute.md)실행 대상에 작업을 보내는 .

## 전화 또는 태블릿 쌍 {/* #mobile-pairing */}

더 보기 **Connect mobile device** 바탕 화면 **Settings → Remote** 제품정보 **WiFi** · **Internet**· 이것은 리모트에서 분리됩니다. 그것은 아래에 묘사된 형태; QR 노선은 리모트를 요구하지 않습니다. 계정.

쌍 패널 잎 먼 접근을 여십시오 **Off** 명시적으로 선택할 때까지 **WiFi** 또는 **Internet**· 이미 활성 연결은 현재 상태를 유지합니다. 다른 장치를 연결하려는 경우에만 모드를 선택하고 호스트 awake 및 실행을 유지합니다.

1. 제품 정보 **WiFi** 같은 로컬 네트워크에 대한 장치. 몇몇 호스트 주소가 나타나면 전화에서 주소가 일치할 수 있습니다. 격리된 손님 네트워크는 둘 다 장치가 동일한 와이파이 이름을 보여줄 때 접근을 막을 수 있습니다.
2. 로컬 네트워크 밖에 접근하기 위해, 선택 **Internet**· Pinggy 연결 통지를 읽고 작업 링크 및 QR 코드가 나타납니다 때까지 기다립니다. 트래픽은 타사 터널을 사용합니다. 표시된 암호 및 연결 요구 사항을 검토하십시오.
3. 현재 QR 코드를 휴대 전화 또는 태블릿으로 스캔합니다. 인터넷 모드의 경우, 입력 **Connection password** 견적 요청 페어링 프롬프트를 따르고 의도된 작업 공간이 열립니다.
4. 코드가 만료되거나 터널 재연결되면 사용 **Refresh QR code** 새로운 코드를 스캔합니다. 무료 Pinggy 터널은 60 분마다 주소를 변경합니다. 오래된 저장 링크가 작동 중지 될 수 있습니다.
5. 기타 **Connected devices**· 제품 정보 **Revoke all** 완료 될 때 그 장치 승인 제거, 선택 **Off** 원격 액세스를 중지하는 원격 설정에서. 연결이 분리되는 작업을 재발행하고 중지합니다.

링크, QR 코드 및 암호를 개인 설정 유지. QR 코드만 사용할 수 있습니다. 다른 장치가 연결되었는지 설정하지 않습니다. 연결이 실패하면 호스트의 실행 상태를 확인하고 다른 제안을 생성하기 전에 선택한 네트워크 주소 및 방화벽 권한을 확인합니다.

## Prerequisites 및 모드 {/* #prerequisites-and-modes */}

홈 컴퓨터에 **Settings → Remote**을 엽니 다. 모드를 사용하기 전에 별도의 Remote.It 데스크톱 응용 프로그램에 설치 및 서명하십시오. Open-Science은 설치 CLI을 호출; Remote.It 계정 또는 서비스 번들을 만들지 않습니다.

| 모드 | 그것은 무엇을 위해 |
| --- | --- |
| 끄기 | 공급자 설치 및 재사용을 위한 신뢰할 수 있는browser 레코드를 유지하면서 일시적인 원격 액세스를 일시 중지합니다. |
| 앱 액세스 | 모바일 앱을 통해 연결하고 2단계 검증을 완료합니다. |
| 브라우저 액세스 | 지속 가능한 HTTPS 브라우저 링크를 사용하여 두 단계 검증을 완료하십시오. |

![먼 접근은 Off 국가에서 검열했습니다](/img/open-science/walkthrough-2026-09-08/63-remote-off.webp)

![Remote.It 앱 링크와 Off, App access, Browser access 모드를 보여 주는 Open-Science Remote control](/img/open-science/settings-remote-control.webp)

액세스 모드 설정은 홈 컴퓨터에서 데스크톱 창에서 변경할 수 있습니다. 연결된 브라우저는 인증될 때 페어링/신뢰를 관리할 수 있지만 데스크탑 전용 모드 컨트롤의 대용품이 아닙니다.

## 환경을 사용할 때 브라우저를 페어링 {/* #pair-a-browser-when-the-environment-is-available */}

1. 예정된 액세스 모드를 선택하고 준비 / 실행 상태를 기다립니다. 오류 또는 액세스 모드 상태 변경은 사용 가능한 연결이 아닙니다.
2. 브라우저 액세스에서 **Copy**, **Open** 또는 표시된 링크의 QR 코드를 사용하십시오. 앱 액세스에서 모바일 연결 지침과 같은 Remote.It 계정을 사용하십시오.
3. 요청 장치에 **Pairing requests**을 사용하여 6자리 코드를 승인된 승인 장치에서 비교합니다. 브라우저, 플랫폼, 시간 및 주소 확인.
4. **Reject**, **Allow for up to 12 hours** 또는 **Trust this browser for 180 days**를 선택하십시오. 임시 접근은 영원한 신뢰가 아닙니다.
5. 의도 된 작업 공간이 열리고 작은 읽기 전용 상호 작용이 성공한다는 것을 검증하십시오. 링크 복사에서 연결하지 마십시오.

액세스 링크 개인을 유지. 의도한 장치에서만 연결을 공유하고 신뢰하기 전에 페어링 요청을 확인합니다.

## 레포크 및 중지 {/* #revoke-and-stop */}

**Trusted browsers** 목록 장치 세부사항과 마지막 사용. **Revoke &#91;브라우저&#93;**은 이후 보호된 액세스/reconnection에 대한 브라우저의 권한이 부여됩니다. 터닝 **Off** 일시 중지 액세스하지만 신뢰 기록을 유지; 분실된 기기를 별도로 수정합니다.

앱이 끝나지 않은 경우 **Retry turning off**을 사용하여 저장된 상태를 확인합니다. 경고 명시적으로 액세스가 저장되지 않은 경우 재시작 후 반환 될 수 있습니다. 선택된 라디오 버튼을 혼자 성공으로 취급하지 마십시오.

### 서비스 변경 가능, 에이전트는 여전히 재시작 {/* #service-changes-accepted-agent-still-restarting */}

메시지가 **Remote.It은 서비스 변경을 허용하지만 배경 에이전트는 여전히 재시작**라고하면 새로운 서비스 ID가 저장되었습니다. 몇 초를 기다립니다. **...** 또는 **Detect again**을 선택하십시오. 다시 장치를 추가하지 않거나 반복된 모드를 전환하지 마십시오; 허용된 서비스 구성을 재사용합니다.

페이지가 브라우저 링크 및 페어링 컨트롤을 제공 한 후만 계속하십시오. 감지가 실패하면 Remote.It 데스크탑 앱이 서명하고 에이전트가 실행되고 정확한 메시지를 유지하고 [문제 해결](troubleshooting.md)을 사용하여보고합니다. 페이지 수준 오류가 없는 **Ready** 서브패널은 종료된 접근을 설정하기에 충분하지 않습니다.

## 단계별 진단 {/* #diagnose-by-stage */}

| 기본 정보 | 【특전】 |
| --- | --- |
| 공급자는 검출하지 않습니다 | Remote.It 설치, 로그인 및 페이지의 탐지 결과. |
| 모드 변경 실패 | 현재 오류 및 로컬 app/provider가 실행중인지 여부. |
| 링크는 열려 있지만 workspace는 하지 않습니다 | 페어링 코드, 만료, 신뢰 및 공인 장치. |
| 이전 작업 브라우저가 거부됩니다. | Revocation/expiry 및 액세스가 꺼져 있는지 여부. |
| Workspace가 열려 있지만 작업이 실패합니다. | 홈 컴퓨터에서 모델, 실행 시간 및 도구 권한; 원격 액세스는이를 구성하지 않습니다. |

로컬 헤더/브라우저 명령의 경우 [서비스 참고](../reference/server.md)을 참조하십시오. Remote.It 모드에서 별도의 엔트리 경로입니다.

근원: [먼 접근 위원회](https://github.com/aipoch/open-science/blob/v0.26.0/src/renderer/src/pages/settings/RemoteControlPanel.tsx).

Linux 헤드리스 배포는 쓸모없는 OS 키링없이, [credential 저장 선택권](../reference/server.md#credential-storage-on-headless-linux)을 읽습니다. 해당 비밀의 로컬 저장소를 변경; 그것은 Remote.It, 브라우저를 쌍하거나 원격 액세스를 부여하지 않습니다.

## v0.31.1에서 페어링 및 재발행 {/* #pairing-v0311 */}

종료 페어링 요청은 **Trusted browsers** 이전에 나타나며 나머지 시간과 긴급한 배지를 나타냅니다. 액세스 권한을 부여하기 전에 요청 장치에 표시된 코드를 일치; 만료된 요청은 다시 시작해야 합니다. 신뢰할 수있는 브라우저는 스스로를 구할 수 있습니다 : 나중에 액세스가 필요한 경우 종료 및 쌍에 대한 보호 된 액세스를 기대합니다. **Off**, 임시 접근 및 재조합 신뢰는 다른 행동을 남아 있습니다.
