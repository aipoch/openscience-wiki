# 更新日志 · v1.3.4

发布于 **2026-11-23 UTC**。[官方发布说明](https://github.com/aipoch/open-science/releases/tag/v1.3.4)。

## 用追踪记录查看内置 Agent 的执行过程 {/* #tracing */}

项目新增 **Agent tracing**，默认关闭。开启后，可将轮次、模型请求和 MCP 工具调用的关联记录发往主机运行者配置的 OTLP/HTTP 接收端，支持通用 Collector 和 Langfuse。Open-Science 不提供代收服务。开启前应检查四项内容采集设置，它们未填写时默认开启。[项目操作](../guides/projects.md#agent-tracing) · [接收端与采集配置](../reference/diagnostics.md#agent-tracing)。

单次 Run 可通过 CLI `--otel-traces` 或 SDK `otelTraces: true` 明确启用追踪，即使项目开关关闭也会生效，不会修改已保存的项目或会话设置。[CLI](../reference/cli.md#otel-traces) · [SDK](../reference/api.md#otel-traces)。

## Windows 更新与 Notebook 响应改进 {/* #updates */}

Windows 准备更新时能识别应用自己的内置 Agent 与图片辅助进程，修复误判为外部占用导致的停滞。稳定版 Windows 更新恢复小体积差分安装包，v1.3.3 使用的是完整安装包。[更新与恢复操作](../guides/installation.md#windows-134)。

较长的 Notebook 历史减少重复读取，并将符合条件的 Run 状态变更批量写入持久检查点。Windows 首次 Python 绘图不再因无关的内核恢复状态卡住。Compute 在 macOS 上的内存用量排除缓存；Windows 在物理用量旁显示提交内存与其上限。[内存汇总说明](../guides/notebook.md#memory-summary)。

## 模型与任务结果说明改进 {/* #models-recovery */}

- CodeBuddy 按模型发现支持的推理强度，恢复历史会话时保留模型选择与 Token 用量更新，并修复影片创作的首次模型请求。智谱新增 GLM-5.4。[提供方选项](../guides/providers.md#codebuddy-reasoning)。
- 拒绝工具操作后，轮次会保留解释；被拒绝的调用与已完成工作分别计数。[权限与审批](../guides/approval-modes.md#denied-action)。
- 提供方明确返回 HTTP 402，例如 Insufficient Balance 时，保留状态码并展示有用的计费详情。[恢复操作](../guides/troubleshooting.md#provider-balance)。
- 影片生成期间，所属会话保留在 Active；被其他生成任务阻塞的影片对话框可以打开该任务所属会话。[影片进度](../guides/research-films.md#film-recovery)。
- 图片编辑版本在发布期间可打开预览，存在图片草稿时也能浏览 Provenance 历史。[图片编辑](../guides/image-generation.md#edit)。
- 内置 Agent 的 Side Chat 使用自身配置的检查点；工具续接中的空身份字段不再导致轮次失败。

另见[安装与更新](../guides/installation.md)和 [v1.3.3](v1.3.3.md)。
