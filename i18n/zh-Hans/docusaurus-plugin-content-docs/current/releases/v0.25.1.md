# Open Science v0.25.1

本文档基于稳定版 [v0.25.1](https://github.com/aipoch/open-science/releases/tag/v0.25.1) 验证，源码提交为 `b3d37e29cc14433c18f9cd3807dc00a556d23a34`。本次从 Wiki 原有的 v0.14.0 基线补档到当前版本；v0.25.1 本身是维护版本，下文同时覆盖期间新增的用户工作流。

## v0.25.1 的变化

- Windows 受保护 Notebook kernel 改用直接 sandbox 启动路径；网络保护仍需完成应用提示的一次性管理员设置。
- 文件与包导出改为原子发布。导出失败不应留下半成品；请改用可写且空间充足的目标后重试。
- 生成图片的预览已恢复。若仍显示占位符，先等待 artifact 发布，重新打开预览，必要时使用 Download。
- Skills 会检测并修复 catalog 不一致。恢复中断的专家包时，应先阅读来源提示再替换。
- 会话并发、artifact finalization、PDF 阅读身份、Claude 用量恢复与中断清理更可靠；这些修复保留记录，但不会自动证明研究结论正确。

## 会话、输入与导航

运行中的 turn 可以继续输入并加入会话队列。队列项可编辑、删除、排序或 `Send now`；后者通过当前框架的 follow-up 通道发送，不会取消正在运行的 turn。队列草稿在重启后可能丢失，重要指令应在发出前另行保存。

在已完成的智能体回复上选择 `Branch in new session`，可从该节点新建会话；系统复制截至该回复的对话与活动记录，但不会自动发送 prompt。配置分隔线会标记 framework、model 或 reasoning effort 的变化。

![长对话中的运行标记](/img/open-science/v0.25.1/workspace-run-marks.png)

桌面端的 run-marks rail 每个标记对应一条可见用户 prompt；悬停或聚焦可预览，选择后跳转。Undo 可恢复界面明确支持的归档或草稿操作，`Cmd/Ctrl+Shift+Z` 重做最近一次 Composer 草稿变化。

- 输入 `#` 选择另一会话，可在当前 turn 中附加其可见 transcript 的只读上下文；它不会跨项目授权。
- 超过 10,000 字符或 300 行的纯文本粘贴会变成托管附件；`Show in text field` 可还原原文与光标位置。
- 可选择 transcript、activity 或 preview 中的文字，或图片上的点，并作为 annotation 发给智能体；annotation 会保留来源。
- 首条消息可生成会话标题与描述；手动编辑会覆盖仍在进行的生成。

## 文件、论文与可编辑 artifact

PDF preview 最多可把三份 PDF 链接为当前会话的阅读上下文。智能体可读取当前页、翻页或搜索；文本与矩形选择会形成 evidence annotation，之后可返回原位置。只应链接允许发送给当前模型的论文；不用时及时 unlink。

Markdown、纯文本、脚本和已识别的源代码 artifact 或 upload 支持编辑：

1. 打开文件 preview，在 File actions 中选择 `Edit`。
2. 编辑 raw source 并保存。
3. 等待新托管版本发布，再用 `Compare` 与前一版本对照。
4. 使用 Previous/Next version 导航，并在引用前检查 Provenance。

每次保存都会创建新版本，不会改写旧证据。二进制文档、图片、Notebook 等不支持的格式仍为只读。出现 revision conflict 时应 reload 并比较，而不是盲目覆盖。

![按版本记录的 artifact provenance](/img/open-science/v0.25.1/artifact-provenance.png)

智能体回复中的 HTTPS 来源可在 sandboxed side preview 打开。外部打开前检查显示的 URL；隔离预览并不代表未知站点可信。

## Notebook 与计算控制

- `Variables` 只读展示正在运行的 Python/R namespace，包括名称、类型、shape 与受限预览；查看不会为了浏览而启动 kernel。终端会提示实时变量名，private 名称默认隐藏。
- 跨运行依赖分析把旧输出标为 `stale`、`clear` 或 `unknown`；`unknown` 应按需要重新运行处理。
- Settings → Network 管理 Notebook 与 compute runtime 的 domain allowlist。被阻止的目标可选择 `Deny`、`Allow once` 或 `Always allow`；一次性授权只适用于该命令。边界不覆盖应用外的系统进程。
- 每个会话分别保存 enabled compute hosts 与 selected execution targets；通过 Composer 计算控件选择已配置 host。密码由操作系统凭据服务保存，条件允许时优先使用 SSH key 或 ssh-agent。
- Settings → Runtimes 可在排空 kernel 后重装 app-managed Python/R runtime，不会修改外部 interpreter。禁止智能体创建环境并不影响用户显式 setup 或 reinstall。

## 能力与账户设置

- Settings 现有 17 个面板，包括 Memory、Tags、Credentials 与 Usage。Memory 为 opt-in 且按项目隔离；不要把 secret 写入 memory。
- Tags 可跨 Skills、Connectors 与 Specialists 分类；Favorites 受保护并固定在首位。
- Credentials 统一保存设备级 key、access token 与 OAuth sign-in。Connector 可将命名凭据绑定到环境变量或 header，portable export 只保留 `${NAME}` 占位符。
- Connector import/export 支持标准 `mcpServers` JSON。预注册 OAuth client 可填写 client ID 与只写 client secret；更改 issuer 或 client ID 会使绑定失效。
- Specialist Marketplace 验证签名包；Marketplace 内容只读，更新必须提升 SemVer。安装前检查来源、Skills 与 Connectors。
- 模型设置包含 main、subagent、reviewer、vision 与 session-details 策略。CodeBuddy 与 Claude Code、OpenCode、Codex 并列；实际可用 provider 以安装版本中的 picker 为准。
- Usage 在 provider 上报足够数据时区分 turns 与 model calls，并计入 delegation、side chat、compaction、session details 等辅助调用；缺失数据会显示覆盖不足。

## 验证限制

v0.25.1 源码已完成依赖安装、typecheck、Electron 与 Web production build。真实 Electron 测试通过桌面与移动项目切换。视觉检查使用隔离的 E2E 数据与确定性测试智能体，不含个人凭据或研究数据。完整视觉套件假设操作系统为英文；测试机为简体中文，因此 fixture 固定英文之前打开的英文标签用例不能作为证据。Windows-only sandbox、SSH 密码主机、付费 provider、OAuth 账户与在线 Marketplace 仅依据实现与测试验证，未使用外部凭据或硬件实测。
