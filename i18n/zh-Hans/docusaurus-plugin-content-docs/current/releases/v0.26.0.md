# Open Science v0.26.0

本 Wiki 已依据稳定版 [v0.26.0](https://github.com/aipoch/open-science/releases/tag/v0.26.0) 验证，源码 commit 为 `5df494a57ac67727c4153c707708a7b1727e968c`。本次从此前已记录的 v0.25.1 补档到该版本。

## 主要工作流

### 文献资料库

新的本地资料库可导入单个 PDF 以及 BibTeX、RIS、NBIB 记录；可用集合和项目整理文献、检查重复项、附加选定的开放获取 PDF，并生成带修订来源的引用。智能体发现的文献会先进入 Inbox，不会静默加入资料库。详见[文献资料库](/docs/zh-Hans/workspace/literature-library)。

![文献资料库](/img/open-science/v0.26.0/literature-library.png)

### 远程计算的 Slurm 执行模式

每个 SSH 主机新增 **Execution mode**：**Direct SSH** 或 **Slurm**。Slurm 模式会提交由调度器管理的 job、轮询持久状态、在中断后恢复、通过调度器取消并清理 staging 文件。内置 **Compute Environment Setup** skill 会为所选主机生成安装、修复与移除说明；应自行复核，或交给集群管理员审核。

![远程主机执行模式](/img/open-science/v0.26.0/compute-slurm-mode.png)

不要因为主机上存在 `sbatch` 就直接选择 Slurm。先确认登录节点规则、partition/account/QoS 默认值、scratch 路径、module/环境准备、wall time 限制和取消规则。Open Science 不负责配置集群或授予调度权限。

### 更易读的工具与授权卡片

Artifact 写入和常用 Notebook 控制会显示紧凑摘要卡片，而不是直接展示 raw JSON。路径、版本、参数或执行状态很重要时仍应展开详情。Skill-load approval 可在决定前展开完整 `SKILL.md`。

![授权卡片中展开的 Skill 文档](/img/open-science/v0.26.0/skill-approval-expanded.png)

### Provider 与模型目录

Apodex 成为内置 provider，包含 `apodex-1.1` 和 `apodex-1.1-mini`。内置目录还加入支持相应 reasoning 控件的 GPT-6 Astra 与 Claude Fable 5.1。目录存在不代表已有凭据、访问资格或容量；应以已安装版本的 picker 和成功的 connection test 为准。

## 其他用户可见变化

- **Permissions**：常规只读 Notebook/runtime 检查、Memory 查询、包清单和已批准计划的进度更新拥有更安全的默认 grant；仍可在 Settings 查看并撤销。
- **Preview 菜单**：在预览内容中右键，可复制路径、下载或把本地文件保存为 artifact；托管 artifact 可提供 provenance 和返回来源上下文。
- **Task API**：CLI、HTTP 和 SDK 客户端无需发送 prompt，就能读取或更新会话的模型、reasoning effort、Memory 设置和计算主机选择。
- **大型 Skill**：包含数万文件的包采用受限的高速导入路径，并保留完整性检查。
- **可靠性**：streaming、长会话资源占用、计划恢复、更新处理、Notebook runtime、artifact 发布、持久化、provider 状态、credential、remote access、存储迁移与无障碍均有恢复和正确性修复。

## Task SDK 破坏性变更

公开 Task SDK 合约已移除旧版 session-plan continuation 字段。客户端必须通过当前受支持的 session/plan API 读取状态。升级前应测试仍反序列化旧字段的集成；普通桌面对话不受影响。

## 验证限制

在一次性 checkout 中，v0.26.0 精确 tag 已完成依赖安装、typecheck、Electron 与 Web production build。真实 Electron fixture 测试覆盖 Slurm execution-mode 持久化和展开 Skill approval；资料库截图来自一次性 catalog。元数据导入、重复项、引用格式和全文工作流另依据实现与自动化测试核验。未使用真实集群、付费 provider、OAuth 账户、外部模型调用、出版商账户或个人研究库，因此 Slurm 调度和公共全文 provider 响应属于代码与测试验证，并非外部实测。
