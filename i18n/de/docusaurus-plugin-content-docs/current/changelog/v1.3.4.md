# Changelog · v1.3.4 {/* #changelog--v134 */}

**2026-11-23 UTC** freigegeben. [Offizielle Veröffentlichungen](https://github.com/aipoch/open-science/releases/tag/v1.3.4).

## Inspizieren Sie den eingebauten Agent mit Tracing {/* #tracing */}

Projekte bieten nun **Agent tracing**, das standardmäßig ausgeschaltet ist. Es sendet zusammenhängende Aufzeichnungen von Dialogschritten, Modellanfragen und MCP-Werkzeugaufrufen an einen vom Betreiber eingerichteten OTLP/HTTP-Empfänger, etwa einen generischen Collector oder Langfuse. Open-Science stellt keinen eigenen Sammeldienst bereit. Die vier Einstellungen zur Inhaltserfassung sind bei fehlender Angabe jeweils aktiviert. Prüfen Sie sie vor dem Einschalten des Tracings. [Projektschritte](../guides/projects.md#agent-tracing) · [Empfänger und Erfassung](../reference/diagnostics.md#agent-tracing).

Für einen Run ermöglicht CLI `--otel-traces` oder SDK `otelTraces: true` explizit das Nachverfolgen, auch wenn der Projektschalter ausgeschaltet ist. Es ändert sich nicht die gespeicherte Projekt- oder Sitzungseinstellung. [CLI](../reference/cli.md#otel-traces) · [SDK](../reference/api.md#otel-traces).

## Windows Updates und Notebook Reaktionsfähigkeit {/* #updates */}

Windows Update-Vorbereitung erkennt den eingebauten Agent und Image-Helfer der App und repariert Stände, die durch die Behandlung als externe Blocker verursacht werden. Stabile Windows-Updates erhalten kompakte Installer-Deltas zurück v1.3.3 verwendete den vollständigen Installer. [Aktualisierungs- und Wiederherstellungsschritte](../guides/installation.md#windows-134).

Lange Notebook-Historien verwenden weniger wiederholte Lesevorgänge und batchfähige Run-Übergänge in dauerhafte Checkpoints. Das erste Windows Python-Plot steht nicht mehr auf einem nicht verwandten Kernel-Wiederherstellungszaun. Die Nutzung von Rechenspeichern schließt Caches auf macOS aus; Windows zeigt engagiertes Gedächtnis gegen seine Grenze neben der physischen Nutzung. [Speicherzusammenfassung](../guides/notebook.md#memory-summary).

## Modelle und klarere Aufgabenergebnisse {/* #models-recovery */}

- CodeBuddy entdeckt unterstützte Argumentationsbemühungen pro Modell, stellt die ausgewählten Modell- und Token-Nutzungsupdates in fortgesetzten Sitzungen wieder her und behebt die erste Film-Authoring-Anfrage. Zhipu fügt GLM-5.4 hinzu. [Anbieterwahl](../guides/providers.md#codebuddy-reasoning).
- Eine verweigerte Tool-Aktion endet mit einer beibehaltenen Erklärung; abgelehnte Anrufe bleiben von abgeschlossener Arbeit getrennt. [Genehmigungen](../guides/approval-modes.md#denied-action).
- Explizite Anbieter HTTP 402 Antworten wie Insufficient Balance behalten ihren Status und nützliche Abrechnungsdetails. [Wiedereinziehung](../guides/troubleshooting.md#provider-balance).
- Ein Generierungsfilm hält seine Unterhaltung in Aktiv. Ein blockierter Filmdialog kann das Gespräch öffnen, dem der Job gehört. [Filmfortschritt](../guides/research-films.md#film-recovery).
- Bearbeitete Bildversionen werden während der Veröffentlichung geöffnet, und die Provenance-Historie bleibt zugänglich, während die Bildentwürfe aktiv sind. [Bildbearbeitung](../guides/image-generation.md#edit).
- Eingebaute agentenseitenchats verwenden die checkpoints ihres eigenen profils. Werkzeugfortsetzungen mit null Identitätsfeldern scheitern nicht mehr an der Reihe.

Siehe [Installation und Updates](../guides/installation.md) und [v1.3.3](v1.3.3.md).
