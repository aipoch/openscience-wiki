# ヘッドレスサービスおよびブラウザアクセス {/* #headless-service-and-browser-access */}

ローカルサービスはヘッドレスバックエンドとローカルホストブラウザインターフェイスを提供します。 SSH ComputeホストとRemote.Itブラウザのペアリングとは違います。 クライアントを接続する前に、ホストの認証および認証ストレージ設定を選択します。

## ターゲット選定と発見 {/* #target-selection-and-discovery */}

v0.37.0から、共有サービスは通常のNodeプロセスで実行され、デスクトップはネイティブクライアントとして接続します。 CLI スタートアップは、隠れたエレクトロンホストを必要としません。

| セレクター | 対象範囲 |
| --- | --- |
| `--port PORT` | ローカルホストポート、整数 1-65535; 占有する明示的なポートはエラーを引き起こします |
| `--config-root PATH` / `--profile PATH` | ポータブルCLI設定ディレクトリ; 同じ絶対パスを全体的に保持する |
| `OPEN_SCIENCE_CONFIG_ROOT` | 環境による明示的な構成ディレクトリ; コマンドオプションは優先されます |
| 自動検出 | ローカルサービスの状態を見つけ、そのプロファイル、ポート、バージョンを確認します |

デスクトップのバックエンドは、指定されていない場合、フリーポートを選択します。 CLI 起動デフォルトは 44100 です。 `status --json`は、開いているウィンドウからポートを差し込むのではなく、使用してください。 同じ構成のための互換性のある既存のサービスを再利用できます。 アクティブな作業を終了し、バージョンが一致しないときに更新指示に従ってください。 レガシー`--app-path`オプションは、新しいNodeバックエンドに電子実行を有効にしません。

ステートファイルは `web-service.json` です。 認証の失敗は、そのレコードを削除したり、PIDを殺したりすることはできません。 実際のサービスと診断を検査して、他のプロセスに影響を与えないようにします。

## 初期化と確認の信頼性 {/* #readiness */}

`open-science init` を使用して、アプリを起動せずにデフォルト設定ディレクトリを用意します。 分離された構成のために、同じ絶対 `--profile` パスを init に渡して下さい、開始およびその後のコマンド。 Debianパッケージは、アプリケーションと一緒にCLIをインストールします。 Codexの準備とログインについては、[ターミナル セットアップ](cli.md#terminal-setup)を参照してください。

`start --no-open`を意図した後、`open-science doctor --json`を実行します。 `ready`全体を見極め、個別にチェックして次のアクションを提案した。 プロセスの終了コードは、単純さの予測ではありません。 既存の認証されたローカルインターフェースでサービスを維持します。 このヘッドレスサービスは、Remote.Itを構成したり、パブリックエンドポイントを公開したりしません。

## ライフサイクルコマンド {/* #lifecycle-commands */}

v1.0.5 では App の接続または明示的な CLI 起動がサービスを維持します。すべてのコマンドで同じ絶対プロファイルパスを使います。

| コマンド | 結果 |
| --- | --- |
| `open-science start` | サービスを起動または再利用し、継続実行を設定してブラウザーを開く |
| `open-science start --no-open --json` | ブラウザーを開かず同じ設定を行う。`started` または `already-running`、サービス情報、`lifetime` を返す |
| `open-science status --json` | 対象を確認。サービスがなければ `{"running":false}` と終了コード 1 |
| `open-science url` | 認証情報付きの URL を表示する。公開しない |
| `open-science stop --json` | 明示的な継続設定を解除。App が接続していない場合のみ停止 |
| `open-science stop --force --json` | App 接続中でも全体停止を要求。進行中の作業を中断する可能性がある |

`start` の繰り返しで設定回数は増えません。**start**、**status**、**stop** は `--json` に対応し、**url** は非対応です。JSON 起動結果には認証 URL を含みません。旧サービスではライフサイクルが不明と表示される場合があるため、新しい規則を利用する前に版を揃えます。

### 停止結果

| JSON `result` | 意味 |
| --- | --- |
| `already-stopped` | 実行中のサービス記録がない |
| `keep-alive-revoked` | 明示的な継続設定は解除したが、App の接続により実行中 |
| `stopped` | 要求対象のサービスが終了し、所有権を解放した |
| `shutdown-requested` | 旧サービスが要求を受理したが、終了未確認。終了コードは非ゼロ |

`result` と `lifetime` を読みます。成功終了コードだけで停止済みとは判断できません。旧名 `daemon-stopped` と `web-service-stopped` は出力されません。`--force` は新プロトコルが必要で、旧サービスでは明示的に失敗します。状態ファイルの削除や記録された PID の強制終了ではなく、エラーと現状を確認してください。

## 認証とブラウザアクセス {/* #authentication-and-browser-access */}

SDKはローカルサービスを発見し、ローカル認証トークンを読み取り、リクエストヘッダで送信します。 通常のヒューマン/JSON/JSONL タスク出力は、そのトークンを印刷しません。 `url`は、認証されたブラウザエントリを生成する意図的な例外です。

ローカルホストサービスは、別のコンピュータから自動的にアクセスできません。 リモートブラウザアクセスは、独自の構成されたアクセスモード、ペアリングおよび信頼できるブラウザのライフサイクルを使用します。 SSH Compute は、ジョブを構成したリモート実行ホストに送信します。

Remote.ItのペアリングとSSHジョブの[遠隔計算](../guides/remote-compute.md)に[リモートブラウザーアクセス](../guides/remote-access.md)を使用します。 ローカルサービスのドキュメンテーション URL を変更することで、各フローが構成されます。

### ヘッドレス Linux のクレデンシャルストレージ {/* #credential-storage-on-headless-linux */}

デフォルトはOS保護された貯蔵です。 Linuxヘッドレスバックエンドで、使用可能なキーリングなしで、明示的な代替手段を選択します。

<p className="example-label"><strong>例</strong> Linuxヘッドレスサービスをファイル認証ストレージで起動</p>

~~~bash
open-science start --credential-store=file --no-open
~~~

| おすすめ商品 | ビーキャビター |
| --- | --- |
| 省略されたオプション / --credential-store=os | OS保護された店を要求して下さい |
| --credential-store=ファイル | 暗号化されていない設定管理の秘密をLinuxヘッドレスでのみ許可する |
| デスクトップ、macOS または Windows 起動 | ファイルモードはサポートされていません |
| すでに実行されているバックエンド | 明示的なモード選択は拒否されます。 そのプロセスのモードを変更しない |
| スタートアップ | モードを再度指定して下さい; 保存された好みではありません |

ファイルモードは、設定ルートでsettings.jsonとCertificate.jsonを使用して、アトミック書き込みとPOSIXモード0600を使用します。 file:v1: 値が base64 でエンコードされている **暗号化されていない** です。 読むことができる人は、秘密を回復することができます。 これらのファイルはリポジトリ、画像、サポートレポートから除外します。

選択は、新しい/更新された設定管理プロバイダのキー、アプリ管理サブスクリプショントークン、GitHub/literatureキーおよび共有MCP/OAuthの秘密に適用されます。 パスワード/保護された計算データは別のOS貯蔵の条件を維持します; 外部のエージェント・フレームワークのログインストアは、独自のルールに従います。 このオプションでサンドボックスが無効になっています。

暗号化された値が自動的に移行されず、元のOSボルトを必要としません。 利用できない場合は、通常のサポートフォームからクレデンシャルを再入力してください。 ファイルの refs は、古いリリースと互換性のない explicit ファイルモードが必要です。 OS ストレージにクレデンシャルを返すには、OS モードで再起動し、vault が利用可能なときに明示的に置換します。

構成が容器の取り替えを生き残らなければならないとき永続的な貯蔵を使用して下さい。 Shutdownは構成を保持します; 使い捨てコンテナのファイルシステムを置き換えると、削除できます。 [クレデンシャルストレージ契約](https://github.com/aipoch/open-science/blob/v0.27.0/packages/open-science/CLI.md) を参照してください。

## バックエンドを維持・停止する条件 {/* #backend-ownership */}

| 操作 | バックエンドへの影響 |
| --- | --- |
| 明示的な CLI 起動なしで最後の App を終了 | サービス停止 |
| CLI `start` 後に全 App を終了 | 明示的な継続設定により実行を継続 |
| ブラウザータブや SDK クライアントを閉じる | 明示的な継続設定は解除されない |
| 通常の CLI、Web、SDK タスクを実行 | 全 App 終了後の継続を単独では保証しない |
| App 接続中に `open-science stop` | 明示的な設定を解除。App のためにサービスは継続 |
| `open-science stop --force` | 全体停止を要求。作業が中断する可能性がある |

デスクトップ終了後もブラウザーや自動処理を続ける場合は、同じプロファイルを明示的に起動します。トレイへ閉じる操作は終了ではありません。全体停止前に作業を終え、その後 `status --json` で確認します。

切断したデスクトップには **Reconnect** と **Quit app** があります。再接続は作業を再送信しません。[接続復旧](../guides/troubleshooting.md#connection-recovery)に従い、応答を失った操作は再試行前に結果を確認します。

### デスクトップ終了中断後の再接続 {/* #desktop-service-recovery */}

同じ版のデスクトップを開き直して元のプロファイルへ接続します。App 接続と CLI の継続設定がサービスの存続を決めます。ブラウザータブだけでは代わりになりません。

終了準備が失敗するとウィンドウが残ります。未保存の作業を保存し、復旧後に元のタスクを確認します。古いサービスが起動を妨げる場合は、プロファイル、版、接続中のクライアントを確認してから停止を選びます。キャンセルならサービスは継続します。ロックファイルを削除せず、停止結果を再確認してください。

## アプリケーション更新の動作 {/* #application-update-behavior */}

CLI 更新機能は削除済みです。`open-science update --json` は使わず、[デスクトップの更新機能または元の配布元](../guides/installation.md#manual-update)を使います。

独立 CLI のファイルを交換する前に、そのインストールを使う全プロファイルの作業を終えます。接続中の App を終了し、各プロファイルの `stop --json` で継続設定を解除します。`stopped` または `already-stopped` を確認してください。`keep-alive-revoked` は App によりサービスが残っている状態です。全クライアントの作業を止める場合だけ `stop --force` を使います。実行中のプログラムファイルを上書きしないでください。

デスクトップ更新で CLI サービスを止めて管理を切り替える確認が出る場合は、対象とタスクを確認します。キャンセルすれば元のサービスは継続します。この操作は独立 CLI のプログラムファイルを更新しません。占有・復旧の案内に従い、ロックや設定を削除しないでください。

更新後、版と元のデータ、`status --json`、`doctor --json` を確認します。認証情報の保存モードは維持します。[1.x 互換性](../guides/installation.md#version-compatibility)は異なるデスクトップ／バックエンド版の混在を保証しません。[公式ランタイムガイド](https://github.com/aipoch/open-science/blob/v1.0.5/docs/standalone-runtime.md)、[CLI](cli.md)、[Task SDK](api.md)も参照してください。

## Web ワークスペースの Compute {/* #web-compute */}

スタンドアロン Web ワークスペースでは、 **Compute** を利用できます。ただし、バックエンドが必要な Notebook・Compute API を提供している必要があります。接続したワークスペースでパネルを確認し、既存の SSH/Slurm 設定手順に従ってください。パネルの表示だけでは、リモート認証情報やジョブ実行の可否は確認できません。

## パッケージと外部ツールクライアント {/* #local-research-tools */}

認証済みのローカル Web では[研究パッケージをアップロード・ダウンロード](../guides/research-packages.md#local-package-transfer)できます。リモート Web にこの能力は追加されません。同じコンピューターの外部クライアントには [stdio MCP アダプター](cli.md#external-mcp)を設定します。起動済みのローカルサービスとプロファイルの権限を使い、リモート MCP URL は作成しません。
