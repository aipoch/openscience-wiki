# 許可および制御 {/* #permissions-and-control */}

このページを使用して、権限決定を担当するルールを識別します。 カードを見直したり、助成金を取り消したりする手順については、[許可と承認](../guides/approval-modes.md)を参照してください。

## パーミッションレイヤー {/* #permission-layers */}

| レイヤー | 値またはスコープ | それが管理するもの |
| --- | --- | --- |
| 会話プロファイル | `ask`, `auto`, `full` | 現在の会話のためのエージェントの承認行動 |
| 選択されたversusの有効なプロフィール | ランタイム依存症 | フレームワークは、選択したプロファイルが要求するよりも少ない機能を公開する可能性があります。 説明を調べる |
| 記憶された機能補助金 | 対話、プロジェクト、グローバル | 記録された機能と修飾子のための将来の呼び出しを一致させる |
| Connectorツールポリシー | 常に許可し、毎回尋ねる、ブロック | 選択したConnectorツール; ブロックされたツールは、付与されたルックアップの前に失敗します |
| ファイルシステムアクセス | 選択したパスとアクセスモード | どの外部の場所でもアクセスできるか |
| Notebookネットワークポリシー | 許可された目的地と接続チェック | ランタイムがリクエストされた目的地に到達できるかどうか |
| Specialist 機能 | Skillsとコネクタの割り当て | その役割に何が利用できるか |

これらのレイヤーは変更できません。 完全なアクセス変更のエージェントのプロンプトの動作; ツールをインストールせず、クレデンシャルを提供したり、サーバーを到達可能にしたり、ランタイムのネットワーク保護が接続を許可していることを証明したりしません。

## プロフィールとスコープ {/* #profiles-and-scopes */}

| UI 値 | 契約条件 | 意味する |
| --- | --- | --- |
| **Ask for approval** / **Ask** | `ask` | 承認を必要とする操作を要求し、既存の助成金およびアプリケーション所有の例外の対象 |
| **Auto-approve edits** / **Auto** | `auto` | ワークスペースの編集と承認されたアプリ所有のライブラリ操作は自動的にパスできます。 任意のシェルまたは MCP 呼び出しは一般に許可されていません。 詳しくはこちら [図書館のルール](../guides/approval-modes.md#library-auto). |
| **Full access** | `full` | エージェントの許可リクエストを手動でプロンプトなしで、ランタイムがサポートします。 |
| **Once** | `once` | 現在の呼び出しのみ。 耐久の付与無し |
| **インタビュー** | `session` | この会話でコールを一致させる, 全体の再起動を含む |
| **This project** | `project` | このプロジェクトでコールを一致させる; ワイドスコープの確認 |
| **Global** | `global` | プロジェクト間での呼び出しの一致; ワイドスコープの確認 |

カードは、そのリクエストでサポートされている範囲のみを提供します。 通常、利用可能な場合の会話スコープを選択します。 ボタンの位置から「オンス」を差し込みません。 完全なラベルを読んで下さい。 コマンドプレフィックスとカテゴリの修飾子は、1つの呼び出しの同一の繰り返し以上をカバーすることができます。

**Default permission mode**は新しい会話に影響を与えます。 既存の会話は、独自の設定を保持します。 **Auto-review**は別の結果レビューオプションです。 `auto` 権限プロファイルではありません。

## Connector 決定注文 {/* #connector-decision-order */}

Connectorブローカーは、これらの条件を評価します。

1. ツールが**Block**にマッチすると、拒否します。
2. それ以外の場合は、Connector の allow/ask の設定を適用します。 Connectorレベルの自動でエントリーすると、呼び出しを許可することができます。 承認が必要なツールは、次のチェックを継続します。
3. 機能および現在のプロジェクト/会話のための有効な記憶された補助金を解決して下さい。
4. 該当なしの場合には、対応する承認スコープが表示されます。 承認が利用できなくなったり拒否された場合、電話に失敗します。
5. 操作を解放する前に記憶された承認を主張します。, 呼び出し主が明示的にその承認ステップまで永続性を防御しない限り.

保存された付与は、**Block**を上書きできません。 逆に、記憶された助成金を取消することは、許可ポリシーまたは広範な助成金がまだコールを覆う場合、プロンプトを導入しないかもしれません。 表示されるポリシーとカバレッジのヒントを読んでください。

## デフォルトのグローバル助成金 {/* #default-global-grants */}

ソースは、20ベースライン付与を定義します。 この数値は、インストールされたすべてのプロファイルが表示されなければならないカウントではなく、組み込みのデフォルトを記述します。

| ファミリー | ベースライン機能 | カウント数 |
| --- | --- | ---: |
| カスタム化 | Specialist を作成/更新します。 Skill を公開/編集する。 SkillsとSpecialistから接続/取り外し | 8 |
| Skills | Skillを呼び出します | 1 |
| 文学の読者 | `read_document` | 1 |
| Notebook検査 | リストランタイム, 読みます Notebook 状態, リスト メモリカテゴリ, 検索の記憶, パッケージを調べる | 5 |
| 計画の進捗 | `update_step_status` | 1 |
| 文献ライブラリ | 検索, 抽象的な読み込み, PDF を読みます, フォーマットの参照 | 4 |

いくつかのデフォルトでは、カスタマイズの書き込みを許可します。 ベースラインを「読み取り専用権限」として記述しないでください。**Restore defaults**は、他の助成金をクリアすることなく、欠落しているベースラインのグローバル助成金を追加します。 すべての許可設定をリセットしたり、完了した作業を解除したりしません。

アプリケーション所有の例外もこのリストの外に存在します: 既存のまたはインライン結果を正確なアーティファクト機能で保存し、インタラクション質問を表示し、アクティビティグループを宣言することで、追加のパーミッションカードなしで渡すことができます。 そのような例外は、ツールの認識表示タイトルではなく、検証済みのツールのアイデンティティに依存します。

## 取消と不完全な状態 {/* #revocation-and-incomplete-state */}

| 展望室 | 意味する |
| --- | --- |
| 行は、グローバルまたはプロジェクトで覆われています。 | このより狭い助成金を取除くことは効果のより広い権限を残します |
| ポリシーヒントはブロックされたと言います | ポリシーは、記憶された行が存在する場合でも、呼び出しを防止します。 |
| 不完全な店の警告 | 目に見える在庫は付与を省略する可能性があります。 完全なセットが知られているまでバルクrevocationは無効です |
| 失効または欠損の付与 | 別の変更は要求された行を無効化しました; 現在の状態を更新し、点検して下さい |
| Undoの通知 | 表示される可用性内で、対象となる付与の取消を逆転させます。 ツールの効果を逆転させない |
