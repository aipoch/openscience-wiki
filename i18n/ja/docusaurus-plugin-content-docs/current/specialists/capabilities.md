# Skillsおよびコネクターを割り当てて下さい {/* #assign-skills-and-connectors */}

Specialistの機能リストは、Skillsとコネクタが到達できるかを判断します。 Connector は、Specialist を制限するたびに自動的に利用できるわけではありません。

## 明示的なアクセスを設定する {/* #configure-explicit-access */}

<p className="example-label"><strong>例</strong> RNA-seq QC Reviewer に能力を割り当てる</p>

1. **Settings → Specialists** を開き、**RNA-seq QCの査読器** を編集します。
2. **Full access**をオフにします。
3. **Skills**では、**スキルの追加**を選択し、`rnaseq-count-qc`を検索し、保存されたパーソナルパッケージを追加します。 **Skills 1** を確認します。
4. **Connectors** では、**コネクターを追加** を選択し、**Omics アーカイブ** を選択します。 **コネクター 1** を確認します。
5. 機能の詳細を開き、意図したリソースを選択したことを確認します。 永続性を確認する役割を保存し、再開します。

![明示的な機能選択とSpecialist](/img/open-science/capabilities-walkthrough/05-specialist-capabilities.webp)

| コントロール | エフェクト |
| --- | --- |
| 完全なアクセスオン | 継承された機能範囲を、リソースのパーリソースの排除を任意の明示的に使用します。 変更後の解決リストをチェックする **Manage access**. |
| 完全なアクセス オフ | 明示的なリストを使用する。 誤った結合は、プロンプトのツールを命名することによってのみ供給できません。 |
| スキルの追加 / コネクターの追加 | その機能タイプのセレクターを開きます。 |
| 機能の細部 | リソースを調べる; 科学的なワークフローを実行しません。 |
| 削除 | リソースをアンインストールせずにこの結合を削除します。 |
| 変更を保存 | 選択したスコープを主張します。 |

アプリケーション必須 Skills は、グローバルに有効になっています。 これは、Specialistの機能リストを置き換えたり、フルアクセスをオンにしません。 このロールに「カスタマイズ」が利用できなくなった場合は、バインディングと解決されたリソースを調べます。 [Skillの活発化](../skills/overview.md#why-some-switches-cannot-be-turned-off) を参照してください。

## リソースからのアクセスを調整する {/* #resource-access */}

**Settings → Skills** または **Connectors** では、リソースの **Manage access** ポップアップを開き、Main エージェントと Specialist の関連付けを一緒に検査します。 ロールの有効状態ではなく、選択したロールのバインディングを更新します。 完全なアクセスの役割は、リソースの除外を持たせることができます。 制限されたロールは明示的な選択を使用します。 マーケットプレースバインディングは、このポップアップでのみ読み書きできます。 [アクセス制御を図示した](../guides/connectors.md#resource-access) を参照してください。

結合を変更した後、ロールが有効になっていることを確認します。サービス資格は準備が整っており、意図した操作が許可されます。 **Used by**は、実行完了ではなく、割り当てを表示します。

## 4つの別々のレディネスチェック {/* #four-separate-readiness-checks */}

| レイヤー | 確認するべきこと | 故障事例 |
| --- | --- | --- |
| プロフィール | インストール, 有効, セットアップ完了 | セットアップが保存されるまで、インポートされたロールは無効です。 |
| 機能特性 | 意図したリソースは、ランタイムによって割り当てられ、解決されます | 表示名/短縮名は、割り当てられたカタログリソースに解決しません。 |
| サービス/ランタイム | 接続されたサーバー、必要な資格情報、利用可能なカーネル/依存関係 | 必要なサービス資格やパッケージを欠損する。 |
| 操作 | 現在の入力バージョンと承認されたアクション | 未利用可能なファイルハンドオフは、子の実行前に失敗します。 |

ローカルの役割は、作成とパッケージのインポート後にSkillとOmicsのアーカイブ結合を保持しました。 最初の委任された子供は、試みた短い名前でSkillを解決しなかったが、Pythonで明示的に供給されたテーブルチェックを完了しました。 これは、成功した子供Skill負荷ではなく、委任と算定を検証します。 この場合、エージェントが利用可能なカタログを調べて、割り当てられたリソース ID を使用するように依頼してください。 命名の問題を隠すために、フルアクセスを拡張しないでください。

## 機能アクセスは許可モードではありません {/* #capability-access-is-not-permission-mode */}

完全なアクセスは「要求せずにすべてのアクションを許可する」という意味ではありません。 [承認モード](../guides/approval-modes.md)、ファイルシステム/ネットワーク境界、ランタイムルールは適用されます。 お子様は、親の会話で独自のリクエスト権限を隠すことができます。 回答の前に、リクエストロールと操作を検査します。

役割をエクスポートするとき、Connector ID は参照、ポータブル接続や秘密ではありません。 選択されたSkillファイルが明示的に含まれている場合があります。 別のデバイスで、各バインディングを確認し、資格情報を設定し、ロールに依存する前に1つの小さなチェックを実行します。 [管理と共有](./manage.md) を参照してください。
