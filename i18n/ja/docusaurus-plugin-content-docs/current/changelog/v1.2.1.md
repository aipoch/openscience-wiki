# リリースノート・v1.2.1

リリース **2026-11-11 UTCの**. [公式リリース](https://github.com/aipoch/open-science/releases/tag/v1.2.1).

## 1つの場所にあるリソースを見つける {/* #resource-center */}

**Resource center** スキル、コネクタ、スペシャリストを、インストールおよびマーケットプレースビュー、検索、フィルタ、ディテールドローダと一緒に持って来ます。 Web ワークスペースでマーケットプレースのインストールも可能です。 質問からスキルリファレンスを開くか、メッセージを送信すると、会話を保ちながらプロジェクトペインの詳細が表示されます。 [リソースナビゲーション](../guides/navigation.md#resource-center) · [スキルマーケットプレイス](../skills/marketplace.md).

## 送信前に質問を絞り込む {/* #prompt-optimization */}

使用条件 **Optimize question** プロジェクトの Composer で、設定されたモデルからドラフトを書き換えます。 結果を確認し、それを編集するか、または使用する **Undo optimization** 送信前に。 プロジェクト設定はカスタムを保持することができます **Optimization prompt**お問い合わせ リクエストした時にのみアクションを実行します。リサーチの質問を自動的に送信しません。 [質問の改良](../guides/composer.md#optimize-question).

## 組み込みエージェントでCodexサブスクリプションを使用する {/* #codex */}

**Open-Science Agent** 現在は、メインおよびサブエージェントのインポートおよびアプリ所有のCodexサブスクリプションアカウントをサポートしています。 既存のサインインとクレデンシャルリカバリコントロールが使用可能です。 組み込みのエージェントは、モデルの出力制限を使用して、コンテキスト会計を改善します。 **Claude Fable 5.2** Anthropicカタログを1Mコンテキストウィンドウで結合します。 モデルの可用性は、選択したプロバイダとアカウントによって異なります。 [エージェントのセットアップ](../guides/frameworks.md#built-in-agent).

## スプレッドシートとして参照メタデータをエクスポートする {/* #csv */}

**Export → CSV** 選択された参照、プロジェクト、または16の安定した英語列の名前のコレクションを保存します。 ページを分割し、個々のアイテムを除外することができます。 フィールドを見逃すと、PDFファイル、スクリーニングの決定、個人的なメモは、このメタデータのエクスポートの一部ではありません。 [CSVエクスポート手順](../guides/library.md#bibliography-csv).

## 長い仕事の移動を保って下さい {/* #reliability */}

- Notebook と Compute の証拠は、検証済みのダイジェストで複製され、繰り返しのコンテンツを長期間短縮します。 `.science` 輸出。 最初のエクスポートは、古い証拠も準備します。 [研究パッケージ](../guides/research-packages.md#compact-evidence).
- Modal および Hugging の顔の接続は、ブラウザのサインインの前に互換性のある Python のランタイムを準備し、システムプロキシを使用してアカウントチェックを行います。 [計算アカウント](../guides/remote-compute.md#cloud-account-runtime).
- セッションを切り替えた後、研究フィルムの生成は継続します。 [研究フィルム](../guides/research-films.md#generate-film).
- 選択するまでモバイルペアリングの葉アクセスオフを開く **WiFi** または **Internet**. [モバイル接続](../guides/remote-access.md#mobile-pairing).
- ノートブックの添付ファイルとローカルファイルリンクは、再びプレビューを開きます。 PDFの回復、翻訳分離、文献識別子および狭いソースのプレビューは修正を受け取ります。
- アイドル通訳者は、セッション活動なしで15分後に返されます。 Windows Updateの回復は、ファイル/プロセスのブロックを識別し、Linuxの回復は、確認されたカーネルスレッドをリークされたノートプロセスとして扱うことを避けます。
