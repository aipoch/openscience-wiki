# 完全なPDFを翻訳する {/* #translate-a-full-pdf */}

比較のために元のままにして、別の言語で紙を読んでください。 **Full-text translation**は文書のテキストを準備し、翻訳された段落を作業の進捗として保存し、管理されたPDFで保存された翻訳を維持します。 元のPDFを取り替えないし、ペーパーの調査を確かめません。

## 紙とモデルを用意する {/* #prepare-translation */}

1. PDF をフル取得し、[ライブラリ](library.md)、Reading、Inbox、アップロードされた添付ファイルまたは保存されたファイルから開く。 メタデータや抽象的なものだけとの参照は、完全なテキストPDFではありません。
2. 必要に応じてプレビューを拡大し、PDF ツールバーの **Full-text translation** を選択します。
3. **Prepare full text** を選択します。 **Full text prepared** の翻訳を開始する前に待ってください。 テキストが欠落しているか、PDF がスキャンされていない場合は、元のページを調べます。 準備は、すべての図ラベルまたはテーブルが抽出されたことを保証しません。
4. **Target language**、**Translation method**、**Model**を選択します。 ピッカーが用意するモデルを利用します。

| メソッド | 構成するべきこと |
| --- | --- |
| **Agent** | 利用可能なエージェントモデル、または **Main model** サポートされている場合。 v0.37.1では、Codexサブスクリプションモデルは、このPDF翻訳操作を実行できません。 会話のMainモデルを交換することなく、互換性のある翻訳モデルを選択します。 |
| **Direct API** | API のモデルを構成しました。 サブスクリプションサインインは、直接APIクレデンシャルとして使用することはできません。 詳しくはこちら [プロバイダーのセットアップ](providers.md). |
| **Local model**、提供されるとき | 表示される制御でモデルをインストールし、準備が整うまで待ちます。 ローカル翻訳は、一度に1つの段落を実行します。 |

エージェントとダイレクトAPIの場合、ドキュメントテキストと用語集が選択したモデルに送信されます。 限られた材料を翻訳する前に、選択したサービスを確認してください。 スクリーンショットは、準備とモデル制御を示しています。 選択したCodexサブスクリプションでは、**Translate document**が利用できなくなります。

![翻訳言語、方法、モデル制御で準備された完全なテキスト](/img/open-science/v0360/translation-settings.webp)

絵付け紙はLang et al.、[非欠陥安定熱的に安定した単原子触媒](https://doi.org/10.1038/s41467-018-08136-3)、[CC によって 4.0](https://creativecommons.org/licenses/by/4.0/)の下でライセンスされています。

## 翻訳と履歴書 {/* #translate-resume */}

1. 技術的な用語が一貫した言葉を必要とするとき **Translation glossary** を開けて下さい。 **Source term** と **Preferred translation** を **Add term** で追加します。 開始前に、これらの条件を見直します。
2. **Advanced → Concurrent translations** をデフォルトで最初の実行時に残します。 より多くの同時リクエストは、プロバイダーの制限に遭遇することができます。
3. **Translate document** を選択します。 翻訳されたパラグラフのカウントを監視します。 部分的なカウントは、完全な文書ではありません。
4. 中断するには、**Cancel** を選択します。 完了した段落は保持されます。 **Continue translation** を使用して保存された作業を再開したり、エラーがそのアクションを提供するときに **Retry** を使用します。 **Skip and continue** を使用する前に段落のエラーを読んで、レビューへのギャップを残します。
5. 同じ管理されたPDFを再オープンし、**Saved translations**でそのエディションを選択します。 **Saved translation parameters** をチェックして、言語とモデルを確認します。 それらを変更するには、異なる設定をリトライに混合するのではなく、**New translation**を選択します。

同じPDF共有の検証されたコピーは、文学、読書、受信トレイ、およびワークスペースを渡る版を保存しました。 ファイル名やDOIだけで一致しても同一のコンテンツは確立しません。 このローカル共有は、別のコンピュータに翻訳を同期させません。

## 比較し、輸出 {/* #compare-export */}

**Original**、**Translation**、**Compare** を使用して、ソースと翻訳されたページを利用可能なときに検査します。 技術的な条件、交渉、量、単位および図の参照を元に対して点検して下さい。 **Translation issues** と元のテキストを保持する任意のパスを確認します。 翻訳された段落のカウントは、すべての通路がレンダリングされたページに適合していることを保証するものではありません。

**Export translated PDF** を選択し、別のコピーを保存し、PDF リーダーで再オープンします。 ページのカウントと複数のテキストヘビーと数字ヘビーページをチェックしてください。 翻訳されていないコンテンツは、元の言語で保存されます。 PDF では、翻訳がサイドバーに読み取れるまま、元のテキストを保持している。 引用と科学的な解釈のために利用可能なオリジナルのものを保持してください。

| 見たら | 次のステップ |
| --- | --- |
| **翻訳する前に全文を準備してください。** | 対象となる段落が見つかったかどうかを完全準備し、検査します。 |
| **このサブスクリプションモデルでは PDF を翻訳できません。別のモデルを選択してください。** | サポートされている翻訳モデルを選択します。 対象言語の変更は、モデルの互換性を修正しません。 |
| 提供者率の限界か一時的なunavailability | 待ってから、保存した設定をそのまま再試します。 同じ中断のための重複版を始めることを避けて下さい。 |
| 進歩は保存できません | PDFを再開し、保存した結果を継続して読み込みます。 |

[PDFの注釈と文書のメモ](pdf-notes.md) を使用して、読書質問を記録します。 翻訳とアノテーションは別々のツールです。

## 科学的なレイアウトをチェックする {/* #scientific-layout */}

エクスポートされた翻訳を使用する前に、複数のパネル図とオリジナルのテーブルを比較します。 凡例をパネルで保持し、グループ化されたヘッダーと行のラベルを確認し、式、スーパースクリプト、シンボル、単位を確認します。 v0.37.1は、これらのソース関係を改善し、再生中に有効な埋め込まれたフォントグリフの名前の差を受け入れていますが、元の元は引用語句または科学的な主張の証拠を残します。 古いエクスポートがコンテンツを失った場合、アプリを更新し、保存された翻訳から再びエクスポートします。 元のファイルを保持し、新しいファイルを比較します。

v1.0.0では、**New translation**は新しい版を始める前に新しい源のテキストを準備します。 新しい抽出または異なる翻訳設定が必要な場合は、使用してください。 通常のリトライは、既存のエディションの設定を保持します。 ソースの準備を待って、エクスポートする前に、読み取り注文、式、およびグループ化されたコンテンツを見直します。 新規版を立ち上げると、新しいモデルリクエストが作れます。

## 内容優先のレイアウトを選ぶ {/* #content-first */}

**New translation** の開始前に **Advanced** を開き、単一列の読みやすい配置にする場合は **Content first** を有効にします。既定では無効で、翻訳版ごとに保存され、翻訳中は変更できません。変更する場合は新しい翻訳版を作成してください。Retry は設定変更ではありません。

本文と図注を再配置し、画像・表・数式・参考文献は原文のまま保持します。元ページと出力ページの対応を確認し、書き出した PDF を再度開いて図と図注を点検します。ページ番号は原文と異なる場合があるため、引用と論拠の確認には元の PDF を使います。
