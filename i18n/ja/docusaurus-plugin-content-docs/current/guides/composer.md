# 会話と送信待ちのリクエスト {/* #conversations-and-queued-requests */}

Composer は、指示を送信し、現在のセッションに参照を入力し、実行中にフォローアップを準備します。 **キュー・保存不可** は、キュードリクエストが保存されたトランスクリプトの指示にまだないことを意味します。

## 研究アイデアから始める {/* #research-starters */}

空の会話ページでは、コンポーザーの横にある**Analyze data**、**Compare papers**、**Find literature**、**Create charts**、その他の研究スターターを提供しています。 矢印を使用して、より多くの選択肢が表示されます。

1. **New** を意図したプロジェクトで開きます。
2. **Explain a paper**などのスターターを選択します。 編集可能なリクエストでComposerを埋めます。 選択すると、メッセージは送信されません。
3. 実際の紙やデータに添付し、アップロードを待ち、一般的なリクエストを質問に置き換え、期待される出力を出力します。
4. モデル、添付ファイル、および送信を確認してください。 結果を受け入れる前に、返されたソースとファイルを開きます。

![リサーチスターターとコンパクトなリサーチパッケージのインポートエントリが新しい会話で登場](/img/open-science/v0351/new-conversation.webp)

**Import previous research**は`.science`パッケージの別のエントリです。 研究スターターを選択すると、パッケージや供給例のデータをインポートしません。

## チェック可能な結果のリクエストを準備する {/* #prepare-a-request-with-a-checkable-outcome */}

目的のプロジェクトで**New**を選択し、**Ask anything**でリクエストを入力します。 入力、目的の出力、および方法制約の名前をつけて下さい。 完全な開始例については、[最初のプロジェクト](first-project.md) に従ってください。

| エントリーフォーム | アクション | 送信前にチェック |
| --- | --- | --- |
| + → 添付ファイル | ローカルファイルを選択してアップロードを待ちます | 意図された破片プレゼント; 転送がアクティブに残りません |
| 付属品の破片 | ステージされた入力をプレビューする | 意図したデータに一致する名前と内容 |
| 添付ファイルを削除 | ドラフト参照を削除 | 元のローカルファイルを削除します。 |
| + → ファイル | 既存のプロジェクトファイルを選択します。 | 正しいアーティファクト/バージョン, だけでなく、同様の名前 |
| `@` | ファイル/アーティファクトまたは利用可能な文献を参照する | 参照を結合する実際の提案を選択してください |
| `/` | 利用可能なSkillを選択してください | 方法は関連性があり、前提条件は利用できます |
| `#` | このターンのセッショントランスクリプトを参照する | すべてのセッションのファイル/カーネルを含むことを約束しません。 |
| + → スキルとして保存 | [再利用可能なSkillに完了したブランチをオンにします](../skills/create.md) | 現在の活動を終えて下さい; 利用できなくなったらツールチップを調べて保存したパッケージを確認します。 |
| + → コンテキスト | 現在のコンテキストの使用状況を調べる | 未就学のセッションは無効なエントリを持つことができます。 |
| + → レビュー | 資格のある仕事が存在するときのリクエストレビュー | 結果と互換性のあるレビューパスが必要です |

10,000 文字または 300 線上の長い文面ペーストが管理された添付ファイルになります。 **Show in text field** は、提供されたときにそのテキストをエディタに復元します。 空のコンポーザーの開始時、Up/Down はプロンプト履歴を閲覧します。 再送の前に復元された添付ファイルを検査します。

## 作業の開始方法の選択 {/* #select-how-work-begins */}

モデルセレクターは、設定されたモデルの中から選択します。 モデル/フレームワークに応じて、その推論オプション。 変更は、既に実行中のターンではなく、その後のリクエストに適用されます。 **Agent controls**は、許可モード、自動レビュー、Specialist選択および委任を露出します。 それぞれに別の効果があります。

| 送信制御 | 利用条件 | 結果/境界線 |
| --- | --- | --- |
| メッセージを送信する | アイドルセッション、準備完了リクエスト | ユーザメッセージを保存し、実行を開始する |
| より多くの送信オプション → 最初に計画する | 実行前の手順のレビュー | 承認された作業が進める前の計画に対応 |
| サイドチャット | 制限されたツールで独立したタブでディスク | 新しいドラフトは会話モデルを継承し、努力を推論する。 Side Chat 選択を送る前に確認して下さい。 詳しくはこちら [Side Chat](delegation.md) |
| 営業部 | 利用できる独立した継続 | 継承された履歴/ファイルをチェックする。 詳しくはこちら [セッション](sessions.md) |
| メッセージをキューに追加 | 実行中にフォローアップの準備 | 保留中のリクエスト 納品まで保存不可 |
| 実行をキャンセル | 現在の実行を停止する | キャンセル待ち 既に保存された結果は自動的に元に戻りません |

## 精密なフィードバックを送って下さい {/* #send-precise-feedback */}

<p className="example-label"><strong>例</strong> リクエスト入力と出力チェックをプランでリクエストする</p>

プランがソースのインテグレーションやアウトプットチェックを省略した場合は、承認する前にリクエストしてください。 下記の出力要件をタスクに適応させます。

```text
Add an explicit before/after SHA-256 check and reopen all three saved
outputs. Use compact sample labels in the plot, and include their exact
original column-name mapping in the CSV/report.
```

**Respond to Plan → Send Plan feedback**で提出された後、改定された計画の承認により提出された。 キューデリバリーのデモンストではありませんでした。 実際の制御とスクリーンショットについては、[プランニング](planning.md) を参照してください。

実行中のタスクは、次の指示を変更する必要がある場合にキューを使用します。 変化と残ったままの状態。 メッセージの更新は、新しく要求されたパッケージのインストールまたはより広いファイルアクセスを承認するものではありません。

## 実行中のタスクのキューを管理する {/* #manage-a-running-tasks-queue */}

1. 実行中に何かを尋ねるでフォローアップを入力してください。
2. **Add message to queue** を選択し、そのカウントを拡大して、保留中のテキストを読みます。
3. **Edit queued message** を使用して、コンポーザーに戻します。 アプリケーションが要求する場合、既存の草案を最初に保存/クリアします。
4. **Remove queued message**は、既に配信された指示ではなく、保留中のアイテムを削除します。
5. 注文ハンドルをドラッグします。 キーボードのリオーダーのために、それを焦点を合わせて下さい、それを動かすために**アップ/ダウン**を拾うために**スペース**を押して下さい、そして**スペース**を低下させます。
6. **Send now** はフレームワークのフォローアップパスを経由して配信をリクエストします。
7. テキストがユーザーメッセージとして表示され、エージェントが変更を認めていることを確認します。

**Sending…**、**Stopping…**または**現在の実行が完了した後にキューイングされたメッセージが送信されます**を読んで下さい。 いくつかのフレームワークは、デリバリーを拒否します。 **保存しない**は、テキストがまだ耐久性のあるトランスクリプトメッセージではないことを意味します。 閉じる/リロードする前に重要な文章を保持します。 ブランチ警告は、キューが別のメッセージパスに属していることを意味します。 重複を追加する前に、既存の項目に送信エラーを解決します。

### レポートが書かれている間フォローアップを編集し、並べ替える {/* #edit-and-reorder-follow-ups-while-a-report-is-being-written */}

キュートなメッセージを修正するには、意図したリクエストを編集し、注文を調整し、不要なリクエストを削除してください。

1. 目的の項目の横に **Edit queued message** を選択します。 Composer に移動し、キューを一時的に残します。
2. テキストを見直し、**Add message to queue** を選択します。 再びその位置をチェックしてください。 編集されたリクエストは、最後に返すことができます。
3. リクエストを先に動かすには、**キューされたメッセージを注文する** ハンドルにフォーカスし、**スペース** を押し、矢印キーを使用して、**スペース** を再度押す。
4. **Remove queued message**は、リマインダーや指示の横に使用し、必要なくありません。
5. 配達後、保存されたトランスクリプトを最終テキストと順序で確認します。 削除されたリクエストは、配信された指示として表示されません。

![編集と再注文後の残りの2つのリクエスト](/img/open-science/local-todo-batch/14-queue-reordered.webp)

配信された返信が編集されたコンテンツと注文に従うことを確認してください。 **保存しない** にラベルを付けられた項目は保存されたトランスクリプトに入っていません; 閉じるか、または再起動する前に重要な不要なテキストをコピーします。

**Exit queued editing** はキュー編集モードを終了し、コンポーザーのテキストを離れます。 編集は元の項目をキューから削除するので、終了は戻りません。 保持するには、ドラフトを確認し、もう一度キューに追加します。 それを捨てるために、ドラフトをクリアします。

### 編集時に添付ファイルを保存する {/* #preserve-attachments-when-editing */}

キューされたリクエストがファイルを含む場合、添付チップがエディタを再オープンするたびに存在していることを確認します。 指示を変更し、**Add message to queue**を選択します。 配信後、保存したユーザメッセージに示したファイルを意図した入力と比較します。 正確なファイル ID が重要である場合は、ファイルチェックサムを要求します。

![編集された添付ファイル要求は、そのファイルとチェックサムで配信](/img/open-science/sept11-completion/queue-result.webp)

### キュードアタッチメントが利用できなくなった {/* #a-queued-attachment-becomes-unavailable */}

編集されたキュートメッセージが **管理されたファイルまたはセッションは削除されます。** で停止する場合、添付ファイルチップと元のファイルをチェックします。 リクエストテキストを保存し、現在のファイルを新しい普通のメッセージに再添付し、再試行します。 同一の階段付属品の参照を繰り返し送信することを避けて下さい。 新しい添付ファイルも失敗した場合、エラーとファイル ID を診断レポートに保ちます。

## アクティビティと完了を読む {/* #read-activity-and-completion */}

引数、コード、出力を調べるためのツールカードを拡大します。 完了後、各リクエスト結果を開きます。 ステップが失敗した場合は、[トラブルシューティング](troubleshooting.md)の回復アクションを選択するために最初のエラーを使用します。

**Show more**は、長いユーザーリクエストを拡張します。 **Copy message** とコード コピーはそれぞれのコンテンツをコピーします。 **Scroll to end**は最新のイベントに戻ります。 デスクトップのランマークレールは、長い会話の中でプロンプトの間でジャンプします。 以前のユーザーメッセージを編集すると、リビジョンが作成されます。 [セッション](sessions.md) を使用して、選択したパスを理解します。

| 問題 | 次の検証 |
| --- | --- |
| 無効な送信 | 空のテキスト、不完全なアップロードまたは未利用可能なセッション状態 |
| キュー編集拒否 | 既存のコンポーザーの草案は保存され/クリアされなければなりません |
| 独自分析が継続 | 更新の配達を確かめて下さい 渡された状態を |
| 計画承認後のタスク待機 | 別のツールのパーミッションが保留中であってもよい |
| モデルは、Daneが、ツールが失敗したと言います | 受入前に最初の失敗と実際の保存されたアーティファクトを調べる |

## 回答表のコピー、ダウンロード、または拡大 {/* #copy-download-or-enlarge-an-answer-table */}

**コピーテーブル**(Markdown、CSV、TSV)、**テーブルのダウンロード**(CSVまたはMarkdown)、**フルスクリーンを見る**(Markdown)を明らかにする応答テーブルをフーバーまたはフォーカスします。 必要な形式を選択し、宛先を確認し、ファイルを再オープンして行とヘッダを確認します。 これらのアクションは、既存の回答をエクスポートします。 Connector を再実行したり、管理されたアーティファクトバージョンを作成したりしません。

![フルスクリーンビューで返されたメタデータテーブル](/img/open-science/guides-walkthrough/60-response-table.webp)

長時間の作業には、[バックグラウンドタスク](notebook.md#background-tasks-and-result-delivery) を使用して、特定の実行を開か中止します。 キュードフォローアップは、保留中の指示です。 背景タスクは既に作業を認めています。 タスクリストを閉じると、実行を停止しません。

## ファイルを会話にドロップする {/* #conversation-drop */}

コンポーザーだけでなく、ローカルファイルを会話エリアにドラッグすることができます。 添付ファイルチップとアップロードが完了するまで待ってから、ファイル名を調べて、リクエストを送信します。 ファイルをドロップすると、メッセージが送信されません。 `.science` リサーチパッケージをインポートするには、空の会話ページで **Import previous research** を使用します。 [研究パッケージ](research-packages.md) を参照してください。
