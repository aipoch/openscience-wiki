# セッションとブランチ {/* #sessions-and-branches */}

プロジェクトグループに関連したソースと仕事があります。 セッションは、その中の1つの会話です。 別の質問に新しいセッションを使用し、新しい質問が選択した会話履歴を保持する際のブランチを使用します。 Neither は、どのファイルや実行が新しい会話を実際にアクセスできるかをチェックするための置換です。

## セッションの作成、名前、戻り {/* #create-name-and-return-to-a-session */}

プロジェクトを開き、セッションで**New**を選択し、リクエストを入力して送信します。 プロジェクト名を最初に確認します。新しいセッションは、そのプロジェクトに所属しています。 セッション行を選択して返します。 タスクが終了する前に、ステータスを読みます。

<p className="example-label"><strong>例</strong> RNA-seq品質チェックセッションの名前</p>

GSE60450 の実行が完了すると、**Edit…** を使用してこの情報を保存します。

| フィールド | サンプル値 | コントレイント |
| --- | --- | --- |
| タイトル | `RNA-seq count matrix - validation and sample QC` | 80 文字まで。 エディタはカウントを表示します |
| 説明 | `Validate the public GSE60450 matrix and retain descriptive QC outputs with source integrity checks.` | 1,000文字まで |
| 保存 | 変更を主張する | 閉じた後、サイドバーのタイトルを確認してください |
| キャンセル/閉じる | ドラフトを申請せずに残しておく | これは、研究の実行をキャンセルしません |

![セッションタイトルと説明エディタ](/img/open-science/guides-walkthrough/40-session-edit.webp)

行メニューから **Pin** を選択し、ピン留めされたグループでセッションを保持します。 **Unpin** は普通のリストに返します。 ピニングはアクセスを整理します; カーネルを生きたままにしたり、削除からセッションを保護したりしません。

セッションをオーバーして、その番号とタイトルとプロジェクトを確認できます。 数字は、同じ名前の会話を区別するのに役立ちます。 編集または削除する前に選択した行を確認します。

## 読書ブックマークを保存 {/* #save-a-reading-bookmark */}

[プライベート読書ブックマーク](bookmarks.md)を使用して、ノートで通路またはPDF領域を保存し、このセッションで**Bookmarks**から戻ります。 ブックマークを保存すると、エージェントへのパスは送信されません。

## セッションメニューを正しく読む {/* #read-the-session-menu-correctly */}

![RNA-seqセッションに属するアクション](/img/open-science/guides-walkthrough/41-session-actions.webp)

| アクション | 結果 | チェックイン |
| --- | --- | --- |
| 編集… | タイトル/説明を変更する | 正しい行と保存ラベル |
| すべてのアーティファクトをダウンロードする | アーティファクト選択/ダウンロードフローを開く | このセッションの保存ファイルとリクエストされた選択 |
| Notebook を表示する | セッションの実行ビューを開く | 所有者、言語、実際の実行 |
| 会話をエクスポート… | 提供されたフォーマット/オプションを通して会話をエクスポートする | トランスクリプトエクスポートは、アーティファクト/Notebookバンドルとは異なる |
| アーカイブ | アクティブナビゲーションからセッションを隠す | これは、設定で回復可能まま → アーカイブ |
| 削除 | 恒久的な削除確認を開く | どのデータが影響を受けるかを正確に読みて下さい; 保存をキャンセルする |



## 完了した結果の後の枝 {/* #branch-after-a-completed-result */}

<p className="example-label"><strong>実践例</strong> サンプルアノテーションのための完了したQCセッションを分岐して下さい</p>

完成した生カウントQCの会話をそのまま保ちながら、下流のサンプルアノテーションを議論したいとします。

1. オリジナルのセッションで完了した回答を開きます。
2. **Branch in new session** を、その答えの下から選択します。
3. 新規のセッション行が表示されることを確認します。 元のタイトルを最初に共有できます。
4. **Edit…**で`GSE60450 - follow-up interpretation`に名前を変更します。
5. 次のリクエストを提出する前に、継承されたトランスクリプトを調べます。 必要に応じて、元のプロジェクトアーティファクトを明示的に参照してください。

![ピン留めされた元の横に独立した名前の枝](/img/open-science/guides-walkthrough/57-session-branch.webp)

ブランチは選択した会話履歴を保持しますが、元のライブカーネルを再作成しません。 **code shown** またはブロックされた歴史的リンクをラベル付けされたコピーされた活動のために、プロジェクトのファイルパネルから元のアーティファクトを開き、その生成セッションを検査します。

ブランチの可用性は、メッセージとフレームワークの状態に依存します。 [Side Chat](delegation.md#side-chat-availability)は別です。 会話の現在のモデルと推論の努力を継承する新しい側面の議論。 次の送信用に異なるモデルを選択することができます。

## 以前のメッセージを再訪する {/* #revise-an-earlier-message */}

**Edit message**は、以前のユーザーリクエストで、履歴全体を消去するのではなく、メッセージリビジョンを作成します。 提出する前に、修正されたテキストと添付ファイルを読みます。 代替品を検査するために利用可能な**前の/次のメッセージのリビジョン**を使用してください。 後で表示されたコンテキストは、選択したパスに依存します。 古い回答は、新しく編集されたリクエストに対する応答として扱われるべきではありません。

<p className="example-label"><strong>実践例</strong> QCメトリック定義のリクエストを改訂</p>

このQCの例では、完成した質問で**Edit message**を選択し、4つの定義で1つの独立した要求を交換し、**Send**を選択します。 新しい応答が実行される間、リビジョン制御は利用できなくなります。 **Previous message revision**は、元の質問と回答で`1/2`に戻ります。 **Next message revision**は、修正された回答に戻ります。 CSV フィールド名が生成された `3/3` の正確な修正。 このCodexサブスクリプションセッションでは、更新されたメッセージが利用できなくなった前に保存された2つのレポートが保存され、ダウンロードしたバイトは変更されませんでした。

同じリビジョンパスもOpenCodeとローカルモデルで練習しました。修正されたリクエストは新しいフレーズを生成し、以前のオリジナルの返信を復元し、次に修正された返信を復元しました。 この接続のみの例では、ツールの状態や外部の副作用が逆転しているわけではありません。

![履歴メッセージのリビジョンを切り替えるための制御](/img/open-science/local-todo-batch/18-message-revision.webp)

**Cancel**は編集を提出せずに葉を取り除きます。 **Send**は新しい答えを要求します; 続行する前にチェックしてください。 フォローアップを使用して、次のアクションまたは別々の名前付き調査のためのブランチを修正します。

## 研究パッケージ {/* #research-packages */}

会話ブランチ、ファイル、エビデンスを一緒に手渡すには、[.scienceの研究のパッケージ](research-packages.md)を使用してください。 ガイドは輸出選択、輸入および点検、読まれたセッションをカバーし、回復を移します。

## 会話や研究ファイルのエクスポート {/* #export-conversations-and-research-files */}

セッションの行メニューから**Export → Export conversation…**を選択し、研究の議論を共有します。 まず、セッションに簡潔なタイトルを与えるために**Edit…**を使用します: PDFエクスポートは、そのタイトルを使用します, そして、長い自動タイトルは、最初のページの大部分を消費することができます.

| コントロール | アクションと結果 |
| --- | --- |
| フォーマット → PDF/Markdown | 読書および印刷のためのPDF; さらなる編集のためのマークダウン |
| 会話全体 | 現在の会話ブランチをエクスポートする |
| 選択済み | 初期に空のチェックボックスを表示。 カウンターは選択に従っています |
| すべて選択 | リストされているすべてのターンを選択 |
| 輸出PDF/輸出Markdown | システム保存ダイアログを開きます。 ターンが選択されていない場合、利用できなくなった |
| キャンセル | エクスポートを作成せずに閉じる |

<p className="example-label"><strong>実践例</strong> 最終的なGSE60450 QCの定義だけを輸出して下さい</p>

![最終的なQCの定義の選択はPDFの輸出のために回します](/img/open-science/local-todo-batch/20-selected-conversation-export.webp)

**GSE60450 — Methods and claim audit**では、最終ターンを選択すると、そのリクエストとその4つのメトリック定義のみを含む1ページPDFが生成されます。 以前の議論は不在でした。 また、PDF全体の会話も再開し、チェックしました。 以前の選択したマークダウンエクスポートは、選択したフォローアップで始まりました。 ターンには複数のアシスタントメッセージが含まれているので、ワンターンを選択すると、正確に2つのメッセージをエクスポートする必要はありません。

会話エクスポートは、研究ファイルのダウンロードを置き換えません。 結果リンクは、受信者が開くことができない内部アプリケーションレコードを参照することができます。 CSV、図、報告書を別々にダウンロードします。

### セッションアーティファクトをダウンロードする {/* #download-session-artifacts */}

**Download all artifacts**を選択し、ファイルを選択し、**Nのアーティファクトをダウンロード**を選択し、宛先フォルダを選択します。 このエントリは、別のファイルを保存します。 ダウンロードした2つのメソッドとクレーム・オーディオ・マークダウンファイルが再オープンし、保存されたアーティファクトバイトをバイト単位で一致させました。

![セッションで保存した2つのレポートを選択](/img/open-science/local-todo-batch/21-session-artifact-selection.webp)

### プロジェクトファイルバンドルをダウンロード {/* #download-a-project-file-bundle */}

左上→**Download artifacts…**でプロジェクト名メニューを開きます。 **Generated** と **Uploads** でファイルをグループ化します。 最初に選択されます。 **Uncheck all** を使用して、ファイルを渡すようにし、ZIP を保存します。

![プロジェクトからレポート、QCテーブル、オリジナルのカウント入力を選択](/img/open-science/local-todo-batch/22-project-artifact-selection.webp)

システムで**Cancel**を選択すると、保存する放棄にダイアログを保存します。 ファイルの選択は可能です。 書き込みが開始されると、アプリはキャンセルと終了を無効化します。 結果の待ち合わせ; コピー先のダイアログをキャンセルすると、書き込みの進行を中止することと異なります。

ダウンロードしたファイルのみの場合、使用不能なソースファイルへのアクセスを復元し、意図したハンドオーバーを選択し、再度ダウンロードします。 同じ ZIP 名に保存すると、以前のアーカイブが置換されます。 失敗したファイルのみを選択すると、それらのファイルだけを含む新しいバンドルが作成されます。 以前のZIPにそれらを追加しません。

ダウンロードしたZIPを開き、`generated/`と`uploads/`の下のファイルカウント、名前、および内容を比較して、共有する前に選択してください。 このバンドルは、フルプロジェクト、会話履歴、Notebookカーネルまたはランタイムのバックアップではありません。

## 完成したブランチのアーカイブと復元 {/* #archive-and-restore-a-finished-branch */}

目的のブランチで**Archive**を選択し、**Settings → Archived → Sessions**を開きます。 **Restore**を選択する前に、プロジェクトとアーカイブ時間を確認してください。 ブランチがアクティブなナビゲーションに戻り、保存されたコンテンツが開いていることを確認します。 オリジナルの会話は別です。

アーカイブされたプロジェクトでは、**Manage** エントリーを使用して、プロジェクトのセッションを調べます。 アーカイブ、復元、削除、およびストレージの移転の違いについては、[貯蔵およびアーカイブされた仕事](storage.md)を参照してください。 アクティブなリストからのセッションの消失は、ディスクスペースが返還されたという証拠ではありません。

ソース: [セッションエディタ](https://github.com/aipoch/open-science/blob/v0.26.0/src/renderer/src/pages/workspace/EditSessionDialog.tsx)、[ワークスペースの実装](https://github.com/aipoch/open-science/tree/v0.26.0/src/renderer/src/pages/workspace)。

## 既存のセッションをフォークする {/* #fork-session */}

ローカルまたはインポートされたセッションの独立した作業コピーが必要な場合は、**Fork**を使用してください。 **Branch in new session** は選択したメッセージから始まります。 フォークは、そのブランチ、Notebookレコード、ファイルバージョン、文学、注釈、プライベートブックマークなど、セッションの完全な保存された研究履歴をコピーします。 ソースセッションは変更されません。 記録のコピーは、その環境がこのコンピュータで準備されていることを再実行または確立しません。

1. デスクトップアプリでは、現在のタスクを終了または停止します。 どのパッケージ転送でも終了待ちます。
2. セッション行のアクションを開き、**Fork** を選択します。 アプリは、転送の進行状況を表示します。 **Run in background** は、そのウィンドウをキャンセルせずに非表示にします。
3. **Fork completed** を待って、新しいセッションを開きます。 **Source session**と新しいセッション番号を調べるタイトルを開きます。
4. 継承されたファイルを開き、その内容を確認してください。 選択したモデルとランタイムを継続する前に調べます。 古い機械パスまたは許可は注意を必要とするかもしれません。
5. コピーに次のタスクを送信し、新しい出力を確認します。 リファレンスレコードとしてオリジナルをキープします。

![セッションアクションメニューのフォーク](/img/open-science/v0311/fork-menu.webp)

![ソースを表示し、QCファイルを継承した新しいセッション情報](/img/open-science/v0311/fork-info.webp)

デスクトップアプリでは、フォークが利用できます。 インポートされたセッションは、フォークで作業するまでのみ読み込まれます。 プロジェクト設定とメモリは、別のコピーされたプロジェクトではありません。 古いレビューまたは検証レコードは、録画バージョンを記述します。 現在のチェックとしてそれらを処理する前に、任意の古いステータスを検査します。

### コピーでQCの計算を続けてください {/* #continue-a-qc-calculation-in-the-copy */}

<p className="example-label"><strong>実践例</strong> v0.31.1でローカルセッションをフォークする</p>

GSE60450プロジェクトでは、既存のQCセッションをフォークし、継承された`gse60450-qc-summary.csv`を開きます。 **12**サンプルと**269,027,617**の総生数を確認します。 コピーでは、エージェントが Python でそのファイルを読み、両方の値を確認し、サンプルごとに平均数を計算し、別の `fork-qc-check.csv` を保存します。 結果は**22,418,968.083333…**です。 ソースと継承されたファイルには、同一のコンテンツがあります。 新しい計算は別のファイルです。 これは、正規化ではなく、継続を実証することを意味します。

![Python計算とフォークされたセッションで保存された新しい結果](/img/open-science/v0311/fork-result.webp)

## セッション情報カードを読む {/* #session-information */}

セッションのタイトルを選択し、その番号、説明、ソース、作成/更新時間、現在のブランチとアーティファクトのカウントのメッセージ数を確認します。 **Pin** を使用して、セッションを簡単に見つけやすく、または **セッションを編集** を使用して、タイトルと説明を変更します。 **チャットから継続**ディバイダーは、録画ソースターンに戻ります。
