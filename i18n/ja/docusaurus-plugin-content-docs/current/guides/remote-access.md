# リモートブラウザーアクセス {/* #remote-browser-access */}

リモートブラウザアクセスにより、別のデバイスがこのコンピュータの実行中のワークスペースを動作させることができます。 プロジェクト、エージェント、ファイル、ノートブックのランタイムは、このコンピュータ上で引き続き実行されます。 とは別に [リモートコンピュート](./remote-compute.md)ジョブを実行対象に送信します。

## 電話やタブレットをペアリングする {/* #mobile-pairing */}

ふりがな **Connect mobile device** デスクトップのセクション **Settings → Remote** オファー **WiFi** そして、 **Internet**お問い合わせ 以下に説明する Remote.It モードとは別です。QR ルートは Remote.It アカウントを必要としません。

リモートアクセス時にこのセクションを開くと、WiFi接続フローが始まります。 別のデバイスがワークスペースに到達できるようにしようとすると、信頼できるネットワークで使用してください。 ホストは覚醒し、実行し続ける必要があります。

1. お問い合わせ **WiFi** 同じローカルネットワーク上のデバイス。 複数のホストアドレスが表示される場合は、電話から到達可能なアドレスを選択します。 隔離されたゲストネットワークは、両方のデバイスが同じWiFi名を表示してもアクセスを防ぐことができます。
2. ローカルネットワーク以外のアクセスには、 **Internet**お問い合わせ Pinggy接続通知を読み、作業リンクとQRコードが表示されるまで待ちます。 トラフィックは、サードパーティのトンネルを使用して、表示されたパスワードと接続要件を確認します。
3. 携帯電話やタブレットで現在のQRコードをスキャンします。 インターネットモードの場合、 **Connection password** お問い合わせ ペアリングプロンプトに従って、意図したワークスペースが開くことを確認します。
4. コードが切れるか、またはトンネルが再接続された場合は、 **Refresh QR code** 新しいコードをスキャンします。 60分ごとに無料のPinggyトンネルが変更されます。古い保存されたリンクは動作を停止する場合があります。
5. チェックイン **Connected devices**お問い合わせ 使用条件 **Revoke all** 終了時にそれらのデバイス認証を削除し、選択する **Off** リモート設定でリモートアクセスを停止します。 接続の呼び出しと停止は、別のアクションです。

リンク、QRコード、パスワードをプライベートにペアリングしてください。 QRコードは、オファーのみが利用可能であることを意味しています。他のデバイスが接続されていることを確立していません。 接続が失敗した場合は、ホストの実行状態、選択したネットワークアドレスとファイアウォール権限で別のオファーを生成します。

## 前提条件とモード {/* #prerequisites-and-modes */}

**Settings → Remote**をホームコンピュータで開きます。 使用するモードを有効にする前に、別のRemote.Itデスクトップアプリケーションにインストールしてサインインします。 Open-Science はインストールした CLI を呼び出します。 Remote.Itアカウントまたはそのサービスがバンドルされていない。

| モード | それはのためにあります |
| --- | --- |
| オフ | プロバイダのセットアップとリユースのための信頼できるブラウザレコードを保持しながら、リモートアクセスを再利用します。 |
| アプリへのアクセス | 署名付きモバイルアプリを介して接続し、2ステップの検証を完了します。 |
| ブラウザーアクセス | 永続的なHTTPSブラウザリンクを使用して、2段階の検証を完了します。 |

![オフの状態で点検されるリモート・アクセス](/img/open-science/walkthrough-2026-09-08/63-remote-off.webp)

![Remote.It アプリのリンクと Off、App access、Browser access モードを示す Open-Science Remote control](/img/open-science/settings-remote-control.webp)

アクセスモードの設定は、ホームコンピュータのデスクトップウィンドウから変更できます。 接続されたブラウザは、許可されたときにペアリング/トラストを管理できますが、デスクトップ専用のモード制御には代用されません。

## 環境が利用可能になったらブラウザをペアリング {/* #pair-a-browser-when-the-environment-is-available */}

1. 意図したアクセスモードを選択し、その準備/実行状態を待ちます。 エラーまたはアクセスモードの状態の変更は、使用可能な接続ではありません。
2. ブラウザアクセスでは、表示されるリンクの**Copy**、**Open**、QRコードを使用します。 Appアクセスでは、モバイル接続手順と同じRemote.Itアカウントを使用します。
3. リクエストデバイスでは、認可された承認デバイスで6桁のコードを**Pairing requests**と比較します。 ブラウザ、プラットフォーム、時間、アドレスを確認します。
4. **Reject**、**Allow for up to 12 hours**、または**Trust this browser for 180 days**を選択します。 一時的なアクセスは永続的な信頼ではありません。
5. 意図したワークスペースが開き、小さな読み取り専用インタラクションが成功することを確認します。 リンクのコピーから接続を差し控えないでください。

アクセスリンクをプライベートに保ちます。 目的のデバイスとのみ接続を共有し、それを信頼する前にペアリングリクエストを確認します。

## Revoke と 停止 {/* #revoke-and-stop */}

**Trusted browsers** はデバイスの詳細と最終使用をリストします。 **Revoke &#91;ブラウザ&#93;**は、ブラウザの承認が保護されたアクセス/再接続を無効化します。 **Off** をオンにすると、アクセスを一時停止するが、信頼の記録を保持する。 紛失した装置を別々に取り消す。

オフが終了しなかったアプリレポートが終了しなかった場合は、**Retry turning off** を使用し、保存状態を確認します。 警告は、オフが保存されていない場合は、アクセスが再起動後に戻ってくる可能性があると明示的に述べています。 選択されたラジオボタンを成功にだけ処理しないで下さい。

### サービスの変更 受け入れられる、代理店はまだ再開します {/* #service-changes-accepted-agent-still-restarting */}

もしメッセージが **Remote.Itはサービスの変更を受け入れていますが、その背景エージェントは引き続き再起動します。** だとしたら、新しいサービス ID が保存されています。 数秒待ってから、**検出する** または **Detect again** を選択します。 再びデバイスを追加したり、繰り返しモードを切り替えたりしないでください。 受理されたサービス構成を再利用します。

このページがブラウザのリンクとペアリングコントロールを提供した後にのみ続行します。 検出が失敗し続ける場合は、Remote.Itデスクトップアプリが署名され、そのエージェントが実行されていることを確認します。正確なメッセージを保持し、[トラブルシューティング](troubleshooting.md)を使用してそれを報告します。 ページレベルのエラーとともに**Ready**サブパネルは、エンドツーエンドのアクセスを確立するのに十分ではありません。

## ステージによる診断 {/* #diagnose-by-stage */}

| ステージ | チェックイン |
| --- | --- |
| プロバイダが検出されない | Remote.Itインストール、サインイン、ページの検出結果。 |
| モード変更は失敗します | 現在のエラーとローカルアプリ/providerが実行されているかどうか。 |
| リンクが開きますが、ワークスペースは使用しません。 | ペアリングコード、有効期限、信頼、認定デバイス。 |
| 以前の作業ブラウザは拒否されます | アクセスがオフであるかどうかの取消/expiry。 |
| ワークスペースが開きますが、タスクは失敗します | 自宅のコンピュータ上のモデル、ランタイムおよびツールの許可; リモートアクセスはこれらを構成しません。 |

ローカルヘッドレス/ブラウザのコマンドについては、[サービス参照](../reference/server.md) を参照してください。 ここに示すRemote.Itモードからの別のエントリパスです。

ソース: [リモートアクセスパネル](https://github.com/aipoch/open-science/blob/v0.26.0/src/renderer/src/pages/settings/RemoteControlPanel.tsx).

Linux ヘッドレスの展開は、使用可能な OS キーリングなしで、[クレデンシャルストレージオプション](../reference/server.md#credential-storage-on-headless-linux) を読み込みます。 対象となる秘密のローカルストレージを変更します。 Remote.It の設定は行いません。ブラウザを組んだり、リモートアクセスを許可したりしません。

## v0.31.1のペアリングとリボケーション {/* #pairing-v0311 */}

**Trusted browsers** の前にペアリングリクエストを保留し、残り時間と緊急バッジが残っています。 アクセスを許可する前に、リクエストデバイスに示されているコードを一致させます。 期限切れのリクエストは、再び開始する必要があります。 信頼できるブラウザは、その保護されたアクセスをエンドに期待し、後でアクセスが必要な場合は再度ペアリングすることができます。 **Off**、一時的なアクセスおよび取消の信頼は異なった行為を残します。
