## 失敗の点で診断する {/* #diagnose-by-the-point-of-failure */}

| シンプトム | 最初にチェックする | アクションと成功条件 |
| --- | --- | --- |
| アプリは空のワークスペースを開きます | データの場所、プロフィールおよびアーカイブ | 意図したルート/プロジェクトに戻る。 すぐに取り替えを作成しません |
| 使用可能なモデルなし | プロバイダーのログイン、アクティブエージェント、モデルの互換性 | [プロバイダーのセットアップ](providers.md): 小さな実際の応答が成功する |
| ログインが接続されているが、タスクが失敗する | プロバイダーのエラーと選択したモデルの拡大 | 認証/認証およびモデル識別子のチェック UIの存在は、証拠にアクセスしません |
| タスクが止まる | プラン、承認またはインタラクションカード | 可視リクエストに対応 許可する前にスコープを読み込む |
| キュード補正は実行しません | 保存されていない/送信/保護された状態 | [コンポーザー](composer.md): ユーザメッセージになったことを確認します。 |
| モジュールが見つかりません | 正確な通訳者とパッケージの在庫 | [ランタイム](runtimes.md): 選択した環境のインポートを検証する |
| 承認されたパッケージのインストールはまだ失敗します | 最初のネットワーク/プロキシ/認証エラー | [ネットワーク](network.md): その原因を修正した後、実際の動作を再試行する |
| Notebookはファイルを読むことができません | 管理されたパス、添付ファイル、フォルダの付与とバージョンの参照 | 意図した許可された入力を使用して下さい; 関係のないファイルシステムアクセスを拡張しない |
| 保存ファイルサービスでは、作業パスを拒否 | 管理された出版物に登録しているかどうか | サポートされているアーティファクト操作で保存します。 結果ファイルの再オープン |
| 表は予想される数と異なる | ソースハッシュ、区切り文字、メタデータ列、計算デノミネーター | 期待値を変更する前に、同じ入力から再計算します。 |
| ファイルが見えるが、プレビューが失敗する | ファイルフォーマット/サイズ、バージョン、レンダリングエラー | [プレビュー](previews.md): ファイル不在からレンダリングを区別するためにダウンロード |
| 参照が欠如しているようです | ライブラリビュー、フィルタ、受信トレイ、ゴミ箱 | フィルターをクリアし、ステータスを調べ、正しいライフサイクルで復元します。 |
| 完全なテキストソースが見つかりませんが、添付ファイルが失敗します | 実際のダウンロード結果とPDFの検証 | 別の正当なソース/ローカル PDF を使用して下さい、そして付属品を開けて下さい |
| Side Chat 無効 | エージェント/providerの互換性メッセージ | [委任](delegation.md): 選択したフレームワークで示されている互換性制限を確認してください。 |
| リモートジョブが実行できない | 実際のホスト、認証、スケジューラ、ランタイム前提条件 | [遠隔計算](remote-compute.md) |

## HTTPの間違い:400、403、429および5xx {/* #http-errors-400-403-429-and-5xx */}

HTTPステータスは、モデルプロバイダ、Connectorサービス、ローカルブラウザサービス、プロキシから応答を記述します。 **設定を変更する前に、応答サービスを識別します。** ステータスをエラーボディと一緒にコピーします。`403`単独では、APIの許可、プロキシポリシー、リソース制限が拒否を引き起こしているかどうかを通知しません。

<span id="permission-request-keeps-waiting" />

### リクエスト、認証、アクセス {/* #request-authentication-and-access */}

| ステータス | 意味する | Open-Scienceで確認する |
| --- | --- | --- |
| **400 悪いリクエスト** | リクエストを拒否する。 | 名前付きフィールドまたはパラメータを読みます。 プロバイダーのエンドポイント、モデル識別子、およびサポートされているリクエスト機能をチェックします。 ツールコールの場合、入力スキーマを確認してください。 添付ファイルやオプション機能がエラーを引き起こした場合、小さなテキストのみリクエストをお試しください。 |
| **401 未承認** | 有効な認証は欠落しています。 | 不正なサービスが使用しているアカウントまたは認証情報をチェックします。 関連するサブスクリプション/OAuth アカウントを再接続するか、API キーを正しいか [プロバイダーの設定](providers.md) または [コネクタ資格情報](connectors.md). |
| **403 禁制品** | 本サービスは、アクセスを拒否します。 | モデル/リソースの権限、組織/プロジェクト権限、およびサービスの記載されたアクセス制限を確認してください。 エラーが言うと **HTTP 接続 403**、点検して下さい [プロキシまたはネットワークポリシー](network.md)モデルキーを想定するのではなく、間違っています。 |
| **404が見つかりません** | エンドポイントまたはリソースは、そのアドレスで利用できません。 | ベースURL、APIパス、モデル/リソースIDを確認します。 ブラウザのURLは必ずしもAPIエンドポイントではありません。 サービスは、アクセスできないリソースを隠すために404を使うこともできます。 |
| **405 メソッドは許可されていません** | エンドポイントは、このメソッドを要求しません。 | 選択した API プロトコルと Connector トランスポートをサービス文書にチェックします。 異なる方法を推測するのではなく、再現可能な統合の不一致を報告します。 |
| **407 プロキシ認証 必須** | プロキシは認証が必要です。 | プロキシ設定をネットワーク管理者にチェックします。 モデル API 資格情報はプロキシを認証しません。 |
| **413 コンテンツ 東大** | ボディは限界を超過します。 | 添付ファイル/バッチサイズを削減するか、サポートされた小さな入力を使用します。 どのサービスが制限を課すか確認して下さい。 |
| **422 加工不可能な内容** | コンテンツのご提供はお受けできません。 | フィールドレベルの検証メッセージを読みます。 正しいタイプ、必要なフィールド、またはツール/providerリクエストでサポートされていない値。 |

**400および403は異なった点検を必要とします:** は、サポートされていないパラメータを名前付ける 400 で、そのリクエスト機能を修正しました。 403 は、制限されたモデルの名前を付けるため、そのモデルへのアクセスを確認してください。 正確な原因が現れない場合、サポートの応答および要求 ID を保持します。 単独でナンバーから原因を推論しないでください。

### Quotas および一時的なサービスの失敗 {/* #quotas-and-temporary-service-failures */}

| ステータス | 意味する | 次のアクション |
| --- | --- | --- |
| **402 支払い 必須** | プロバイダー固有の支払い/アクセス処理; HTTPは、普遍的な請求手段なしでこのステータスを予約します。 | プロバイダーのエラーボディとアカウントページを読んでください。 数字だけではトップアップは必須ではありません。 |
| **429 Too 多くのリクエスト** | レート制限; いくつかのモデル API は、排気された quota にも使用できます。 | レートリミットの場合、同時リクエストを減らし、待ち時間を減らします。 **再試行後** または文書化されたリセット。 クォータエラーの場合、サービスの許容/照合を確認してください。 サブスクリプション制限とAPIクレジット残高は別々です。 |
| **500 内部サーバーの間違い** | 応答サーバが失敗しました。 | サービスのステータスを確認してください。 安全であれば、一時停止後の小さなリクエストを再試行してください。 リクエスト ID で繰り返し失敗を報告します。 |
| **502 の悪いゲートウェイ** | ゲートウェイは無効な上流応答を受信しました。 | ゲートウェイ/providerを識別し、そのステータスと構成された上流を確認します。 永続的なカスタムゲートウェイの失敗は、管理者が要求する可能性があります。 |
| **503サービス利用不可** | 本サービスは一時的に利用できません。 | 提供され、回復を待っていればRetry-Afterに続いて下さい。 ローカルエンドポイントでは、意図したモデルサーバーが実行されていることを確認し、準備が整っていることを確認します。 |
| **504ゲートウェイタイムアウト** | ゲートウェイは、上流を待っていた。 | 再試行する前に、既に稼働を開始または完了しているかどうかを確認してください。 分析、仕事の提出、またはアーティファクトの書き込みのために、重複排除を避けるために最初に既存の結果をチェックしてください。 |

いくつかの組み込み Connector 要求はのための縛られた自動retriesを備えています 429, , 500, , 502, , 503 そして、 504. . . . これは、すべてのモデル/フレームワークに適用されず、または繰り返しマニュアルの提出を安全に行わない。 特定のサービスの応答に従ってください。

### HTTPの応答無し、またはまだ失敗します {/* #no-http-response-or-still-failing */}

`ECONNREFUSED`、`ENOTFOUND`、`ETIMEDOUT`、証明書のエラーは、HTTPステータスコードではなく、接続/TLSの失敗です。 タイムアウトリクエストは、HTTP 408 または 504 は自動ではありません。 [ネットワーク](network.md) から始める。

設定を変更した後、同じprovider/Connectorを小さなリクエストでテストし、影響を受けた動作を再試します。 それでも失敗した場合は、[フィードバックの指示](#report-a-bug-or-ask-the-community) を使用します。 サービス名、エンドポイントのホスト/パスを秘密、ステータス、エラーボディ、現在の場合のリクエストID、および時間/タイムゾーンなしで含めます。 認証ヘッダーやトークン取得URLをパブリックレポートに貼り付けることはありません。

## エラーメッセージの一致 {/* #match-the-error-message */}

正確なコードをコピーし、失敗したツール、ダイアログ、またはログからメッセージを添付します。 **コード**、Python例外名、OSメッセージは異なる種類の識別子です。 Open-Scienceは、すべての失敗に1つの普遍的な数値コードを割り当てません。 メッセージにはいくつかの原因があります。 リモートジョブでは、[SSHと計算エラーテーブル](remote-compute.md#resolve-ssh-and-job-errors) を使用します。

| コードまたはメッセージ | 意味と次のアクション | 回復を確認 |
| --- | --- | --- |
| `ModuleNotFoundError: No module named '…'` | 選択した Python インタープリタは、そのモジュールをインポートできません。 インスペクト [ランタイム](runtimes.md), サポートされているパッケージ管理ルートを介して、その環境で必要なパッケージをインストールします。, 任意の再起動指示に従ってください. | 同じNotebook環境でモジュールをインポートし、失敗したセルを再実行します。 |
| `ENOENT` / `No such file or directory` | リクエストされたパスが見つかりません。 ファイル名とソースの場所を確認します。 参照が stale なら、既存のファイルを再度添付してください。 | 意図した入力を同じタスクからプレビューまたは読み込みます。 |
| `EACCES` / `EPERM` / `Permission denied` | 操作はファイルシステムアクセスを欠きます。 OS の権限とプロジェクトのフォルダーの付与の両方を調べます。 使用方法 [プロジェクト](projects.md) タスクが必要とするディレクトリだけを付与する。 SSH用 `Permission denied (publickey)`, 代わりに認証をチェック. | 意図したパーミッションスコープ内で元の読み込み/書き込みを繰り返します。 |
| `ENOTDIR` / `Not a directory` | ディレクトリの操作は、ファイルまたは無効な親パスを受け取りました。 実際の保存フォルダを選択します。 | ディレクトリリストが開きます。 |
| `EISDIR` / `Is a directory` | ディレクトリのファイル操作が受信されました。 目的のファイルを選択します。 | ファイルが開き、またはダウンロードします。 |
| パッケージは非公開の目的地の要求を拒否しました | 拒否されたホストを点検し、IPを解決しました。 プロキシまたはDNSの設定は、ネットワークポリシーブロックのアドレスを供給することができます。 詳しくはこちら [ネットワーク](network.md); アドレスの解像度を隠す代わりに、アクセスをブラインドに拡張します。 | 元のパッケージ要求とその後のインポートは両方成功します。 |

### データベースの起動エラー {/* #database-startup-errors */}

これらのコードは、アプリが安全にデータを開くことができないときに表示されます。 既存のデータフォルダを保持します。 再試行する前にエラーの詳細を読みます。 データベースの削除は、修復ステップではありません。

| エラーコード | 意味する | 次のアクション |
| --- | --- | --- |
| `database_runtime_unavailable` | バンドルされたデータベースエンジンはロードできませんでした。 | 適切な公式アプリパッケージを再インストールし、別々のデータフォルダを保持します。 |
| `database_open_failed` | データベースは開くことができません。 別のアプリインスタンス、不十分なディスク容量、または読み取り専用の場所がこれを引き起こす可能性があります。 | 他のインスタンスを引用し、空きスペースとフォルダのパーミッションを確認し、再試行します。 |
| `database_newer_than_app` | 新しいアプリバージョンでは、このデータフォーマットを書きました。 | 互換性のある新しいリリースをインストールし、同じデータフォルダを再オープンします。 スキーマをダウングレードしようとしないでください。 |
| `database_history_invalid` | 移行履歴は、アプリの想定した履歴と一致しません。 | フォルダを保存し、コードを報告します。 既知のバックアップがある場合, データを交換する前に回復手順を求める. |
| `database_migration_failed` | データベースの更新は終了しませんでした。 | 空き領域、他のインスタンス、権限をチェックします。 利用できる場合のRetryを使用して下さい。 再度失敗した場合はマイグレーション ID を同梱してください。 |
| `database_validation_failed` | 保存されたデータは必要な構造を満たしません。 | アプリを更新し、再起動します。 データベースの行を編集するのではなく、コードをレポートします。 |
| `database_startup_unavailable` | データベースの起動サービスは、応答したり、チェックを終了しなかった。 | リトリート; それが主張するならば、完全に終了し、アプリを再オープンし、それからそれを報告して下さい。 |

回復は、起動画面がクリアされ、予想されるプロジェクトが開いていることを意味します。 **Still stuck? Create an issue for help** アクションが利用可能な場合、レビューフローは [詳細はこちら](#report-a-bug-or-ask-the-community) を記述します。 これらの意味は、[スタートアップガイド](https://github.com/aipoch/open-science/blob/v0.26.0/src/renderer/src/components/database-startup-gate.tsx)に従う。

起動画面が**Quit**のみを提供し、アプリを終了すると、報告された原因を解決し、再度起動します。 このページが提供したときにのみ、**Retry** を使用します。 回復後、予想されるプロジェクトとファイルを再び開きます。

### 回復メッセージ {/* #recovery-messages */}

| シンプトム | 次のアクション |
| --- | --- |
| ストレージの回復後にジョブがキューに入れられている | 影響を受ける会話の通知を読んで、識別されたファイルを保存し、有効なコピーを回復し、選択します **Recheck saved conversations**. 別の投稿の前に同じジョブを調べます。 |
| PDFのアップロードはキャンセルされますが、参照は残っています | 保存された参照を開き、添付ファイルの状態を確認してください。 バッチを使用する **Retry unfinished** 提供されているパス。 |
| 別のクライアントがそれを編集した後、コレクションは拒否されました | 最新のコレクションを再オープンし、再び保存する前に変更を調整します。 |
| Windows 更新レポートはアクセスを拒否しました | 正確なファイルパスとWindowsエラーを読みます。 管理者として公式インストーラを使用する通知の指示に従ってください。 |
| Windows アップデートは、使用中のファイルを報告します | そのインストールファイルを使用して識別されたプロセスを閉じた後、選択します **Retry**, または **Cancel** アップデートを停止します。 |

Windowsエラーは、HTTPステータスコードとは異なるオペレーティングシステムのコードです。 回復が失敗した場合は、インストールされたバージョン、正確なメッセージ、および [問題を報告する](#report-a-bug-or-ask-the-community) のときにサニタイズされたファイル/ジョブのアイデンティティが含まれます。

## ローカルWindowsデータをリセットする {/* #windows-data-reset */}

スタンドアローンのリセットユーティリティは、ローカルのインストールのデータを破棄し、起動しようとする場合にのみ使用します。 **リストされたデータを永久に削除し、認証情報を保存します。 修理やバックアップは行いません。** コピーは、リストされているすべてのディレクトリの外側に研究ファイルやバックアップを必要としていました。 アプリを単独で再インストールすると、このデータが保持されます。

1. [公式リセットガイド](https://github.com/aipoch/open-science/blob/v0.33.0/scripts/windows-reset/README.md)から`reset-open-science.cmd`と`reset-open-science.ps1`の両方を**生ファイルのダウンロード**でダウンロードします。 アプリのデータディレクトリの外で一緒に保存してください。
2. Open-Scienceは、トレイのプロセスを含む、および終了し、そのエージェント、Notebook、ヘッドレスおよびWSLプロセスを閉じます。 通常のWindowsアカウントを使用してください。 管理者モードは必要ありません。
3. ダウンロードフォルダにコマンドプロンプトが開いた状態で、`reset-open-science.cmd -Preview`を実行します。 提案されたデータ、構成、プロファイル、ランタイムキャッシュパスをすべて見直します。 プレビューはデータを削除しません。
4. これらの場所を見直し、バックアップした後にのみ、`reset-open-science.cmd`をダブルクリックします。 削除直前に`RESET OPEN SCIENCE`を正確に入力するように要求します。 その他の応答はキャンセルされます。
5. アプリを再オープンする前に最終結果を読みます。 完了したリセット後、データの場所を選択し、プロバイダと管理されたランタイムを再度設定します。

プロセスが実行されているか、検査できないか、またはパスが安全でないと、報告された条件を最初に解決します。 拒否を迂回しないでください。 設定が破損しているか、カスタムデータの場所が関与している場合は、公式ガイドの明示的な`-DataRoot`手順を使用してください。 削除エラーは部分的なリセットを残すことができますので、変更された何も仮定するのではなく、エラーを読んでください。 ユーティリティは、外部プロバイダのアカウントを見直したり、別途インストールしたPython/R環境を削除したりしません。

## 有用な診断を集めて下さい {/* #collect-useful-diagnostics */}

1. レコードアプリのバージョン、OS、アクティブエージェント/モデル、プロジェクト/セッション、失敗時間。
2. 最初の関連するツールエラーとそれを引き起こした操作をコピーします。 想定される対観察行動を含む。
3. 入力の問題には、公開ソースリンク、ファイル名、サイズ、チェックサムが含まれます。 最小限の再現性のある入力は、関連のないスクリーンショットよりも便利です。
4. **Settings → General → Diagnostics** を開き、必要に応じて実行時間ログに **オープン/リバイアル** を使用します。
5. 共有する前にログを調べる。 アカウントトークン、プライベートソースコンテンツ、および関連のないパスを省略します。 ログを開くと自動的にログが送信されません。
6. 変更後に同じ動作が成功するかどうかを状態にします。 有効なボタンは成功状態ではありません。

[診断の参照](../reference/diagnostics.md)で技術メッセージの意味を収集します。

### 1つのセッションのための輸出診断 {/* #session-diagnostics */}

1. 影響を受けるセッションを開き、そのヘッダーで**Export diagnostics…**、セッションメニューの**Export → Export diagnostics…**を選択します。
2. 利用可能なソースを確認します。 **session.json**と**Session database records**は、選択したセッションに関心を寄せています。 **メインページ** および歴史的なアプリケーションログは、他のセッションからメタデータを含むこともできます。 関連する場合のみ選択します。
3. **Export** を選択し、ローカルの宛先を選択し、**Diagnostics exported.** の使用 **Show in folder** アーカイブを見つけるために待ちます。
4. 共有する前にマニフェストとエクスポートログを調べます。 欠落または破損したソースは、要約または省略することができます。 アーカイブの存在だけは、すべてのソースが捕獲されたことを証明しません。

![ローカルエクスポートの前にセッション固有の診断ソースを選択](/img/open-science/v0330/session-diagnostics.webp)

通常のメタデータエクスポートは、プライベートコンテンツフィールドを除外します。 .scienceエクスポートが機密コンテンツチェックをトリガーする場合、ソースリストには、赤字のスキャナーの証拠と元のフラグが付けられたファイルも含まれています。 **元の機密ファイルはデフォルトでチェックされていない。 選択するには、アーカイブ内のオリジナルのバイトが含まれています。** 共有する前に、必要なソースだけを選択し、アーカイブとスクリーンショットを調べます。 輸出はローカルにとどまり、アップロードかモデル要求をしません。 これは、研究バックアップではなく、診断証拠です。 [.scienceパッケージ](research-packages.md) は、研究用ハンドオーバーに使用します。

### 有用なGitHubの問題を提出する {/* #submit-a-useful-github-issue */}

1. エラーコードや特徴的なフレーズを使用して、既存の問題を検索します。 同じ問題が存在する場合は、そこに関連した再現情報を追加します。
2. GitHub にサインインし、**バグ報告** を開きます。 実際のエラーで`[Bug]: database_open_failed when reopening a project`などのタイトルを使用してください。
3. **何が起こったのか?**、**再現するステップ**、**オペレーティング システム**、**App version**に記入して下さい。 関連する場合は、**Provider / model** を追加, プラスアクティブエージェントフレームワーク.
4. **関連するログやスクリーンショット**では、最初のエラーと周囲のコンテキストの少量を含みます。 問題が入力データに依存したときに公開または最小限のサンプルを追加します。
5. 報告書を見直し、それを提出してください。 問題のURLを保ち、同じ問題で提案されたチェックの結果を投稿してください。 GitHubがアカウントに問題作成を提供していない場合は、Discord を使用して、適切な報告ルートを見つけます。

問題やDiscordの質問を準備するときに、このチェックリストを使用します。

```text
Open-Science version and installation method:
Operating system and architecture:
Agent framework / provider / model (if relevant):
Page and action:
Steps to reproduce:
Expected result:
Actual result:
Exact error code and full message:
Time of failure and time zone:
Public/minimal input (if needed):
Checks already tried and their results:
Relevant log excerpt or screenshot:
```

リモート障害には、実行モード、アプリジョブID、スケジューラジョブID、終了コード、関連するstdout/stderrも含まれます。 プライベートホストにニュートラルエイリアスを使用します。 パスワード、トークン、SSHプライベートキー、患者データ、またはプライベートリサーチフォルダ全体に添付しないでください。 最小限の例で、機密情報を交換します。

<span id="report-directly-from-a-startup-error" />

### エラーからレポートを作成する {/* #prepare-a-report-from-an-error */}

会話エラーの横に**Report this error**を選択します。 スタートアップ画面では、**Still stuck? Create an issue for help**も提供できます。

1. **Error details** を読んで、共有する前にプライベートパス、識別子、または機密入力を削除してください。
2. アプリケーションバージョン、オペレーティングシステム、エージェントフレームワーク、プロバイダー/モデル、ランタイムバージョンの**Also included**を確認してください。
3. **Copy details** を使用して、編集されたテキストと環境情報をコピーします。 **Reveal log file** はローカルランタイムログを見つけます。 自動的に添付されず、共有する前に別のレビューが必要です。
4. **Open GitHub issue**を有効にするには、公開共有のアクセシビリティを確認してください。 エラーテキストの編集は、更新されたコンテンツを再度確認し、確認する必要があります。
5. GitHub フォームを開き、プレフィルドフィールドを調べ、有用な再生手順を追加し、準備完了時に送信してください。 報告書のプレビューだけを開くと、問題は提出されません。

## よくある質問 {/* #common-questions */}

**あらゆる操作でモデルアカウントが必要ですか?** いいえ。 ローカルブラウジング、組織、および多くの設定は、モデルなしで動作します。 エージェントの応答、解析計画、モデル生成されたレビューは、互換性のあるモデルアクセスが必要です。

**ローカルストレージは、すべての処理がデバイスにとどまることを意味しますか?** いいえ。 選択したプロンプト、ファイル、または取得したコンテンツは、使用時に設定されたモデル/サービスに送信される場合があります。 ローカルファイルとモデルの実行場所は別々の質問です。

**オフラインで作業できますか?** ローカルファイルと利用可能なローカルビューの既存のことは、使用可能です。 ホストされているモデル、オンラインデータベース、および欠落したパッケージのダウンロードには、それぞれの接続が必要です。 リモート/ローカルのエンドポイントは、独自の実行サービスも必要です。

**請求書やサブスクリプション残高は使えますか?** いいえ。 利用可能なテレメトリーを報告します。 使用を欠くことはゼロではないです; サービスの請求/リムジンは別々に残ります。

**アーカイブの復元は、作業を再開しますか?** いいえ。 維持された仕事のための運行を元通りにして下さい。 ライブカーネルまたは失敗した操作は、明示的な再起動/再実行を必要とする場合があります。

**成功するSSHテストは、私の分析が実行できることを意味しますか?** いいえ。 選択した実行モード、スケジューラ権限、ランタイム、リソースリクエストをチェックし、小さなジョブを実行し、出力を検査します。 [遠隔計算](remote-compute.md) を参照してください。
