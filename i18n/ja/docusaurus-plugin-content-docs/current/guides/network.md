# ネットワーク、プロキシ、パッケージミラー {/* #network-proxies-and-package-mirrors */}

モデル、Notebookリクエストまたはパッケージのダウンロード時に**Settings → Network**を開くと、その宛先に到達できません。 このページは接続状況を分離します。, Notebook 許可ドメイン, プロセスプロキシとパッケージミラー. 緑の接続チェックは、すべての保護されたNotebookリクエストが成功することを証明しません。

プロバイダーのリクエスト、Notebookネットワークアクセス、パッケージインストーラーなど、さまざまなルートを使うことができます。 これらの設定を変更しながら、ホスト名と正確なエラーを使用可能にしてください。

## ネットワークステータスを最初に読み込む {/* #read-network-status-first */}

ステータスは、ネットワークリンク情報とパッケージ登録プローブを組み合わせたものです。 **READY・パッケージ登録が可能**はプローブが成功したことを示します。 **チェックイン**、到達不能またはオフラインの状態は、別のチェックまたは接続修理が必要であることを示しています。 接続を変更した後、利用可能な**Check again**を使用してください。

ネットワークが **Ready** を報告するが、ツールが失敗した場合は、そのツールのエラーを拡張します。 ステータスプローブは、独自の目的地をチェックします。 失敗したリクエストのホスト名とメッセージを使用して、影響を受けたルートを診断します。

| 失敗 | 次のページを調べる | この誤った結論を回避する |
| --- | --- | --- |
| プロバイダのログインが失敗します | プロバイダ認証とモデル接続チェック | Notebookドメイン設定はモデル認証情報を提供します |
| 1つの研究のホスト名は否定されます | **Manage access** リクエスト内の正確なホスト名 | 広範な関連ドメインを追加すると、修正されます |
| パッケージホストは既に許可されていますが、CONNECT は失敗します | インストーラのログ、プロキシ、DNSの解像度 | 別の同一 クリックを許可すると、すべてのネットワークの障害が解決されます |
| 証明書の検証が失敗する | 構成されたCAの束および組織の信頼の条件 | 証明書の検証を無効にする必要があります。 |
| パッケージの索引は関係の間違いの後で一致の配分を戻しません | 初期ネットワークメッセージと選択したPython/platform | パッケージは存在しません |

## パブリックネットワークルールの設定 {/* #public-network-rules */}

1. **Settings → Network → Manage access** を開きます。 **Public internet access** を読んで、HTTPS が読み込まれているか、どのリクエストが承認を必要とするかを確認します。
2. **Built-in services** を点検して下さい。 **Required** がマークされたグループが有効になっています。 タスクに他のグループが選択できます。
3. **Custom public domains** では、**Domain hostname** を正確に入力し、**Add to list** を選択します。 **Save changes** の前の草案の記入項目を見直して下さい。

パブリックドメインルールでは、そのホスト名にデータを送信することができます。 サブドメインをカバーしたり、プライベートアドレスへのアクセスを許可したりしません。 スキーム、パス、ポート、ワイルドカード、またはIPアドレスなしでホスト名を入力します。 パブリックでないアドレスに解決するホスト名は、適切なプライベートサービスレビューを必要とします。 これらのルールは、保護されたコードがリンクまたはアイコンの検索に続く場合にも適用されます。

## プライベートサービス {/* #trusted-private-services */}

研究コードがアクセスすべき既知の社内サービスのみに使用します。 デスクトップアプリでは、このコントロールが利用できます。 プライベートサービスアドレスのみがサポートされます。 localhost、このコンピューターおよび予約済みアドレスはブロックされます。 フィールドは、生のIPアドレスやワイルドカードを受け入れません。

1. **Trusted private services**では、**Add service**を選択し、**Hostname**と**Port**を入力します。 正確なサービスを確認します。 デフォルトポートは 443 です。
2. **Review service** を選択します。 **Add to trusted services**を選ぶ前に解決された**Approved addresses**を点検して下さい。
3. リストを確認し、**Save changes**を選択します。 保存する前にDNSが再びチェックされます。 アドレス変更には、別のレビューが必要です。
4. その特定のサービスに小さなリクエストを繰り返し、その応答を検査します。 アドレス審査だけでは認証やサービスの可用性をテストしません。

助成金は、正確なホスト名、ポート、およびレビューされたアドレスをカバーしています。 保護されたNotebookとシェルコードは、すべてのプロジェクト間でそのサービスにデータを送信します。 タスクのニーズへのアクセスのみを追加します。 ネットワークルールを保存して保護された接続をリセットし、アクティブな転送を中断できます。 変更を加える前に転送を終了します。

## プロキシモードを選択 {/* #choose-a-proxy-mode */}

**Configure proxy** を選択します。 独自のネットワーク構成で供給されるプロキシアドレスを使用する。 スクリーンショットのポートは、そのコンピュータに固有のものです。

| モード | ビーキャビター | 必須入力 |
| --- | --- | --- |
| **System** | アプリのリクエストは、デバイスプロキシをフォローします。 エージェントプロセスは、アプリの起動からプロキシ環境を継承する | 明示的なサーバーフィールドなし |
| **Manual** | 新しいアプリのリクエストを提示し、固定プロキシを処理する | **Proxy server** URL |
| **Direct** | 構成された/継承されたプロキシなしで新しいプロセスを接続して下さい | サーバフィールドなし |

マニュアルモードは、HTTP、HTTPS、SOCKS、4およびSOCKS5のURLを受け入れます。 URL に埋め込まれた認証情報はサポートされていません。 **Bypass rules**は、直接接続するホストのオプションのコンマ区切りリストです。 localhost は常にバイパスされます。

1. **Manual** を選択します。
2. **Proxy server** をネットワークで使用しているプロキシアドレスに記入します。
3. 関連する目的地が直接接続する必要がある場合のみ、バイパスルールを追加します。
4. **Save**を選択し、**Proxy settings saved.**を待ちます
5. 新規リクエスト/プロセスを開始し、元の失敗操作をテストします。 既存のエージェントセッション、カーネル、インストーラーは既存の接続を維持できます。

マニュアルモードが**プロキシサーバー URL を入力してください**を報告したら、作業プロキシアドレスを入力するか、**Done**で草案を破棄してください。 有効なアドレスを保存すると、プロキシが失敗したリクエストを運ぶことができること自体が確認されません。

### ドメインが非公開アドレスに解決する場合 {/* #observed-fake-ip-failure */}

インストールが `destination resolves to a non-public network address` を報告する場合、短いエラーが `conda install failed` または `pip install failed` を言う場合でも、詳細なインストーラーログを調べます。

```text
deny network-outbound pypi.org:443
(destination resolves to a non-public network address)
```

1. 影響を受けるホスト名とその解決されたアドレスを確認してください。 `198.18.*`などのアドレスは公開先ではありません。
2. 目的地のチェックからドメインリスト決定を区別します。 `alreadyAllowed`は、解決されたアドレスが許容されていることを確立しません。
3. パブリックDNSの解像度と意図したプロキシルートをネットワーク所有者にチェックし、元の小さなリクエストを再試行します。 ドメイン保護を有効にします。
4. インストールを検証し、別々にインポートします。 保存されたプロキシ、Readyの通訳者または既存のパッケージの成功した使用は不十分です。

同じエラーが永続している場合、ホスト名、解決されたアドレス、プロキシモードをインストーラーログで保持し、[トラブルシューティング](troubleshooting.md)に従う。 成功した設定は、ダウンロードを成功させるものではありません。


## パッケージのミラーおよび証明書の信頼の構成 {/* #configure-package-mirrors-and-certificate-trust */}

パッケージミラーの下の**Configure**か**Edit**を選んで下さい。

| フィールド | 入力および効果 |
| --- | --- |
| **Conda channel mirror** | Condaチャンネルのダウンロードに使用されるミラールート |
| **Python package index (pip)** | Pythonのパッケージの索引URL、通常終わる `/simple` |
| **CA bundle path** | 必要なパブリックと企業のルートを含む完全なPEM信託束へのパス。 ブランクは公共の証明書の権限を使用する |
| **View available mirrors** | 外部ミラーのドキュメントを開く |
| **Save** | その後のパッケージ操作のための設定を保存します。 |
| **Cancel** | 草案を破棄 |

![パッケージ ミラーおよびCA字の入力](/img/open-science/walkthrough-2026-09-08/56-package-mirror.webp)

パッケージミラーはパッケージのソースを変更します。 選択したランタイムで、ミラーの必要なroot/index形式、保存、および小さなパッケージ操作を再試行してください。 モデルproviderプロキシ設定は別々です。

コンダ、PyPI および CRAN ミラーのホスト名はパッケージ管理操作のための一時的なアクセスを受け取ります。 これは、永久的なNotebookドメインリストに追加したり、通常のNotebookコードを同じアクセスに付与したりしません。 他のホストへのリダイレクトはまだネットワーク承認フローに従います。

埋め込まれた資格、空白、ローカルホスト、または未加工IPアドレスなしで支えられたHTTP(S)ミラーのURLを使用して下さい。 受け入れられたミラー設定は、利用可能なサーバーやホスト名を予約したアドレスに解決しません。 インストールが失敗した場合は、その操作の実際の目的地と再試行する前にエラーを調べます。 リモート**model**エンドポイントには、別々の[HTTPS要件](providers.md#custom-gateway-every-visible-field)があります。

## リクエストが失敗したときに情報を保持する {/* #information-to-keep-when-a-request-fails */}

アプリのバージョン、操作、ランタイム/環境、パッケージ、ホスト名、プロキシモード、および最初の有用なエラーを記録します。 元のインストーラーの出力を保存します。最終的な「マッチングディストリビューションなし」ラインは、以前の接続障害を隠すことができます。 共有診断からトークンとプロキシ認証を除外します。

Pythonモジュールが正常に接続した後に、[実行時間とパッケージチェック](./runtimes.md)を続行します。 [コンピュート](remote-compute.md)では、リモートホストのセットアップが別々にカバーされます。

[ネットワーク設定ソース](https://github.com/aipoch/open-science/blob/v0.26.0/src/renderer/src/pages/settings/NetworkPanel.tsx), [Notebookネットワーク境界](https://github.com/aipoch/open-science/blob/v0.26.0/src/main/notebook/network-sandbox-owner.ts).

## HTTPエラールックアップ {/* #http-error-lookup */}

400、401、403、404、429、または5xx応答については、[HTTPトラブルシューティングテーブル](troubleshooting.md#http-errors-400-403-429-and-5xx)を使用してください。 応答サービスおよびステータスコードの詳細なメッセージを保持します。

プロキシ、ミラー、または Notebook ドメインの設定を変更した後、値を永続的に確認し、同じランタイムで元の操作を再試行します。 ダウンロードとパッケージのインポートの両方を確認します。 成功する設定は、インストールエラーを解決しないだけ保存します。

## R セルは実行前にブロックされた {/* #r-network-warning */}

v0.31.1では、Notebookは、ネットワーク保護ブロックのR実行時にインライン警告を表示します。 設定リンクをフォローし、リクエストされたアクセスを調べます。 警告は、細胞が実行しなかったことを意味します。 科学的な結果や完了した実行ではありません。 特定の条件を解決した後、細胞を再度動かし、出力を点検して下さい。 Windows 標準モード R サポートはネットワーク保護を有効にしません。
