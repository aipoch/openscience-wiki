# 更新日誌 · v1.3.4 {/* #更新日志--v134 */}

釋出於 **2026-11-23 UTC**。[官方釋出說明](https://github.com/aipoch/open-science/releases/tag/v1.3.4)。

## 用追蹤記錄檢視內建 Agent 的執行過程 {/* #tracing */}

專案新增 **Agent tracing**，預設關閉。開啟後，可將輪次、模型請求和 MCP 工具呼叫的關聯記錄發往主機執行者配置的 OTLP/HTTP 接收端，支援通用 Collector 和 Langfuse。Open-Science 不提供代收服務。開啟前應檢查四項內容採集設定，它們未填寫時預設開啟。[專案操作](../guides/projects.md#agent-tracing) · [接收端與採集配置](../reference/diagnostics.md#agent-tracing)。

單次 Run 可透過 CLI `--otel-traces` 或 SDK `otelTraces: true` 明確啟用追蹤，即使專案開關關閉也會生效，不會修改已儲存的專案或會話設定。[CLI](../reference/cli.md#otel-traces) · [SDK](../reference/api.md#otel-traces)。

## Windows 更新與 Notebook 響應改進 {/* #updates */}

Windows 準備更新時能識別應用自己的內建 Agent 與圖片輔助程序，修復誤判為外部佔用導致的停滯。穩定版 Windows 更新恢復小體積差分安裝包，v1.3.3 使用的是完整安裝包。[更新與恢復操作](../guides/installation.md#windows-134)。

較長的 Notebook 歷史減少重複讀取，並將符合條件的 Run 狀態變更批次寫入持久檢查點。Windows 首次 Python 繪圖不再因無關的核心恢復狀態卡住。Compute 在 macOS 上的記憶體用量排除快取；Windows 在物理用量旁顯示提交記憶體與其上限。[記憶體彙總說明](../guides/notebook.md#memory-summary)。

## 模型與任務結果說明改進 {/* #models-recovery */}

- CodeBuddy 按模型發現支援的推理強度，恢復歷史會話時保留模型選擇與 Token 用量更新，並修復影片創作的首次模型請求。智譜新增 GLM-5.4。[提供方選項](../guides/providers.md#codebuddy-reasoning)。
- 拒絕工具操作後，輪次會保留解釋；被拒絕的呼叫與已完成工作分別計數。[權限與審批](../guides/approval-modes.md#denied-action)。
- 提供方明確返回 HTTP 402，例如 Insufficient Balance 時，保留狀態碼並展示有用的計費詳情。[恢復操作](../guides/troubleshooting.md#provider-balance)。
- 影片生成期間，所屬會話保留在 Active；被其他生成任務阻塞的影片對話方塊可以開啟該任務所屬會話。[影片進度](../guides/research-films.md#film-recovery)。
- 圖片編輯版本在釋出期間可開啟預覽，存在圖片草稿時也能瀏覽 Provenance 歷史。[圖片編輯](../guides/image-generation.md#edit)。
- 內建 Agent 的 Side Chat 使用自身配置的檢查點；工具續接中的空身份欄位不再導致輪次失敗。

另見[安裝與更新](../guides/installation.md)和 [v1.3.3](v1.3.3.md)。
